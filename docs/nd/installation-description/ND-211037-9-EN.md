## Error Messages and Issues

- When an inline routine was invoked inside another inline routine, PLANC gave an error message (as it should), but then it crashed.

- PLANC did not accept `Ind(<INTEGER POINTER>)` or an INTEGER parameter to ROUTINE STANDARD/REFERENCE as parameters to the Monitor_Call statement, even if an INTEGER parameter was expected.

- PLANC gave no warning/error message when the following code was compiled, even if the INTEGER had not been given any name:
  ```
  MODULE xxx
  INTEGER:
  ENDMODULE
  $EOF
  ```

- PLANC gave no error message for the code:
  ```
  TYPE x = x
  ```

- PLANC did not allow you to initialize a record declared inside a routine, even if it was declared as READ only.

- PLANC crashed if an INLINE ROUTINE was declared inside a macro.

- PLANC did not handle INLINE ROUTINE properly if they were declared with the new routine header.

- If a routine pointer was initialized with `Addr(NoName)`, where `NoName` was not declared, PLANC gave a very misleading error message.

- PLANC allowed type definitions before the first MODULE statement in a file, but not between ENDMODULE and the next module in the file.

- PLANC did not evaluate constant expressions when the constants were of type ENUMERATION.

- PLANC did not allow you to use the syntax
  ```
  5 =: Ind(rp)
  instead of
  5 Ind(rp)
  ```
  when `rp` was a pointer to a routine with `invalue`.

- PLANC generated incorrect code for the following statement:
  ```
  'ABC'//Ind(<BYTES POINTER ARRAY>(<VARIABLE>))=:BYTES
  ```

- PLANC did not give any warning/error message for an import statement outside the outermost module, even if it could not handle the imported variable/routine later on.

## 3. Modifications, New Features

- **Routines as components in records**:
  ```plaintext
  TYPE x = RECORD
    ROUTINE VOID,VOID: a
    % Inside the record, THISRECORD may be
    % used to refer to the record itself
    ENDROUTINE
  ENDRECORD
  ```

- **New syntax for routine heading**:
  ```plaintext
  ROUTINE VOID,VOID(INTEGER: a,b,c; BOOLEAN: d): x
  ENDROUTINE
  ```

- **Matching <routine name> after ENDROUTINE**:
  ```plaintext
  ROUTINE VOID,VOID: a
  ENDROUTINE a
  ```

  This will compile without any warnings/errors, because the name after ENDROUTINE matches the routine name.

- Unsigned integer variables, e.g. INTEGER1 UNSIGNED is equivalent to INTEGER RANGE(0:255).

- Underscores in integer constants to improve readability, e.g. INTEGER2: Bit_Pattern := 2#1101_1001_0000_0110#

- String constants, e.g. CONSTANT TheVeryBest = 'PLANC'.

- **Private/public variables in objects**:
  
  In a record declaration, you may specify which components are to be accessible, by writing the word PUBLIC followed by the list of identifiers which are to be accessible, as the first statement inside the record declaration. If no PUBLIC-statement is present, all variables are public by default. Only public components may be initialized when variables of the record type are declared. Overloaded routines within a record will be either all private or all public.

## Features

- **On/Off Commenting Style:**
  - Outside string literals, comments may now be started with a left parenthesis followed by a percent character, i.e. `(%`.
  - This type of comment continues until PLANC finds a percent character followed by a right parenthesis, i.e. `%)`.
  - Comments may continue over several lines, may be nested, or may be placed within statements.

- **No Warning 'Not Assigned Value':**
  - For variables which are not referenced.

- **Hexadecimal Input/Output of Integers:**
  - This is done by giving the format ‘H’ as parameter, e.g.
  - `Output(1,'H',63)` ⇒ `3F` is output

- **Converting a Record to Bytes:**
  - `rec CONVERT BYTES =: str`
  - `Str` is given the value of the components of `rec`, as a sequence of bytes, with the first byte of the record in the first byte of `str`.

- **Priority for Routines:**
  - The user may specify routines to have a priority equal to one of the operators in PLANC, e.g.

  ```
  ROUTINE BOOLEAN, BOOLEAN(BOOLEAN): mypluss(b) PRIORITY +
  % Mypluss will have the same priority as %
  % + in expressions. %
  ENDROUTINE
  ```

- **$EOF Not Necessary on Include Files:**
  - It is now possible to leave out the `$EOF` command at the end of include files. When PLANC reaches the end of the include file, it will react as if a `$EOF` command was present.

- **New Routine Modifier XARGs:**
  - Allows calls with a variable number of parameters.

- **New Routine Modifier MAINSTART:**
  - Allows UNIX parameters `(argc, argv, envp)` with types `(integer, byte pointer pointer, byte pointer pointer pointer)`.

- **$CPU-EXTENSION Command:**
  - Expects an argument which is an integer literal in the range 0:3. If you give any other argument, PLANC will now list the alternatives and their meaning.

- **$MESSAGE-TO-TERMINAL Command:**
  - The message was always converted to uppercase. In PLANC-I, the message is output without converting the message to uppercase, unless the source file (in the compile command) is unit 1 (terminal).

## `@PLANC-100-H`
- `*LIST ON`
- `*COMPILE MYSOURCE,MYLIST,MYCODE`

Unless your source file name is equal to (an abbreviation of) a compiler command, you can leave out the COMPILE command in the first example:

`@PLANC-100-I MYSOURCE,MYLIST,MYCODE`

## `<Command>, ++/--`

You may now use `++` and `--` as parameters to some commands, in addition to the parameters `ON` or `OFF`. `++` increments a level counter for the command, while `--` decrements the counter. The command is switched `ON` when the level counter is `>= 1`. Use `HELP <CR>` to see which commands `++` and `--` may be used with.

## `$GET-VALUE_<command>`

May be used to get the current value of command, e.g.  
`$IF $GET-VALUE LIST $THEN % Listing is on.`

In the command processor, the value is output to the terminal (`ON/OFF` or an integer value), while during compilation `$GET-VALUE` returns `TRUE/FALSE` or an integer value. `$GET-VALUE` may be used with the same commands as `++` and `--`, plus `CPU-EXTENSION` and `TARGET-MACHINE`. The last two commands return an integer value.

## Extensions to `$HELP_command`

You may now give a parameter to the help command, which is an abbreviation of one or more commands. Help then lists only commands which may be abbreviated to the parameter given. `$HELP` now also lists the current value (if one exists) for a command. This applies to the commands listed under `$GET-VALUE` above.

## `$EXIT_abort`

Will set the completion code to 4095 (= 7777B), i.e. FATAL ERROR DURING COMPILATION/LOADING before exiting.

## `$EXIT_warnings`

Will set the completion code to 0 before exiting, unless there were errors during compilation. Thus warnings are ignored in the completion code, while errors will still give a completion code > 0. All errors/warnings will still be listed and included in the summary at the end of the compilation.

## $EXPAND-MACROS_ON/OFF/++/--

Will give you the expanded version of a source line containing macro invocations on the listing. Macros within inline routines are not expanded. This command has lower priority than $EXIT, thus $EX still means $EXIT.

## $VERSION-INFORMATION

Will tell you where you can find a file containing most of the information in this PROGRAM DESCRIPTION, i.e. new features, modifications, and errors corrected.

## $GENERATE-IMPORTS_{file_name}

When this command is given prior to compiling a source file, the compiler will generate import statements for all the exported identifiers in the source file. Note that if you export user-defined types, then the type definitions will also be written to the import file. The default file type for the import file is :IMPT.

## $LONG-NAMES_ON/OFF/++/--

May be used to set the length of identifier names to 16 characters. $LONG-NAMES OFF sets name-length back to the default 10 characters. When using library routines, you should not invoke these with names longer than 10 characters, to avoid undefined entries during loading.

- Some new warning messages are introduced:

  ```
  'NOT IMPLEMENTED "STACKERROR"'
    No further explanation.
  
  'NOT IMPLEMENTED "RANGEERROR"'
    No further explanation.
  
  'String literal continues on new line'
    Strings which are neither terminated by an apostrophe (') nor an ampersand (&) on the current line.
  
  'Control identifier modified'
    In a FOR-loop if the control variable is explicitly modified.
  
  'Invalid argument'
    Bad command argument (in PLANC-H, the error message was '?').
  
  'Write Access Not Allowed'
    In assignment to variables without write access.
  ```

@CC or
@CC - Manually:

@CC
@LINKAGE-LOADER
ND-Linkage-Loader - x

N11:DELETE-DOMAIN_PLANC-100
