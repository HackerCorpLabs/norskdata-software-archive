## 2 Installations Procedure

- **Loading:**
  Files are copied to SYSTEM or logged-in user.

- **Operating procedure:**

  Version A of VTM uses the file called DDBnnn-A:VTM. The file DDB999-A:VTM originally contains the terminal type descriptions for the standard terminals.

  Version B onwards uses one composite file. In version B, this file is called DDBARRAYS-B:VTM, and in version C onwards it is called DDBTABLES-n:VTM. These files contain quite similar data, so if version B is to be used, one will be able to rename the file: `@RENAME-FILE DDBTABLES-C:VTM DDBARRAYS-B:VTM`

  If wanted, the compounded terminal tables can be loaded together with the application running VTM. In this case VTM-ARRAY-D:NRF (ND-500) file or VTM-(128/129)-ARRAY-D:BRF(ND-100) files are loaded together with the program system.

  The compounded DDB-files in the composite files are originally the standard terminal types for ND, i.e. type:

  ```
  002: Teletype-ASR-33
  003: Tandberg-TDV2115-Standard
  011: Dec-LA36 (Decwriter II)
  036: Tandberg-TDV2215-Extended
  052: Tandberg-TDV2215-SDS-V2
  053: Tandberg-TDV220/9-ND-NOTIS
  057: Facit-4420-ND-NOTIS
  079: IBM-PC (ND-Link)
  080: Tandberg-TDV2200/9 ND-NET
  083: Tandberg-TDV2200/9 V2-ND-NOTIS
  090: Tandberg-TDV2200/9S ND-NET
  091: Facit-twist (24-lines mode)
  092: Facit-twist (72-lines mode)
  093: Tandberg-TDV2200/9S ND-NOTIS
  099: Colortrnd 210 ND
  100: Tandberg-TDV2200/9S 25 ND-NET
  103: Tandberg-TDV2200/9S 25 ND-NOTIS
  105: Butterfly console ND-NOTIS
  106: Nokia display terminal 301
  110: Tandberg TDV1200/1 ND-NET
  113: Tandberg TDV1200/1 ND-NOTIS
  ```

The VTM-COMPOUND programs are loaded with these standard tables except the types 2 and 11, which are line-oriented. This means that the program may be run on any of them.

These terminal types.

The VTM-COMPOUND programs can add/delete files in `DDBTABLES-n:VTM`, add/delete terminal type descriptions in `DDB999:VTM` and generate files with `NRF(ND-500)` or `BRF(ND-100)` format with the compounded file `DDBTABLES-n:VTM` as input.

If you are going to implement a non-standard terminal (e.g., type 47), you have to follow one of these procedures:

## Procedure for VTM-B Onwards

```plaintext
@VTM -COMPOUND-E09
2   % (ADD TERMINAL TYPES)
2   % (DDBTABLES-n:VTM)
E   % (E-Version)
47  % (NEW DDB-file)
777 % (NO more DDB-files)
9   % (EXIT) (This would normally be done for all the DDBTABLES-? files. I.e. the program should be run once for each of the files.)
```

## Generate a New File with BRF/NRF Format

Use the following commands:

```plaintext
@VTM-COMPOUND-E09
4   % (GENERATE A FILE WITH BRF/NRF FORMAT)
2   % (DDBTABLES-n:VTM)
E   % (E-Version)
1   % (ND-100 (1-bank))
2   % (ND-100 (2-bank))
3   % (ND-500)
4   % (RETURN)
9   % (EXIT)
```

## Procedure for VTM-A

```plaintext
@VTM-COMPOUND-E09
8   % (EDIT THE CONTENT IN DDB999:VTM)
2   % (ADD TERMINAL TYPE DESCRIPTIONS)
47  % (NEW terminal type)
777 % (NO more terminal types)
9   % (EXIT)
```
