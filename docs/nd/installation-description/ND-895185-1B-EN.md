# Installation Procedure

## 4.1 Automatic Installation

### 4.1.1 Preparations

Prior to the installation, verify the following:

- Ensure that the user areas specified in Chapter 1.3 exist with the required number of free pages and free files. If not, find a directory with enough space to hold the user areas. The installation program will try to allocate space whenever needed, but you may need to specify on which directory to create user areas.

- The following files will be loaded/linked to UNIQUICK:

| Abbrev. | File Name  | Default User Area(s)     |
|---------|------------|--------------------------|
| SIBAS library | SIB-LIB  | SIB-500                  |
| UE library   | UE-PLIB  | USER-ENVIRONMENT         |

Check where these files are installed. If not installed on the default user area, the installation program will ask where to find these files.

- If you already have a version of UNIQUICK installed, make sure it is not defined as a standard domain. Delete it prior to the installation.

- Ensure that your configuration fulfills all other requirements mentioned in Chapter 1 and 2.

```
----------------------------------------------------------
NOTE:
TO INSTALL UNIQUICK ON AN ND-500/5000 MACHINE WITH THE NEW
ND-LINKER, THE NON-AUTOMATIC INSTALLATION PROCEDURE MUST BE USED
(SEE CHAPTER 4.2).
----------------------------------------------------------
```

## 4.1.2 Installation from Floppy

- Put the diskette 210872C<rev>-XX-01D into the floppy drive.
- Log in to user area SYSTEM.
- Enter directory 210872C-XX-01D.
- Run the INSTALL program on the diskette.

Example: How to enter the directory and start the installation program (user input is underlined).

```
@ENTER-DIRECTORY 210872C-XX-01D FLOPPY-DISC-1 0_
```

```
@(210872C:FLOPPY-USER)INSTALL_
```

The following screen will appear:

The installation program can do the following:

- **CREATE**: Create a new user area (or verify an existing one) for UNIQUICK.
- **COPY**: Copy all files from the floppy to the desired user area.
- **LOAD**: Write the load procedure and load the UNIQUICK ND-500 domain.
- **DUMP**: Dump UNIQUICK as a standard domain.
- **EXIT**: Leave the installation program and return to SINTRAN.

The first time, run all the tasks 1-4, one at a time, in sequence.  
To reload UNIQUICK, run tasks 3 and 4. To re-dump UNIQUICK, run task 4.

When selecting the CREATE or COPY option, and an (old) version exists on this user area, you are asked if these files should be deleted. You may answer Yes, No or Manually. When answering YES, program files, domain files, `.MODE` and `.LIST` files of current and previous versions/revisions will be deleted. Afterwards the program checks if there are enough free pages on the user area.

When selecting the LOAD option, there are some questions that need an explanation:

**LANGUAGE**: 'Language to be used if UE is not active? /NO/'

By default UNIQUICK will use the language found in the user profile in User Environment. The answer to this question selects the language to be used if UE is NOT active on the terminal running UNIQUICK.

**SW-CONFIG**: 'Should it be legal for users to define their own SW-CONFIG:SYMB file? /N/'

Answer `Y` if you want to allow users to have a personal copy of the configuration file.

## 4.1.3 Subsequent Installation

If at a later date you want to reload or re-dump UNIQUICK, you can use the installation program that is automatically copied from the floppy during the first installation. To re-run the installation program, log in to user area SYSTEM and type:

```
@(DIALOG-SYS)QUICK-IN-S5-C-
```

To reload UNIQUICK, run tasks 3 and 4. To re-dump UNIQUICK, run task 4.

You may of course also reuse the previously created load/dump procedures (:MODE).

## 4.2 Non-Automatic Installation

Create a user area with the number of pages mentioned before and copy all the :NRF and :MODE files from the floppy into it.

### Loading with Linkage Loader:

Log in to the user area containing the :NRF files. Edit the file `QUIC-LOAD-S5-C:MODE` to suit your installation and run it by typing:

```
@MODE QUIC-LOAD-S5-C:MODE "QUIC-LOAD-S5-C:LIST"↩
```

### Loading with ND Linker:

Log in to the user area containing the :NRF files. Edit the file `QUIC-DOM-C:MODE` to suit your installation and run it by typing:

```
@MODE QUIC-DOM-C:MODE "QUIC-DOM-C:LIST"↩
```

### Define Standard Domain:

Update the file `QUIC-DUMP-S5-C:MODE` and run it from user SYSTEM. Update the system startup file (HENT-MODE:MODE) if you want UNIQUICK to be defined as standard domain after a cold-start.

## 5 Modifications

### 5.1 New Functions/Commands

**Revision C10**

- UNIQUICK has been rewritten with a new user interface and new application generating routines.

- Advanced applications can be made using many tables (owner-member structures and join structures) and most UNIQUE-II field functions are available.

- The word "Letter" (language dependent) is displayed in the status line if you have some unread electronic mail (NOTIS-ID).

- New terminology has been introduced in the DIALOGUE family. UNIQUICK uses the new terminology.

- UNIQUICK now reads the parameter 'prefix-source=' from the SW-CONFIG file, under 'system-name:<domain-name>' or 'system-name:@'. 'System name:@' denotes parameters valid for all UNIQUE systems.

- There is an additional configuration parameter, 'UNIQUE-ON-LINE=', which is not documented in the manual. This is used to tell UNIQUICK the name of UNIQUE-II if the standard name is not used.

Example of use:

```
SYSTEM-NAME: @
  UNIQUE-ON-LINE : UNIQ-II-SIBAS
```

- If the file (J)UNIQUICK-C-HEAD:INCL can be opened it is used to make a heading for the application. In addition, for each ^ character found, the application name is inserted.

Example of UNIQUICK-C-HEAD:INCL:

```
+----------+---+
| Unique-II | ^ |
+----------+---+
```

## 5.4 Other Modifications

**Revision C13**

- Due to changes in the S-format required in different versions of the NOTIS products, a new file must be present on user DIALOG-SYS. This file is named `UQ-ND-S:INI` and must have public read access.
  
  All S-format files produced by UNIQUE products will have the same S-format header as the file `(DIALOG-SYS)UQ-ND-S:INI`.
  
  `UQ-ND-S:INI` is an 'empty' file containing only an S-Format header matching the version of NOTIS-WP you are using on your machine. By storing the S-Format header in a file, it is possible for you to define the default settings and rulers. UNIQUE will read the default header from this user defined file, if it exists.

  If you start using a version of NOTIS-WP with a new S-Format, e.g. going from WP version M to N, just repeat the procedure described below and UNIQUE will produce documents readable by the new WP version.

  You have to install/create this file manually:

  ```
  1. Log in on user area DIALOG-SYS.
  2. Start NOTIS-WP.
  3. Use the internal menus in WP to set the wanted default values.
  4. Make sure you define it to be an S-Format document.
  5. Type some blanks so WP will store it as a document.
  6. Save this 'empty' document to the file "UQ-ND-S:INI".
  7. Set public access to READ: @set-file-access UQ-ND-S:INI R R,,
  ```
