## 4 Installation procedure

- All applications using SIBAS must be stopped. All SIBAS processes of version SIBAS-II-F, SIBAS/R-A, and SIBAS/R-B must be PASSIVE. Use SIBAS-SERVICE/STATUS/ALL DATABASES to check if there are active processes.

### 4.1 Automatic installation

- Insert the floppy 380694B-XX-01D into FLOPPY-DISC-1, unit 0  
  `@ENTER-DIRECTORY,FLOPPY-DISC-1,0`

- Log in as user SYSTEM

- Run the installation program:  
  `@(380694:FLOPPY-USER)IN-DSBCKJ`

**NOTE:** You will be asked if you are going to use SIBAS/R Backend for NOTIS-DS over TCP/IP.

### 4.2 Completing the installation

When the installation program has been run:

- **How to run SIBAS Backend for NOTIS-DS:**

  It may be necessary to increase the following parameters for the XMSG, (by using XMSG-IN), on the application machine:

  - **X5PRT (number of ports)** : one for each application
  - **X4MES (number of message elements)** : one for each application
  - **X4BPG (buffer space in pages)** : max. one page per active application.

  The SIBAS port name (‘*SIBn’) of the database machine should be defined in XMSG, for both the application machine and the database machine. This is done by the use of the following commands:  
  `@XMSG-COMMANDJ`  
  `DEFINE-REMOTE-NAME,*SIBn,<Database-machine-system-number>J`  
  `EXITJ`

  Where "n" should be an integer value between 1 and 326. This means that it is possible to communicate with up to 326 database machines from one application machine. `<Database-machine-system-number>` is the CPU-number of the database machine.

Read the rest of this section if you are going to use your SIBAS/R Backend for NOTIS-DS over TCP/IP, in addition to COSMOS.

- Fetch the AIP-HOSTS:SYMB file in your OpenLAN network used for manual updating.

Update the file with information concerning the computer where the SIBAS Backend for NOTIS-DS has been installed, as follows:

1. Isolate all records concerning the Ethernet III controllers where the TCP/IP Basic Module/III is installed.  
   (If you don't know the addresses of these controllers, you can find them by reading the file `AIP-CONFIG:SYMB` which contains information on all the local Ethernet-controllers running TCP/IP. All controllers with TCP-device number >= 4 are running the TCP/IP Basic Module/III)

   - Remove the service SIB-551 if defined for any of the controllers.
   - Define the service SIBRCOM-561 (in the comment-field) for ALL the controllers.

2. Isolate all records concerning the Ethernet III controller where the TCP/IP Basic Module/III is installed as TCP-device number 4. (If you don't know the address of this controller, you can find it by reading the file `AIP-CONFIG:SYMB` which contains information on all the local Ethernet-controllers running TCP/IP).

   - Define the SIBAS port name (`'*s1bn'`) of the computer as Alias name for the controller.  
     See the DIALOGUE Operations (830072.2 EN) for information on the name.
   - Define the service SIB-560 (in the comment-field).

Be sure to distribute the updated file to all computers concerned.

See the OpenLAN Network Supervisor Guide (830107.3 EN) for more information.

- Fetch the `AIP-SERVICES:SYMB` file in your OpenLAN network used for manual updating, and update the file as follows:

  1. Include the service SIB-560/TCP if not already defined.
  2. Include the service SIBRCOM-561/TCP if not already defined.

Be sure to distribute the updated file to all computers concerned.

See the OpenLAN Network Supervisor Guide for more information.
