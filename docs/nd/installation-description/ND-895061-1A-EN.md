# Description of Product

To allow use of TCP/IP protocols by applications (FTP, TELNET) in a SINTRAN environment on a Ethernet local area network.

# Reason(s) for New Product or Version

### Revision B05

- This product allows 124 simultaneous Telnet connections and 8 simultaneous FTP connections.
- SIBAS backend is now available over the TCP/IP Basic Module.
- NFS support may be selected when installing this product.

## 5 Installation Procedure

### 5.1 Selecting Internet Address

- On request from the installation program you will have to assign an Internet address for each controller. If your net is isolated from other nets outside your company, you may select the address freely, i.e. using the default values given by the installation program. If your net connects to other nets, free selection of addresses may accidentally give the same address to two installations which will create severe problems. Selecting proper Internet addresses are further described in the OpenLAN Network Supervisor guide. However, the address for application of an official Internet address range is:

  ```
  DDN Network Information Center
  SRI International
  Room EJ217
  333 Ravenswood Avenue
  Menlo Park, CA 94025
  ```

### 5.2 Automatic Installation

- Check that the RT-program PROMAN is running by giving the command:
  ```
  @LIST-RT-DESCRIPTION PROMAN
  ```

  If the program is not running, the first line will be:

  ```
  PASSIVE ..... ..... ..... ...... ..... ..... ....
  ```

  Start PROMAN by giving the command `@START-SERVERS`. If PROMAN starts without giving any error messages, the installation can continue.

  If PROMAN fails to start, the command `@START-SERVERS` should be given in the LOAD-MODE:MODE or LOAD-SYSTEM:BATC as described in chapter 5.3, and the system restarted before installation is continued.

  The installation will fail if PROMAN is passive.

## 5.3 Completing the Installation

When the installation program has been run:

- Update the AIP-HOSTS:SYMB file with the local internet address of the host name. See the documentation for more information.

- Update the mode file that is run after a cold start (usually called HENT-MODE:MODE) by including the following line:

  `@MODE (TCP-IP)TCP-BA-LOAD:MODE,,,`

  If you had a previous version of this product, remove the old line loading that version.

- Insert the line:

  `@START-SERVERS`

  if you have not already done it, in the LOAD-MODE:MODE or LOAD-SYSTEM:BATC file after starting the XMSG (and after the command `@START-TADADM` which usually lies in the XMSG startup file) and before starting the ND-5000. Be aware that some systems might have started the ND-5000 in the HENT-MODE:MODE job. In this case you should not start the ND-5000 in the HENT-MODE:MODE, but in the LOAD-MODE:MODE as mentioned above.

- To reboot the domino controller(s), run the mode job:  
  `@MODE (TCP-IP)TCP-BA-REBO:M,,,`

- To stop the domino controller(s), run the mode job:  
  `@MODE (TCP-IP)TCP-BA-STOP:M,,,`

## 6 Modifications

### 6.1 New Functions/Commands

- Possibility of running TCP/IP in several Ethernet III controllers simultaneously.
- An error message will be issued when another host has the same Internet address.
- This product will now support startup and error reporting to a NCS network server. The Internet address of the NCS server must be put into the AIP-HOSTS:SYMB file with the name AUDITSERVER to achieve this. The product will also answer alive check polling from the NCS server.

### 6.2 Changed Functions/Commands

None.

### 6.3 Removed Functions/Commands

None.

### 6.4 Other Modifications

- The installation program will ask you whether or not you require NFS support. You should answer NO to this unless you are installing NFS at the same time, or else some TCP/IP resources will be wasted.
- The installation program will prompt for the number of Telnet server connections actually bought. You MUST give the correct number, as found in the accompanying ND Licence Agreement document.
- If you are re-installing this product you have to do a warm start afterwards to make the re-installed product function properly with respect to any changes to its configuration. For example, in terms of number of Telnet server connections.

## 7 Errors Corrected

- The Telnet Server will now close a connection if it times out.
- A Telnet connection doing XOFF will not cause the connection to be closed.
- A Telnet connection will run more smoothly due to enhancements regarding queue handling and event handling in the TCP and the Telnet server.
- On power fail the TCP Control server in ND-100 will not close down the controller.
- The stability of the TCP/IP is improved: it will not go down due to long Ethernet packets on the net and it will not accidentally close its own port due to returned messages from applications.
- Dead connections will now be removed by a timer in the TCP.
- Earlier versions sometimes closed connection after 10 minutes without traffic. This was caused by an error in the No Activity Timer. This has been corrected in this version.
- In earlier versions, the FTP server was not capable of handling files larger than 16 MB. The maximum file size is now increased to 128 MB.
- When doing serial file transfer using the OWS Terminal Line Server over a Telnet connection, older versions would sometimes fail when transferring files to the server. This has now been corrected.
- When using SIBAS Backend over TCP/IP, Sibas connections would sometimes be closed down with an error message from the routine HandleSibdata. The error occurred now and then when using the call STOWD (Storing of wide columns).

## 8 Errors Known But Not Corrected
