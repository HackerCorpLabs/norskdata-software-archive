## Description of Product

NOTIS-DIARY is a new product designed as a replacement for NOTIS-PM, providing both a personal diary for recording appointments and a meeting-scheduling system. The latter will arrange meetings at a mutually convenient time for all participants based on information in their diaries.

The appearance of the diary may be customised in many respects by individual users and the supervisor may also control some operational aspects of the system.

## Reason(s) for New Product or Version

NOTIS-DIARY provides an increased functionality for the personal diary compared with NOTIS-PM as well as the addition of a meeting scheduler.

## 4 Installation Procedure

### 4.1 Automatic Installation

- Before you start installing NOTIS-DIARY, check that the prerequisites listed above are fulfilled.

- Log in through UE under a UE-Supervisor user, and enter SINTRAN user area `SYSTEM`.

- Using UE-PMAN, create a new user with the name NOTIS-DIARY. If you are using Version C of User Environment, set the Authorization as "Supervisor"; with Version D, set the Authorization as "Server". Set SINTRAN as "YES". The SINTRAN user area can be set to anything, eg. Floppy-User. In UE-D, don’t forget to make this a legal user area for NOTIS-DIARY on your machine as well as its default user area.

  The password can be anything. You will be asked to enter it again by the installation program, you should answer with a password **different** to the one you enter now.

  To prevent users logging into the system as NOTIS-DIARY, set the Standard Task to "@LOGOUT".

- In UE-D (not in UE-C), processes that use no UE functions are logged out of UE after a set period (default 12 hours). The DIARY servers may therefore be logged out of UE after a period of inactivity (but they remain logged in through SINTRAN). The next time they try to use a UE function the message "Protected function. Not allowed for this user" is displayed.

  Restarting the servers solves the problem until they are next logged out, but it is possible to lengthen the allowed period of inactivity. Type UE-FUNC and select the option 'Functions for the System Supervisor'. A menu for supervising appears, select option 'Machine'. Alter the login timeout to some suitable value.

- **Using DS-SERVICE, create NOTIS-DIARY as a DS user area.**

  The OUTTRAY of NOTIS-DIARY is used to send reminders to DIARY users, and therefore NOTIS-DIARY requires a MAILBOX and an OUTTRAY. These are created automatically when you create the DS user area NOTIS-DIARY even if you answer 'No' to the question 'Create STANDARD HIERARCHY for this user area? (Y/N) :'.

  Reminders consist of the text of appointments and therefore tend to be short, but they may be numerous. They are held in the OUTTRAY between the time they are mailed to the diary owner and the day after the appointment they refer to. We suggest 300 elements and 700 blocks as the user area limits for NOTIS-DIARY (each element requires just over 2 blocks minimum), but obviously the limits should be set according to the amount of use the reminder system gets.

- **Insert the diskette 211778A\<rev\>-EN-01D in the floppy drive and enter the directory as usual by typing:**

  ```
  @ENTER-DIRECTORY 211778A<rev>-EN-01D <device-name> <device number>↩
  ```

- **Start the installation program by typing:**

  ```
  @(211778A<rev>-EN-01D: FLOPPY-USER)IN-NDIARY-EN:PROG↩
  ```

  NOTIS-DIARY will then be installed. Note that for NOTIS-DIARY, Module 1 asks no questions but must be executed. It will try to stop the NOTIS-DIARY servers. Don't worry if there are no servers present for it to stop.

  Module 2 of the installation need not be executed during the first installation of NOTIS-DIARY but should be executed when re-installing or installing a new version or revision. It deletes the old NOTIS-DIARY files. NOTE: if you answer 'Yes' to the 'Delete previous version (Y/N)?' question, whatever version is present will be deleted, regardless of whether it is the same as the one you are installing. 'Yes' to 'Delete current version (Y/N)?' deletes only files belonging to the version you are installing.

  Note that module 2 does not delete the files NDIARY-QUEUE-A:QUE and NDIARY-INIT-A:INIT in user area NOTIS. The reason is that these files contain information that must be preserved across new installations of NOTIS-DIARY.

## 5 Errors Known But Not Corrected

1. It is not possible to send a remote SINTRAN enclosure during a Schedule or Broadcast unless:
   - the user is logged into a SINTRAN user area that also exists on the remote machine
   - the passwords of the two SINTRAN user areas are identical
   - the user has read access to the file he is trying to enclose  
   This bug is due to an error in the monitor call FullFileName.

2. A user specified twice as an attendee at a scheduled meeting, e.g., by virtue of being on two lists, appears twice on the invitee list below the Meetings/Schedule chart. He does not receive two diary updates/letters.

3. If the Request Server stops unexpectedly (for example, if a power fail crashes the machine), it is sometimes not possible to start it again. The error shown on the error device is: 'Page Fault on Non-Demand'. To start the Request Server, stop the Diary Server with the Stop-Servers command in Diary-Service and run the mode file (NOTIS-DIARY)NDIARY-LOAD:MODE from SINTRAN user SYSTEM. Then start both servers again with Diary-Service.

4. In certain circumstances pressing the right arrow key when the cursor is on the last character position of a field can undo edits to the field and give the message "Can't perform this function (current 'X' position is unknown)".

5. The priorities of the NOTIS-DIARY servers are set with the DIARY-SERVICE command Define-Parameter Priority. It is not allowed to set this value to zero (i.e. time sliced). A value of zero seems to hang most systems!

   The installation value of the priority is 40 octal. This is the same as the priority of DS and may be too high for systems that use DS intensively. If DIARY adversely affects the performance of DS, try reducing the priority.

6. The conflict flag is not displayed if the conflicting appointments are separated by an appointment without an end time.

   A cancellation can leave the conflict flag on unexpectedly. The flag can always be cleared by deleting all appointments on the day.

7. It is inadvisable for two people to use the service program at the same time. Changes made by one may overwrite changes made by the other.
