## DESCRIPTION OF PRODUCT

To allow use of TCP/IP protocols by applications (FTP, TELNET) in a SINTRAN environment on a Ethernet local area network.

SIBAS backend is available over the TCP/IP Basic Module/III.

NFS support may be selected when installing this product.

This product supports startup and error reporting to a NCS network server. The Internet address of the NCS server must be put into the AIP-HOSTS:SYMB file with the name AUDITSERVER to achieve this. The product will also answer alive check polling from the NCS server.

## 5 Installation Procedure

### 5.1 Selecting Internet Address

- On request from the installation program you will have to assign an Internet address for each controller.

  If your net is isolated from other nets outside your company, you may select the address freely, i.e. using the default values given by the installation program.

  If your net connects to other nets, free selection of addresses may accidentally give the same address to two installations which will create severe problems.

  Selecting proper Internet addresses are further described in the OpenLAN Network Supervisor guide. However, the address for application of an official Internet address range is:

  DDN Network Information Center  
  SRI International  
  Room EJ217  
  333 Ravenswood Avenue  
  Menlo Park, CA 94025  

### 5.2 Automatic Installation

- Check that the RT-program PROMAN is running by giving the command:  
  `@LIST-RT-DESCRIPTION PROMAN`

  If the program is not running, the first line will be:

  ```
  PASSIVE ..... ..... ...... ..... ..... .... 
  ```

  Start PROMAN by giving the command `@START-SERVERS`  
  If PROMAN starts without giving any error messages, the installation can continue.

  If PROMAN fails to start, the command `@START-SERVERS` should be included in the LOAD-MODE:MODE or LOAD-SYSTEM:BATC as described in chapter 5.3, and the system should be restarted before installation is continued.

  The installation will fail if PROMAN is passive.

When the installation program has been run:

- Update the AIP-HOSTS:SYMB file with the local internet address of the host name. See the documentation for more information.

- Update the mode file that is run after a cold start (usually called HENT-MODE:MODE) by including the following line:

  `@MODE,(TCP-IP)TCP-BA-LOAD-D:MODE,...`

If you had a previous version of this product, remove the old line loading that version.

- Insert the line: `@START-SERVERS`

  if you have not already done it, in the LOAD-MODE:MODE or LOAD-SYSTEM:BATC file after starting the XMSG (and after the command `@START-TADADM` which usually lies in the XMSG startup file)

## 6 Modifications

- Some error reports from the Eth-III controller software has been changed: e.g. the "Duplicated IP addresses" report now gives both the IP and Ethernet addresses of the offending system. The ARP command of the TcpIp-Monitor enables you to find the supposedly correct Ethernet address for that IP address.

## 7 Errors Corrected

- **TCPD and waste of Nucleus resources**  
  The previous versions of this product did not release the Nucleus resources involved in error reporting from the Eth-III controller software to the AuditServer. The nucleus resources will be wasted. This has been corrected in TCPD rt-program.

- **Telnet server and excessive error reported**  
  In the previous versions of this product, the Telnet server would sometimes continue to poll connections that was disconnecting, resulting in excessive error reports. Error of type: "illegal socket ID etc ..." This has been corrected.

- **UDP-broadcasts thrown away**  
  The previous versions of this product did not handle UDP-broadcasts correctly, especially incoming UDP-broadcasts were thrown away.

- **ARP-entries are kept for at least half an hour**  
  The ARP-entries will be kept for at least half an hour while in the previous version, they were not kept for more than 3 minutes which causes a bad performance.

- **MBUFs used were not released**  
  The MBUFs used by the RAW protocol were not released when they were no longer needed.

- **Nucleus resources not released**  
  The Nucleus resources used by the controller when an application used SLib to send data with the RAW protocol, were not released when finished.

- **Mixing TCP-port and UDP-port**  
  In previous versions of this product, datagrams sent to local UDP-port number X would end up at local TCP-port number X if.
