## Description of Product

NOTIS-DS is a database system designed to manage information belonging to an organisation. To manage means to keep information safe, to make it readily available to those who need it and are allowed access, and to protect it from all others.

The structuring itself follows the well-known model of a filing cabinet. A user may at any time list, on the screen, all documents to which he is allowed access. Searching for documents given abbreviated names and/or key words are standard features in NOTIS-DS. Access rights may be granted to personal users and to user groups.

NOTIS-DS’s structure is adaptable to each customer’s needs. This tailoring is simple and may be carried out by most end-users. For example, the structure may be tailored to emulate the public services’ filing systems. Access limitations may be implemented by controlling the structure and by grouping users into distinct access groups.

## Reason(s) for New Product or Version

The E version of NOTIS-DS offers improvements to safety, security, operations and performance.

- **Safety**  
  If the system or database crashes, NOTIS-DS will automatically restart under most circumstances. No verification or other action is required.

- **Security**  
  A number of extensions to the access control system have been made, according to needs observed at customer sites.

- **System Administration**  
  NOTIS-DS version E may have automated operational procedures. The routines used require minor tailoring to the customer’s actual configuration once and for all. Backup and verification may be night-time jobs. Both backup and verification routines are considerably faster than those for the D version.

- **SIBAS**  
  NOTIS-DS version E uses the SIBAS/R database system. This is the basis for the improvements in safety and system administration.

## 5 Installation Procedure

### 5.1 Before You Start

1) You should read the NOTIS-DS Supervisor Guide before starting (specially chapters 1-6).

2) If you already have a NOTIS-DS version E database, your database will not be affected by the installation.  
   However, the DS Emulator server must be stopped before installation.

3) If you have a NOTIS-DS version D database, you must take a backup of the database and verify the backup. The database must later be converted (see section 7, CONVERTING...).  
   The document server and the backup server may be running while you are installing the E version of NOTIS-DS.

4) If you have several computers in a network, you can have your database on one computer, and make it available to users on other computers. The computer holding the database is the **database computer**. Other computers with access to the database are **frontend computers**.  
   (Refer to the Supervisor Guide for more information on computer configuration and NOTIS-DS in a multimachine environment.)

5) You should install the following products before installing DS, if they have not previously been installed.

**On the database computer:**

- SIBAS/R Process
- SIBAS/R Libraries
- SIBAS/R Utilities
- SIBAS/R Backend for NOTIS-DS  
  (Only if you are installing NOTIS-DS/E on both frontend and database computer, and you are going to use TCP/IP communication between the two, and SIBAS/R Backend (version B) has not previously been installed.)
- Multi-machine Operator Environment
- SIBAS Manager

**On the frontend computer(s):**

- SIBAS/R Libraries

If you want to install a NOTIS-DS archive on a computer where SIBAS is already installed, SIBAS process number 23 must be free, as it is reserved for NOTIS-DS. The RT-program SIBRC must be started.

## 5.2 Automatic Installation

1. The installation program will take about 30 minutes.

2. Log in as user SYSTEM.

3. Insert the floppy 210794E-<lang>-01D into FLOPPY-DISC-1, unit 0.

4. Give the following command to start the installation procedure:

   ```
   @ENTER-DIRECTORY 210794E FLOPPY-DISC-1 Q-
   @(210794: FLOPPY-USER)IN-DS-XX-E-
   ```

   The installation program is divided into 5 modules. The modules must run in the right order from 1 to 5. Module 1 must run before module 3 and module 3 must run before module 4. You may run module 2 as often you like. Module 2, in particular, should be rerun if module 4 is interrupted.

   The program will guide you through the installation. When asked questions, press CARRIAGE RETURN unless you want an option different from the default displayed. You may press '?' to get help when asked questions.

   When replying to questions, you may give SINTRAN commands. You start the command with '@'.

   You may press ESCAPE to interrupt a module. If you exit the installation program in an abnormal way, you must give the command `@DEFINE-ESCAPE-CHARACTER,,,` from user SYSTEM to reset the ESCAPE character.

5. During installation SINTRAN user SYSTEM is defined as a friend of users DSBASE and DSLOGG with access RWACD. SINTRAN user DSBASE is defined as a friend of user DSLOGG with access RWACD. SINTRAN user RT is defined as a friend of user DS-SCRATCH with access RWACD and as a friend of user SYSTEM with access RWA.

## 5.4 After Installation

1. If you have copied the DDBTABLES file, remember to run the UEER-RENAME program on user SYSTEM. This program deletes old revision of DDBTABLES-G:VTM and renames the :NEW file to :VTM. It should be the first statement in the LOAD-MODE, job after @ENTER. You should then do a warm start before trying to run NOTIS-DS.

2. Include the following lines in the XMSG-START (or corresponding) file, to define the database computer (if not already defined):
   
   ```
   @(<SINTRAN user>)XMSG-COMMAND
   DEFINE-REMOTE-NAME..*DSSYSTEM <system number>
   DEFINE-REMOTE-NAME..*SIB<n> <system number>
   EXIT
   ```

   `<system number>` is the CPU number of the computer running the database. Give the SINTRAN command LIST-TITLE to get the system number. `<n>` should be an integer value between 1 and 326. If you already have other computers with *SIB<> ports defined in your network, make sure to employ an unused number. If you already have a *SIB<> port on your database computer, you must **not** define a new, additional one.

   **YOU NEED TO DEFINE THIS BOTH ON DATABASE AND FRONTEND COMPUTER(S).**

3. Include the next line in the (SYSTEM)LOAD-MODE (or corresponding) file after starting the SIBAS control program (SIBRC), SIBAS-MANAGER, and SET-AVAILABLE. This command starts the NOTIS-DS emulator server:

   ```
   @MODE (DS-PROGRAMS)DS-EMSTART-<rev>:MODE..↵
   ```

   Because you have the parameter AUTO-START-ON in SW-CONFIG, SIBAS Manager starts the DS database automatically.

   **You must start the NOTIS-ID mail servers after the DS emulator server.**

## 7 Converting Your Old DS/D Archive

**NOTE!!!** This chapter is **not** applicable if you already have a NOTIS-DS version E database.

1) If you have a NOTIS-DS version D database, you must convert your database with the program DS-CONVERT before starting to use DS/E. The conversion may take some time.

   See the NOTIS-DS Supervisor Guide for a description of how to convert your database and of the program DS-CONVERT.

   (If you have a version of DS older than the D version, you must install the D version before trying to convert to the E version.)

   The old document server and the new database must be running while you convert your database.

   During installation, NOTIS-DS/E is defined as a standard domain. If you need NOTIS-DS/D as a standard domain while converting the database, you must define this after the database password has been defined.

   Check the output from the conversion to see if the conversion has been successful.

   **When the conversion has run successfully, take a backup of your database.**

2) After the successful conversion of your database, you may delete the version D program files and domains by running these two jobs:

   ```
   @MODE (SYSTEM)DS-DEL-PRE-E<rev>:MODE (SYSTEM)DS-DEL-PRE-E<rev>:LIST
   @MODE (<user>)DS-DEL-PRE-E<rev>:MODE (<user>)DS-DEL-PRE-E<rev>:LIST
   ```

   `<user>` is the user area where the version D domain and program files are stored.
   You may delete the above files after the deleting is finished.

**NOTE!!!** Only if you have been running an **automatic installation**. After a non-automatic installation the old program files and domains must be deleted manually.

## 8 Modifications

### 8.1 New Functions/Commands

- Full logging and recovery functionality provides added security, to prevent the loss of documents as a result of a disk crash or computer failure.

- The function for creating user areas has been extended. When creating new users, you may copy the hierarchy from another user area. You also have a new function that copies the hierarchy from one user area to another.

- It is possible to run the NOTIS-DS program with a backup of the database by using the command `CHANGE DATABASE USER AREA` in the ADMINISTRATION menu in NOTIS-DS.

- When listing elements, you can write the list to a file as well as print it on a printer.

- There is a new access code, U=Unavailable, used to prevent access to elements.

- **From revision E02:**  
  When printing documents it is possible to specify if NOTIS-WP directives shall be expanded or not. If printing documents when expand directives on, the WP-PRINT module of NOTIS-WP will be used for printing. NOTIS-WP, version N08 or newer have to be installed on the machine.

- **From revision E02:**  
  The emulator service program, DS-EMSERVICE has two new commands. `LIST-CONNECTED-USERS` will list users currently connected to the emulator server. `DISCONNECT-USER` will disconnect an active user from the emulator server.

### 8.2 Changed Functions/Commands

- DS-SERVICE has been removed. Instead, you use SIBAS utilities and the ADMINISTRATION command in NOTIS-DS for supervisory functions. The ADMINISTRATION command, available only to supervisors, has subcommands for user administration, such as creating and deleting users, and managing user connections to the database. The program DS-EMSERVICE is for starting and stopping the emulator server and defining a remote NOTIS-DS system and password.
