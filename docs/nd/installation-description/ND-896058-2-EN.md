## 1 Read This First

The following things are required in order to use this product.

- **This Patch Kit requires versions B01 or B02 of the Basic Software Package for ND tpServer.** If the version A09 or earlier of the Software Package is used, you must upgrade it to version B01 first. This Patch Kit is generated with a SINTRAN III/VSX-500 standard C (250306 M06) and a Patch file 7400 (250360 M09).

- **Changing the CPU-number in the UE-DATABASE:**

  UE will no longer do an automatic change of CPU-number on its database if the CPU-number is changed (or the database is moved to another machine). If the CPU-number is to be changed you must run the program (USER-ENVIRONMENT)UE-CHCPU-D07:PROG before you start the UE P-SERVER.

  Even if the UE-DATABASE is not converted from another CPU, it is advisable to run this job because the 'machine name' sometimes is incorrect in the UE-DATABASE.

  It is very important that this is taken care of before you start installing this upgrading kit.

  The program UE-CHCPU-D07:PROG asks for the name of the database, the name and the CPU-number of the old machine. XMSG must be running and the local machine must be defined as the first machine name in XMSG.

  The latest version of this program must be used. It can be copied from this Patch Kit to the user area USER-ENVIRONMENT.

- **Software Keys (210507B)**

  After installing this Patch Kit, all previously installed software keys are lost and must be reinstalled. Ensure that the diskette(s) with all necessary software keys are available before you start installation of this Patch Kit. UNIQUE is a product which requires a software key.

- **Output to a connected printer.**

  By changing the variable TINFO, you can choose if you want the output to the console to be written on a printer or on the terminal.

  - **TINFO = 0** : the output will be written on the terminal
  - **TINFO = 20** : the output will be routed to a connected printer

  After installation of this Patch Kit, TINFO is set to 20. If TINFO and you do not have a printer connected to the console terminal, all output will disappear.

  To change TINFO, the following procedure should be used:

  ```
  @SINTRAN-SERVICE-PROGRAM
  *CHANGE DATAFIELD 1 I N Y Y
  TINFO/ nnn 0       (or 20)
  .
  *EXIT
  ```

## 11. Modifying for Special Modification Reports (SM Reports)

If you do not want to run any SM reports, verify that the file `(CONFIG-FILES)PF-MODIF-M:FADM` exists and consists of only one line containing the character `@`.

If you want to run some Special Modification patches, you must edit the file `(CONFIG-FILES)PF-MODIF-M:FADM` before you run the file `(SYSTEM)AFTER-COPY:MODE`.

A list of Special Modification Reports is found on page 23.

```
PN031
PN035
@
```

If you want to install additional SM patches at a later stage, follow the procedure described on page 43.

## 14. Edit the LOAD-MODE:MODE File to Reflect Actual Memory Size

Read the file `(SYSTEM)LOAD-MODE:MODE` into the editor PED and edit the commands used to initialize the ND-500 Monitor to reflect the actual memory configuration:

The example below assumes 8% Mbyte memory in the ND-100 part and 32 Mbyte memory on the MF bus (ND-5000 part).

```
@CC ---------------------------------------------------
@CC - Initialize ND-500-MONITOR
@CC - Prior to this task @START-SERVER is performed.
@CC - Take 500 pages to DMASRV.
@CC ---------------------------------------------------

@ND-500-MONITOR 1
@CC
@CC If you have a special memory configuration you could put it in
@CC here by using the following command:
@CC
@CC DEFINE-MEMORY-CONFIGURATION
@CC 10400           [10400₈ = 8% MB]
@CC 27400           [32MB-8%MB = 23%MB of MF-bus memory is visible from ND-100]
@CC Y
@CC Y
@CC N
@CC 10400           [All of MF-bus memory is visible from ND-5000]
@CC N
@CC Y
@CC Y
@CC Y
@CC CHANGE-CPU 2      [Handle CPU number 2 if applicable]
@CC LOAD-CONTROL-STORE,,,, 
@CC CHANGE-CPU 3      [Handle CPU number 3 if applicable]
@CC LOAD-CONTROL-STORE,,,,
CHANGE-CPU 1
LOAD-CONTROL-STORE,,,,
START-SWAPPER
TAKE-N500-PAGES 400D,,
EXIT
```

Edit the commands relating to your memory configuration and/or CPU configuration if applicable.

## 9 General Information

Defining OpenLAN printers with a SINTRAN spooling queue in SPRINT.

1. Select a SINTRAN logical device number between 2300₈ and 2377₈ (1216 to 1279 decimal).

2. Connect the logical device number to the COSPO datafield:

   Read the file SYMBOL-2-LIST:SYMB into an editor (for example PED) and find the symbol 'F1731'. Note the value of the symbol.

   In a standard M-version the value (datafield address) is 074330.

   **Note**   
   This address may be different in later version. You should therefore always verify the value of this address, because patching in the wrong address may cause serious damage to your system.

3. Then execute the following commands:

   ```
   @SINTRAN-SERVICE
   INSERT-IN-LOGICAL-UNIT-TABLE
   LOGICAL UNIT NUMBER (OCT): 23xx   (use the device number you selected)
   INPUT OR OUTPUT? OUT
   DATAFIELD ADDRESS (OCT): 072162   (use the address you noted above)
   MEMORY? YES
   IMAGE? YES
   SAVE-AREA? YES
   EXIT
   ```

4. Define the device number in the S3-CONFIG program and then perform a cold-start or use the command 'SET-SPOOLING-DEVICE' in the SINTRAN Service Program.

5. Define a peripheral file and spooling files in the usual way.

6. Stop COSMOS spooling by executing the command @ABORT COSPO   
   (Otherwise you will get the error message 'Device already defined' when defining the printer in SPRINT).

7. Define the printer in AIP-HOST:SYMB and SPRINT.

8. Start COSMOS spooling: @START-SPOOLING COSMOS-SPOOLING

9. Stop and start SPRINT.   
   (Otherwise you will get the error message 'Not opened for sequential read' when printing via SINTRAN III).

## Instructions

!! Do NOT restart a printer from SPRINT (without investigating first) !!  
If a printer gives an error message in SPRINT, check the printer itself.  
If no reason for the problem is evident, you may restart the printer.  

Unnecessary starting of printers will 'jam' SPRINT, and you may end up with the message 'Sprint is busy'.  

Note that OpenLAN printers may sometimes give 'misleading' error messages. If a printer stops due to paper crash or empty input-bin during a printout, the connection will stay open and give one of the messages 'Printer is occupied. Waiting for access' or 'Impossible to send data to printer' when printing from another system. These messages may then also mean paper crash if they do not disappear within reasonable time.  

ALWAYS check the printer itself before you do anything else.
