## 1 NOTICE

Multi-Machine OE (OEM) consists of a server part and a user interface part. The user interface part may only be installed on ND-500/5000 computers. The servers are to be installed on both ND-100 computers and ND-500/5000 computers. At least **one** machine in the cluster needs to have the user interface part installed.

## 2 INSTALLATION PROCEDURE

The system may be delivered on:

- 1.2 MByte, 2 inch or 5 1/4 inch double-sided diskettes  
  or  
- 0.3 Mbyte, 9 inch single-sided diskettes  

You must use the same kind of diskettes throughout the installation procedure.

The installation program is fully interactive, which means that once started, it will continuously check the operation. It will inform the operator if any error occurs and tell how to proceed. The operator is also asked some questions about the specific configuration. By typing "?" and "return", some additional information is provided.

### 2.1 How to start the installation

- Remember prerequisites, see page 1.
- The installation must be run from SINTRAN.
- Log in with SINTRAN user SYSTEM.
- Insert the diskette with the directory name 211078A<rev>-EN-01 into the diskette station.
- Execute these commands (operator input is underlined and parameters are enclosed in angle brackets:)

```
@ENTER-DIRECTORY,211078A-EN-01↵
DEVICE NAME: FLOPPY-DISC:<drive-no.>↵
DEVICE UNIT: <floppy-unit>↵
@(211078A:FLOPPY-USER)IN-OEM
```

The installation procedure has now started. It is self explanatory.

## 2.2 Questions the operator will get during the installation

On ND-500/5000 computers you will be asked whether the OEM user interface program is to be installed.

You may choose to:

1. Install the servers and the interface program (ND-500/5000 computers only), OR
2. Install the servers only

> Do you want to install the user interface program?

The OEM servers will log into User Environment, and execute on TADs. The installation program asks for a UE user to be used by the OEM servers. This user must not have a menu system, but have SINTRAN as standard task, and must log in to SINTRAN user area SYSTEM. The UE user name cannot have space in it. The UE name and password are used in the file MULTI-OE-START:MODE at system startup. If for security reasons you do not want this file on the system, you should delete it and start the servers manually. (See the manual for details).

> Which UE user do you want the Servers to use?

> UE password for this User <UE-User>?

## 3 Operating Procedure and Use

### 3.1 Loading the System

If you install the user interface program, you must remember to update your ND500-HENT file on user SYSTEM, to include the commands:

```
@ND-500-MONITOR
DEF-STAN-DOM OEM-STATU-A<rev> (ND-OPERATIONS)OEM-STATU-A<rev>
```

You must remember to update your HENT-MODE file under user SYSTEM with:

```
@MODE (ND-OPERATIONS)OEM-OETAD-R-A:MODE
```

and update your LOAD-MODE file under user system with:

```
@MODE (ND-OPERATIONS)MULTI-OE-START:MODE
```

which must be placed after UE has been started. This file is created during installation, and will contain a UE user and Password. The access is therefore NONE for public users. If you do not want this file on your system, you may choose to start the servers yourself, by the OEM-SERVICE command START-SERVER, e.g. in the LOAD-MODE file. For installations using the ACCOUNTING system, this is the only way to start the servers. For more information about how to start the servers manually, see the manual (reg. no. ND-30.101).

## 3.2 The File (ND-OPERATIONS)SW-CONFIG:SYMB

The file (ND-OPERATIONS)SW-CONFIG:SYMB must be updated with information for the OEM programs. A table in the file defines which machines are members of the operators domain (cluster). As an example of how to do this, the file (ND-OPERATIONS)OEM-SW-CONFIG:SYMB contains a skeleton entry for MULTI-OE with explanations. If you do not have the SW-CONFIG file on your system, you may rename the OEM-SW-CONFIG file to SW-CONFIG, otherwise you may append OEM-SW-CONFIG to SW-CONFIG.

The SYSTEM-NAME identifies the product, and must be set to OEM-MULTI.

The next entry is SERVER-NAME (optional). This enables you to specify servers that will be started up by OEM-MASTER, normally as part of a warm-start procedure. The servers started in this manner will execute on TADs. In the first version a maximum of 10 servers may be started. For each server you will have to specify a UE user and password. This is because the servers are logged on through UE. There are only a few exceptions to this rule, and OEM-SERVE is one - it does not require you to give the UE user name and password, but you must include a dummy user and password for consistency. Other system servers may use the same method. If you use this method to start your own servers, the servers will have to execute the call UESECCODE((SSI-CODE),0) as one of the first program statements.

The CLUSTER command enables you to define the members of the cluster. The servers will only accept requests from machines which have been defined as cluster members in the local SW-CONFIG file. These machines will also be the ones that the operator may select from the OEM user interface program. (Thus in order to perform operations on a remote machine, each machine will have to be part of the other machines SW-CONFIG cluster definition.) For more information on this, see the manual.

The TASK command is for internal use only, and must not be altered.

NB: The SW-CONFIG:SYMB file must only be edited with 7 bit format, e.g. PED.

To start the system after you have edited/created the SW-CONFIG:SYMB file, you must enter the command:

`@MODE (ND-OPERATIONS)MU-OE-START:MODE`

to start the servers, or use the OEM-SERVICE command START-SERVER.

You may then call the interface program by:

`@OEM-STATU-A`

## 4. Editing the Terminal Communication Parameters

Multi-Machine Operator Environment allows you to edit the terminal communication parameters, and the changes are updated in MEMORY, IMAGE and save, and will thus survive both a warm start, and a COLD-START.

## 5. The Send-Message - Broadcast Functionality

The message functions depend on SINTRAN K, work mode 312B or newer. If you have an older version of SINTRAN, the send-message or broadcast functions will return with 'Illegal function code', and the user interface program will terminate.

## 6. Integration with the OE Menues - OE >= A03

In order to integrate the OEM interface program with the OE menus, the installation program modifies the file OE-COMMANDS-AO:DATA to use OEM-STATU instead of the OES-STATU program for terminal and batch overview. The files OE-STATUS-SUBST:MODE and SUBSTITUTE:PROG are used for this purpose, and are deleted once they have been used.

To ensure integration with future release of OE, Multi-Machine OE must be reinstalled after a new version of OE is installed.
