## 1 Known, But Not Corrected Errors

- If the specified default file cannot be opened, default values are used, but no error message or warning is given. The user will think the default file was OK, and will not understand why wrong defaults are used.

- The accumulate function is not working properly if the field is not in the database.

- Groups cannot be used in expressions (compute, if, etc.). The compiler will not inhibit this and the application will not run correctly if groups are used in expressions.

- The :UNIQ compiler gives wrong error message (fields width too small) if the format code is not correct (eg '00001', '33').

- If a field is defined to be longer on the screen than in the base, UNIQUE will not handle this properly (the correction of this error will cause this to be illegal).

- UNIQUE cannot handle remote printers/files when using the print commands.

- MENU-COMM may be used to enter a new application with current record. Problem: current record is set from next field, not from the calling field. If next field is another record, then this record will be transferred.

- If F7 gives no result using a group key, all the fields in the group are set to zero. This makes the use of F7 very little user-friendly.

- If the file (SYS)DDTABLES-Exx:VTM is not available (does not exist, no access, ambiguous etc.), UNIQUE gets suspended without giving any error message.

## 3 Installation

### 3.1 Software Key, Protection of the UNIQUE-II Product

To avoid unauthorized installation of the product, UNIQUE-II uses the Software Key system of SINTRAN III. The Software Key is delivered along with UNIQUE-II. Assure that the Software Key is properly installed before installing UNIQUE-II.

If UNIQUE-II still does not start correctly, check with your local ND office that the CPU number of your SINTRAN III is correct. If SINTRAN III is generated with incorrect CPU number, it must be regenerated.

### 3.2 ISAM Data Buffer Size

The xxKB-ISAM-BUFFER:BRF files are used to set the ISAM data buffer size. Maximum size is 22Kb if the applications in your installation does not contain any SPECIAL routines. If there are SPECIALS involved, you have to reduce the ISAM buffer size at least as much as the data area size of the SPECIAL routines. The possible ISAM buffer sizes are 22-, 20-, 18-, 16-, 14-, 12-, 10- and 8Kb. By inspecting the load run, you will find out how much you have to reduce the ISAM buffer size.

Example: Data area size in SPECIAL routine = 2.5Kb.
ISAM buffer max. size = 22Kb - 2.5Kb = 19.5Kb.
=> You have to use 18Kb-ISAM-BUFFER:BRF.

In the course of the installation procedure you will be asked to specify the ISAM buffer size. When this occurs, answer 18.

Note: Loading the first PROG-file (A-UNIQ-II-I-B).

```
FREE : P 177777  D 175777
```

You must check that the data area upper limit is less than 175777. If it is greater than 175777, you will have to tune the SPECIAL's data area and ISAM buffer size so that this value will be less than 175777.

### 3.3 Installation Procedure

Create a user (default=DIALOG-SYS) and give 640 pages if you want to install both UNIQUE and the examples. You need 56 extra pages if you want to copy FORTRAN-2BANK.

Some of the files form an EXAMPLE system for introduction purposes. The EXAMPLE system consists of applications (:UNIQ), ISAM database (:INFO), :ISAM files and :DATA files. These examples are also found in the manuals.

## 3.3.1 SPECIAL TEST LOADING

It is possible to load/reload SPECIAL routines without loading the whole system. The PERFORM job UNIQ-TEST-B<rev>:MCRO is provided for this purpose.

The system is loaded on 4 segments instead of 3, and there will be more segment shifting using this method. Reloading the SPECIAL routines will only take 1-3 minutes depending on the size of the routines.

1. Run the job LOAD-MAIN the first time you are loading the system

2. Run DUMP-SPECIAL from user SYSTEM

When you have changed the SPECIAL routine:

4. Run the job RELOAD-SPECIAL

5. Run DUMP-SPECIAL from user SYSTEM

6. Repeat from 4) each time you have changed the SPECIAL routine

7. When the testing is OK, the system should be loaded with the normal load job.
