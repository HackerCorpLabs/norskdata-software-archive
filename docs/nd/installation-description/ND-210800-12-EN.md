## Installation Procedure

**NOTE:** This installation procedure requires BACKUP-SYSTEM version F or later.

If you want to preserve any of the files from your "old system" do make backup copies first.

### 1) Prerequisites

a) The product 210586C UE-ERRORS contains "standard error message texts for standard error codes (SEC)", in source form and is translated into a runtime file called UE-ERMSG-xx-Cnn:ERR, where xx is the language and nn is the version number.

For any other language, except English (EN) and Norwegian (NO), it is the responsibility of your regional support office to translate this product and supply the file UE-ERMSG-xx-Cnn:ERR.

b) The 210188F FOCUS product is only needed if any of the Y-command forms and/or article-record forms need editing. Please note that this product requires version F of FOCUS, and NOT any later versions.

### 2) Installing The Product

a) Log in as user SYSTEM.

b) Put the installation floppy into the floppy drive and enter it with:
```
@ENTER-DIRECTORY,,FLOPPY-DISC-<drive-no.>,<floppy-unit>
```

c) Start the installation procedure by typing:
```
@X (210800:FLOPPY-USER)INSTALL↓
```

This XCOM file will copy a secondary installation command file, ED100-INSTALL2:XCOM, to SYSTEM and call on that one.

If this product has been installed previously, user-modifiable files will NOT be automatically replaced. You will be asked if you want the new versions of the files installed, (and the old one deleted) or not. This will happen for the following files:

```
(MAINTENACE-NTX)LAMU-CONSTANTS:MODE
(MAINTENACE-NTX)LOAD-LAMU:MODE
(WORKFILES-NTX)TABFIL-EDITOR:DATA
(WORKFILES-NTX)NTXWP-FORM-NAMES:SYMB
(WORKFILES-NTX)FONTDEF-GR:FONT
(PARAMETERS-NTX)NTXWP-PARAM-:NTXP
(PARAMETERS-NTX)ADS-PARAM-:NTXP
(USERFILES-NTX)TYPO-FORMATS:DATA
```

# Important Parameters

The most important parameters are ("nn" means a 2-digit number):

- **HYnn** - Hyphenation table file.
  - Defines the correspondence between hyphenation language number (nn) used in the `<LGn>` typographical command and the hyphenation language.
  - HY01 must always be defined and determines the default hyphenation language.
  - All hyphenation table files are placed under user (USERFILES-NTX) at installation time and are called TAB-HY-xx:HBRF, where xx is the standard 2-letter abbreviation for the ethnic language.

- **TFnn** - Typesetter table file.
  - Defines the correspondence between typesetter numbers (nn) and typesetters, i.e. TABFILs for all phototypesetter output programs.
  - The nn-number also corresponds to the typesetter number used in article-records, and determines for which typesetter an article is justified.
  - There must be one TFnn definition corresponding to each FOTON RT-program. Two or more TFnn-definitions may point to the same TABFIL for identical typesetters.
  - TF01 **must** be defined.
  - All typesetter table files are placed under user (USERFILES-NTX) at installation time and are called `<Photosetter>`-100:DATA.

- **FFnn** - Format file.
  - Defines the correspondence between format group numbers (nn) and format files containing formats.
  - FF01 **must** be defined.
  - It is recommended to place the format files under user (USERFILES-NTX).
  - An empty initialized format file, (USERFILES-NTX)TYPO-FORMATS:DATA is distributed with this release.

## LAMUs in NORTEXT-100

LAMU means Logical Address Memory Units.

LAMUs are used for speed improvements by reducing disk I/O. Basically the LAMUs are pages fixed in memory, taken from the normal page swapping area. This means that the more pages used for LAMUs, the smaller the remaining swapping area will be - with a given physical memory size there is obviously a trade off with respect to overall system performance.

## In NORTEXT-100, LAMUs are used for:

1. **Hyphenation tables**

   1 to 10 LAMUs with 16 pages each are used for each language. The number of LAMUs depend on the amount of exception words defined. Another LAMU with 1 page is used for the hyphenation table header information.

2. **Graphic font definitions for "Graphic Option"**

   Approximately 23 LAMUs with a total of 65 pages are used for this purpose (for the released font-file).

   If any changes are done to the font definitions the requirements may be computed as follows: 1 LAMU of 1 page for the header, and 1 LAMU for each graphic font - size given by the SERVICE-GR program.

3. **Font information tables**

   Two font information tables are stored on each LAMU. Each LAMU uses 1 page. Another LAMU with 1 page is used for the font information table header.

   A flag ("Frequency") in the font description is set to force loading into LAMU. Thus the customer may control which fonts will be loaded, and this should of course reflect the anticipated frequency of use of the various fonts. Additionally, the maximum number of "LAMU-resident" font info tables is controlled by a variable in the "CONTROL-BLOCK" (program CONTRLBLOCK). If this variable is not set to a positive value, no font-info tables will be loaded into LAMUs at all.

4. **Memory resident formats**

   A number of LAMUs are used, each having one page. Each format that is "memory resident" is stored with its maximum size (as declared for the format file) in a LAMU. Several formats may be stored in one LAMU, but are not allowed to cross over from one LAMU to another.

   Global formats are marked as "memory resident" with the FORMATLIST-program.

## 5) Global Format Names

One LAMU is used, having a fixed size of 16 pages.

The number of LAMUs required and the number of pages used by these LAMUs should be adjusted according to the actual needs. To find out the actual needs, study the log written during LAMU initialization, (SYSTEM)LAMU-DIRECTORY:LIST.

### If the "number of LAMUs" must be changed:

- Edit the new requirement into `(MAINTENANCE-NTX)LAMU-CONSTANTS:MODE`
- Log in as SYSTEM and do

```
@MODE (MAINTENANCE-NTX)LAMU-CONSTANTS:MODE
```

- Warm start the system by:

```
@RESTART-SYSTEM
```

### If the number of pages for LAMUs must be changed:

- Edit the new requirement into `(MAINTENENCE-NTX)LOAD-LAMU:MODE`
- Log in as SYSTEM and execute:

```
@RESTART-SYSTEM
```

### If the contents of LAMUs must be changed:

In various cases the contents of LAMUs will need to be re-initialized. This might be due to changes in width-tables, memory resident formats, global format names etc. Normally LAMUs are initialized when the system is re-started. If you want to reload LAMUs without stopping the system, you must first make sure that nobody is using LAMUs (doing justification), and then go through the following steps:

- Log in as SYSTEM

```
@X (MAINTENANCE-NTX)DELETE-LAMU
   First lamu: 1
   Last lamu: nn   (look it up in "LAMU-DIRECTORY:LIST")
```

- `@(MAIN-NTX)LOAD-LAMU:PROG`

- Wait until loading is finished, then inspect (SYSTEM)LAMU-DIRECTORY:LIST.
