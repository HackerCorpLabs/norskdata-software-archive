## DESCRIPTION OF PRODUCT

Backup Manager is a program system for backup and restoring on ND-500 and ND-5000 computers. Backup Manager consists of four modules:

- **BM-Definition**  
  To predefine sets for backup and restore.

- **BM-Operator**  
  To run predefined sets, do occasional copying and service functions.

- **BM-Scheduler**  
  To schedule backup sets and ordinary SINTRAN batch-jobs in a COSMOS network.

- **BM-FileRestore**  
  To restore single files from image (device) backups stored in volume format on tape or disk.

## REASON(S) FOR NEW PRODUCT OR VERSION

- Handling Unix TAR (Tape ARchive) format on sequential media
- All known errors from previous versions have been corrected
- Improved stability and robustness

## 4 Installation Procedure

### 4.1 Automatic Installation

- Before you start installing Backup Manager, check that the prerequisites listed in Chapter 1 are fulfilled.

- Note that it is possible to install Backup Manager without an interface to SIBAS. This is selected during the installation procedure.

  If an interface from Backup Manager to SIBAS is wanted the following three possibilities exist:
  
  - SIBAS/R-B interface (new domain format-automatic inst. proc.)
  - SIBAS/R-A interface (old domain format-manual inst. procedure)
  - SIBAS-F interface (old domain format-manual inst. procedure)

  In any case, Backup Manager should be installed the standard way by use of the installation program. For the two latter possibilities (old domain format) the standard installation should be performed with NO SIBAS interface. Thereafter the BM-Operator domain should be reinstalled in the old domain format with link to the correct SIBAS version as described in section 4.4. The 2 floppies 211226C01-XX-06D and 211226C01-XX-07D are exclusively delivered for this purpose and are therefore not requested by the installation program. For the manual reinstallation of the BM-Operator domain in old domain format in order to interface SIBAS/R-A or SIBAS-F see section 4.4.

- Log in on user area: **SYSTEM**.

When installing Backup Manager C, the file BM-JOBDB-C:DATA is copied to user ND-OPERATION. This file includes some SET examples which can be modified to your needs. (This gives you the opportunity to implement the new features offered by the C-version.)

Due to changes in the internal format of the Backup Manager database from the B to C version (BM-JOBDB-B:DATA -> BM-JOBDB-C:DATA), all your previously defined SETs must be converted. So if you already have a B-version installed (B01/B02/B03/B04/B05) and you want to keep the old SET and JOB definitions, the file (ND-OPERATION)BM-JOBDB-C:DATA must be deleted and the SET conversion program (BM-JOB-CONVERT-C:DOM) must be run. See section 10.4.

## 9 Information and Hints

- When doing image backup, it is possible to skip compare of selected CONTIGUOUS files (for example, Segfile and Swapfiles).   IMAGE-NO-COMPARE-FILE = (SYSTEM)SWAP-FILE-0:SWAP
  IMAGE-NO-COMPARE-FILE = (SYSTEM)SEGFILEIO:DATA

## 10 Handling TAR Tapes

### 10.1 Copying files to TAR format

When copying SINTRAN files to magtape/streamer, there exist 2 ways of specifying which files to copy:

1. By specifying FILE as 'Copy method' and giving appropriate 'From' and INCLUDE/EXCLUDE selection parameters. The destination Unix file names (stored in the TAR header blocks on the tape) will be generated by a standard file name conversion algorithm from the SINTRAN filename and filetype.

2. By specifying SELECTION FILE as 'Copy method'. The name of a selection file will be prompted. All files named in the selection file will be copied. If a selection does not give exact match, all matching files are selected. In the case of an exact match, a distinct destination Unix file name may also be given. Otherwise the standard file name conversion algorithm will be used.

#### 10.1.1 Selecting files by use of 'From' and 'Include/Exclude' selections

Example:

| Object   | Copy method | Incremental |
|----------|-------------|-------------|
| SINTRAN  | FILE        | NO          |

| From      | Computer name | Directory Name | User area | Control |
|-----------|---------------|----------------|-----------|---------|
| DIRECTORY | PACK-TWO      | A              |           |

| To  | Computer name | Device name | U S | Mode    |
|-----|---------------|-------------|-----|---------|
| TAR | STREAMER-1    |             | O   | Ov, Sm  |

| Selection | File name | Selection date |
|-----------|-----------|----------------|
| INCLUDE   | :TEXT     |                |

## Comments:

- **'Object':** The objects to be copied are still 'SINTRAN'

- **'From' fields:** Copy from all users starting with 'A' on PACK-TWO

- **'To':** Select TAR instead of VOLUME (the volume concept does not exist in the TAR format, i.e., Volume name is not prompted).

- **'Mode':** Available mode parameters:
  - **Ov:** Overwrite tape
  - **Oe:** Overwrite if blank tape or if the tape contains files in TAR format already (prevents overwrite of SINTRAN volumes or other data)
  - **Re:** Retension
  - **U1:** Unload tape after copy
  - **Sm:** Shrinking mode; the file is copied according to the maximum bytecount of the file (default)
  - **Ns:** No shrinking; the file is copied according to the number of pages in the file
  - **(Ap):** Append; this option is not implemented

- **'Selection':**
  - **INCLUDE:** Include all files matching the specifications in the 'From' fields AND the specification in at least one of the INCLUDE lines (max 5).
  - **EXCLUDE:** Include all files matching the specifications in the 'From' fields AND NOT ANY of the specifications in the EXCLUDE lines (max 5).

In the example above, all :TEXT and :SYMB files from all user areas on PACK-TWO with 'A' as the first character will be copied.

### Comments

The format of the selection file is mainly unchanged, i.e., each line to be accepted as a selection has to include a '(' (left bracket) from where the actual selection starts (start of possible directory and user name).

A date selection may be specified (see existing manual).

Behind the optional date selection, an explicit UNIX path name may be specified to give the destination path name exactly as wished. This must, if wanted, be specified on each selection file input line. No checking of the specified path name is done.

If this `destination path` is not specified, BM-Op will generate the path name to be written on the tape from the SINTRAN file name by simply adding `./` (period and slash) in front, skipping all non-Unix characters, and replacing the ':' (colon) with '.' (period) as the separation character between the object name and the file type (default file name conversion).

**NB!** If a selection line, containing a destination Unix file (path) name, does not give exact match on the SINTRAN specified file name (source), the destination Unix file (path) name will be generated from the expanded SINTRAN file name and the specified path name will be ignored.

## 10.2 Restoring files FROM TAR format

When copying SINTRAN files from a magtape/streamer containing files stored in TAR format, there exist 2 ways of specifying which files to copy:

1. By specifying FILE as 'Copy method' and giving appropriate 'From' and INCLUDE/EXCLUDE selection parameters. The destination SINTRAN file names will be generated by a standard file name conversion algorithm from the UNIX filename and type as found on the TAR tape.

## 10.2.2 Selecting Files by Use of a Selection File

When restoring files from TAR tapes you may also use a selection file. Each line in this file has to start with a selection path name. It may be followed by an optional date selection (W is the only valid selection letter) and finally an optional destination SINTRAN file name. If no destination file name is given, BM-Op will generate a SINTRAN filename from the UNIX file name. This filename conversion is done by replacing all non-SINTRAN characters with a hyphen (-). All file name characters from position 16 and outwards are skipped. Likewise, only the first 4 characters of the file extension are kept. The delimiter character is of course changed from '.' (period) to ';' (colon). The logged in user (and its default directory) is used as destination user area.

## 10.4 New format of the BM Job database

The structure of the BM-JOBDB database (containing the predefined backup and restore SETs) has changed from earlier versions. This means that the file (ND-OPERATIONS)BM-JOBDB-B:DATA must be regenerated. This program is delivered together with Backup Manager C. It takes the file (ND-OPERATIONS)BM-JOBDB-B:DATA as input, reads all the SET, JOB and SUBJOB records, converts them to the new format and writes them back to the file (ND-OPERATIONS)BM-JOBDB-C01:DATA.
