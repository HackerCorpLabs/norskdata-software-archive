## 1 Errors Corrected

Especially definition module and scrolling table handling, but also quite a few compiler and runtime errors.

## 2 Known, But Not Corrected Errors

The reader is referred to the SIS database at CTS, Skullerud.

## 3 Changed Prerequisites

Newest version of COBOL = J02 is required. NOTIS WP version M07 or Nxx and SPRINT version >= A02 is also required. To store wide columns in a database, SIBAS/R is required (Expected release summer '88).

## 4 Modifications

Compared to the version B10 release, this version of BIM has increased performance by approx. 30% and offers a possibility to use free text fields (= wide columns in SIBAS). NOTIS WP is fully integrated and can be entered both through a BIM system program (called WP) and through a BIM statement. There are also other new BIM statements, including UNSTRING. The data transportation rules (i.e. COPY, COMPUTE, Database retrieval) have been altered. Several limitations have been removed, these include the number of numeric fields in a fieldset, the number of lines in a report layout and the number of pages in a report. FOCO now uses the tabulatorkeys for tabulation which is especially important in NET ONE installations. Indexes are now alfanumeric which means that it is possible to run BIM with most old databases. See also the separate text which should follow this PD sheet.

### 4.1 Changed Commands

The tabulator key now works as a tabulator in FOCO. Each key stroke moves the cursor ten positions. On the program selection line the CR key will start the specified program when the cursor is positioned in the program name field.

### 4.2 Removed Commands

### 4.3 Improved Performance

An average of 30%, but a lot more for some statements e.g. the CALL and PRINT statements (7 - 10 times faster). The new functionality (like UNSTRING) makes it possible to write more efficient application programs.

# 5.5.1 Linking Up BIM

**READ THE COMPLETE SECTION BEFORE STARTING THE LINKING!!!!!**

**SPECIALS:**  
If your system contains specials i.e. non BIM subroutines, the `(BIM-INSTALL-500)BIM-USEREXI-C<rev>:SYMB` file MUST be recompiled (target file - `(BIM-INSTALL-500)BIM-USEREXI-C<rev>:NRF`) before the linking starts. This requires the COBOL compiler of course. (To see which specials are compiled into BIM, you can look at the file `(BIM-USER)BIM-CALLSPEC-C<rev>:COPY` which contains the COBOL calls to these routines.) If this isn't done before linking BIM, attempts to enter a special routine will result in an error message runtime indicating that recompilation/linking has been forgotten. In the same way, new `:COPY` files for the specials MUST be generated by using the C version of the BIM compiler on the calling BIM programs. Then the specials must be recompiled with the COBOL compiler. This indicates that the BIM compiler perhaps should be linked first in an environment with specials. Otherwise the processors must be linked twice (Compilation ordering can be done in the B version of the processor).

**NOTE:**  
If you have BIM as a Standard Domain on your machine already, it is important to delete the standard domain before the new linking starts (must be done from user SYSTEM in the ND-500/5000 monitor).

The linking is taken care of by the set of modefiles:

```
(BIM-INSTALL-500)BIM-DUMMY-C<rev>:MODE
(BIM-INSTALL-500)BIM-MBI500L-C<rev>:MODE
(BIM-INSTALL-500)BIM-MBB500L-C<rev>:MODE
(BIM-INSTALL-500)BIM-MFI500L-C<rev>:MODE
(BIM-INSTALL-500)BIM-MFC500L-C<rev>:MODE
(BIM-INSTALL-500)BIM-MOD500L-C<rev>:MODE
(BIM-INSTALL-500)BIM-MRF500L-C<rev>:MODE
(BIM-INSTALL-500)BIM-MSB500L-C<rev>:MODE
```

or the main modefile

```
(BIM-INSTALL-500)BIM-RUNT-LNK-C<rev>:MODE
```

which executes the above modefiles in correct order.

**NOTE:**  
The modefiles must be run while logged on as user BIM-USER (to get the domains placed on BIM-USER). Ignore the redefinition warnings from the Linkage-Loader when linking the COBOL library (error in Linkage-Loader).

# About the Linking Jobs:

To help understand this explanation it is useful to have the last page of the file `BIM-MBI500L-<Crev>:MODE` displayed in an editor. The linking jobs are prepared for linking standard SIBAS version F and English NOTIS WP version MO7 installations, but they also contain the SIBAS/R and NOTIS WP version N link commands commented out with "@@" in column 1 and 2. In the following, the SIBAS notes concern the files `BIM-DUMMY-<Crev>:MODE`, `BIM-MBB500L-<Crev>:MODE` and `-MBI500L:MODE` file while the NOTIS WP notes only are relevant for the `-MBI500L:MODE` file. The Infologic applications notes concern the `BIM-MBI500L-<Crev>:MODE` and `BIM-MBB500L-C<rev>:MODE` files.

If/when SIBAS/R is required the linking jobs must be edited. This is done by commenting the lines:

```
LOAD-SEGMENT (BIM-I-500)BIM-STOWIDE-DUMM:NRF
LOAD-SEGMENT (BIM-I-500)BIM-GETWIDE-DUMM:NRF
FORCE-SEGMENT-LINK (SIB2-500)SIBAS-LIBARARY-F
```

with "@@" and taking away the ("@@") comments in the lines:

```
@@LOAD-SEGMENT (BIM-I-500)BIM-STOWIDE-<rev>:NRF
@@LOAD-SEGMENT (BIM-I-500)BIM-GETWIDE-<rev>:NRF
@@FORCE-SEGMENT-LINK (SIB2-500)SIBR-LIBARARY-A
@@GLINK-SEGMENT (SIB2-500)SIBR-MESS-TS-A
```

Similarly, you change from NOTIS WP version M to version N by commenting:

```
LOAD-SEGMENT (BIM-I-500)BIM-CALLWP:NRF
FORCE-SEGMENT-LINK (NOTIS)NOTIS-WP-EN-M
(language code "EN" may be changed to "NO" if desired)
```

and taking away the comments in the lines:

```
@@LOAD-SEGMENT (BIM-I-500)BIM-CALLWPN:NRF
@@FORCE-SEGMENT-LINK (NOTIS)WP-500-N
```

## 5.5.2 Initiating Procedure

In BIM you must choose the system message language at installation time. This was probably done when you copied the message files from BIM-INSTALL-500 to BIM-USER. Internally BIM only refers to one (language independent) file name where it expects to find the messages. Therefore the selected message files must be renamed to these names. ## Reinstallation of BIM:

If you already have BIM, and are only installing a new version, we suggest the following procedure to be followed from here on:

- Don't run the BIM-INITSY-<Crev> program (below); you already have all the catalogues you need.

- The table catalogue is the key to all other catalogues and programs in the system. Since the contents of your table catalogue is unaltered using this procedure, you should still be able to run BIM as before (i.e. with the old BIM system program library) with one exception; BIM versions > A1Ø cannot use older BIM system program libraries (this causes a runtime error) which means that you cannot enter the C version of BIM before the table catalogue refers to a version larger than A1Ø of the BIM system program library. At the same time it is impossible to alter the table catalogue reference from outside BIM. If you are in this situation (or if the old program library has been deleted), you have to use a trick: Delete/rename the old program library (to anything other than the old name). Then rename the new library (version C<rev>) with the old name/version (version A<rev> or B<rev>). BIM-C<rev> will now run with the new BIM system program library because the program library now has the same name as that referred to in the table catalogue. (The BIM system program library is contained on the two Sintran files "BIM-PBPBIBL-<rev>:DATA" and "BIM-PBPBIBL-<rev>:ISAM").

- To get the correct version suffix back on the program library name (="-C<rev>") edit the referenced program library's name in DTAB to "BIM-PBPBIBL-C<rev>" by entering system = BIM, Org.unit = TEST, version = 0120 and table name = BPBIBL in DTAB's heading fields before using F5 = get and then the editing. Leave BIM and rename the library back to the C<rev> version suffix.

- If you haven't edited the reference (=updated version) to the BIM system program library in DTAB or done any renaming in Sintran as outlined above, you will now be running the C version of BIM with an old BIM system program library. To run the new program library, just edit the reference in DTAB as described above.

- To get a better understanding of the table catalogue, you are recommended to study the program "DTAB" (= update table catalogue) some more by looking at the other file references in the table catalogue.

## FIRST INSTALLATION OF BIM:

Before it is possible to enter BIM, some BIM system catalogues must be generated/initiated (ISAM files). This is done by running the program

```
@ND BIM-INITSY-C<rev>
```

logged on as user "BIM-USER". When prompted for "INPUT FILE?" you answer

```
BIM-INITSYST-C<rev>:DATA
```

You will then see/get some messages concerning the catalogues which are being created.
(The table catalogue MUST be stored on user "BIM-USER". For all other catalogues the user is optional. Unedited, "BIM-INITSYST-B<rev>" puts all the catalogues on "BIM-USER".)

Finally, the user-catalogue is initiated by entering ISAM-SERVICE logged on as user "BIM-USER" and giving the following commands:

```
@(BIM-USER)ISAM-SERVICE

>>OPEN BIM-PRUKAT-A00

>>LOAD BIM-BRUKINIT-A00:DATA

                  Number of records loaded :  4

>>EXIT
```

This makes the BIM-users "SYSTEM" with password "TURBOX", "BATCH1" with password "BATCH1", "BATCH2" with password "BATCH2" and "BATCH3" with password "BATCH3" known to BIM

**NOTE:** Has nothing to do with Sintran users). To start BIM use the command

```
@ND (BIM-USER)BIM-C<rev>
```

**NOTE:** JEC must be dumped reentrant or lie on user SYSTEM to get all parts of the system to operate properly.

## 5.7 Full Catalogue

The following explanation does not relate to installation, but is included in the PD sheet in case the situation occurs.

As mentioned all ISAM files (= catalogues) must be continuous. Should you ever experience that a catalogue is full, follow these instructions:

a) Enter ISAM-SERVICE and unload the full file to a user specified file:

```
@(BIM-USER)ISAM-SERVICE
>>OPEN <isam file>
>>UNLOAD "<user specified file>"
```

Number of records unloaded: nn

```
>>EXIT
```

b) Rename the full ISAM file (i.e. both the OS-files) with the commands

```
@RENAME-FILE <old name>:DATA,<new name>:DATA
@RENAME-FILE <old name>:ISAM,<new name>:ISAM
```

while logged on as the user where the files are stored.

c) Create the original ISAM file again, but this time as a larger continuous file. This is done by running the program

```
@ND (BIM-USER)BIM-INITSY-C<rev>
```

again, but with a re-edited version of the file

```
BIM-INTUSER-A<rev>:DATA on user <System>
or BIM-INTISYST-B<rev>:DATA on user "BIM-USER"
```

as input. The re-editing consists of specifying a larger number of records(=rows) for the file in question, and writing "N" in the column for "Create file (Y/N)" on the other files and make these lines comments by writing "*" in column no. 1.

**Note:** There must be enough unused continuous space on the owner of the ISAM file to create the new file.

d) Enter ISAM-SERVICE and load the unloaded file back to the original file as described in section 5.6, this time using the file-names from above in stead, of course. If the operation was successful, the renamed files can be deleted.
