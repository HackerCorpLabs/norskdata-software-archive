# Installation Procedure

## 4.1 Automatic Installation

### 4.1.1 Preparations

Prior to the installation, please verify the following:

- Ensure that the user areas specified in Chapter 1.3 exist with the required number of free pages and free files. If not, find a directory having enough space to hold the users areas. The installation program will try to allocate space whenever needed, but you may need to specify on which directory to create user areas.

- The following files will be loaded with XTRA:

| Abbrev. file name | Default user area(s)    |
|-------------------|-------------------------|
| UE library        | USER-ENVIRONMENT        |
| UE-PLIB           |                         |
| SIBAS F library   | DIALOG-SYS, SYSTEM      |
| SIBLIB-2B         |                         |

Check where these files are installed. If not installed on the default user area, the installation program will ask where to find these files.

- If you already have a version of XTRA installed, you should make sure it is not dumped reentrant. Delete it prior to the installation.

- Ensure that your configuration fulfills all other requirements mentioned in Chapter 1 and 2.

### 4.1.2 Installation from Floppy

- Put the diskette 211262C<rev>-XX-01D into the floppy drive.
- Log in to user area SYSTEM.
- Enter directory 211262C-XX-01D.
- Run the INSTALL program on the diskette.

Example: how to enter the directory and start the installation program.

```
@ENTER-DIRECTORY 211262C FLOPPY-DISC-1 0↵

@(211262C:FLOPPY-USER)INSTALL↵
```

The following screen will appear:

```
┌──────────────────────────────────────────────┐
│                I N S T A L L A T I O N       │
│          X T R A  R U N T I M E  N D 1 0 0   │
│              V E R S I O N  C x x            │
│                                              │
│ Unique A/S                    Date : 22-JUN-87│
└──────────────────────────────────────────────┘
```

You may ESCAPE at any time to abort the installation procedure.  
Choose one of the following options:

1. CREATE : Create user and allocate space  
2. COPY   : Copy files from floppies  
3. LOAD   : Make and run load procedure  
4. DUMP   : Dump system reentrant  
0. EXIT  

Make your selection (1/2/3/4/0):

The installation program will ask you for some information (e.g. user areas, directory names etc) but will usually suggest reasonable default values. You can answer these questions by typing ↵ (the ENTER key) thus using the default value.

You may install XTRA on any user area, but DIALOG-SYS is used as default in the installation program.

The installation program can do the following:

- **CREATE**: Create a new user area (or verify an existing one) for XTRA
- **COPY**: Copy all files from the floppy to the desired user area.
- **LOAD**: Load the XTRA Runtime program.
- **DUMP**: Dump XTRA Runtime as a reentrant program.
- **EXIT**: Leave the installation program and return to SINTRAN.

The first time, run all the tasks 1-4, one at a time, in sequence. To reload XTRA, run tasks 3 and 4. To re-dump XTRA, run task 4.

When selecting the CREATE or COPY option, and an (old) version exists on this user area, you are asked if these files should be deleted. You may answer Yes, No or Manually. When answering YES, program files, domain files, .MODE and .LIST files of current and previous versions/revisions will be deleted. Afterwards the program checks if there are enough free pages on the user area.

When selecting the LOAD option, there are some questions that need an explanation:

## SEGMENT

'Give SINTRAN segment name to load UNIQUE on /XTRIC/'

UNIQUE is loaded on 4 SINTRAN segments which will be named A<seg>, B<seg>, C<seg> and D<seg> respectively, where <seg> is the answer to this question.  
NOTE: Maximum 5 characters in the answer.

## SPECIAL

'Do you want to load any SPECIAL routines (Y/N)? /N/'

If you answer Y, the program will ask for the name of the .BRF file which the special routine has been compiled into. Answer N (or ↵) if you don't have any special routines. See also chapter 4.1.4.

## LANGUAGE

'Language to be used if UE is not active? /NO/'

By default UNIQUE will use the language found in the user profile in User Environment. The answer to this question selects the language to be used if UE is NOT active on the terminal running UNIQUE.

## NOTIS-WP

'Which version of NOTIS-WP will be used (M or N) /M/'

Answer M (or ↵) if you have the M version of NOTIS-WP. Answer N if you have the N version of NOTIS-WP.

## SW-CONFIG

`Should it be legal for users to define their own SW-CONFIG:SYMB file? /N/`

Answer `y` if you want to allow users to have a personal copy of the configuration file.  
**NOTE:** This should not be allowed if the UNIQUE access control is activated in the global SW-CONFIG:SYMB file. Users will then be able to bypass the control system.

After a successful installation of UNIQUE XTRA, you must update the system startup file (SYSTEM)HENT-MODE:MODE with the following command:

```
@MODE <(user)>XTRA-DUMP-R1-C:MODE <(user)>XTRA-DUMP-R1-C:LIST
```

where `<(user)>` is the name of the user area where the :PROG files are loaded.

## 4.1.3 Subsequent Installation

If at a later date you want to reload or re-dump XTRA, you can use the installation program that is automatically copied from the floppy disc during the first installation. To re-run the installation program, log in to user area SYSTEM and type:

```
@(DIALOG-SYS)XTRA-IN-R1-C~
```

To reload XTRA, run tasks 3 and 4. To re-dump XTRA, run task 4. You may of course also reuse the created load/dump procedures (:MODE).

## 4.1.4 Implementing Special Routines

To install a special routine the following must be done:

- Write the routine in PLANC, COBOL or FORTRAN.
- Compile it with the appropriate compiler.
- Run the installation program and select the load option.
- When the program asks if you want to load a special routine you must answer YES.

## 4.2 Non-Automatic Installation

Create a user area with the number of pages mentioned before and copy all the :BRF and :MODE files from the floppy into it.

Log in to the user area containing the XTRA files.  
Edit the file `>XTRA-LOAD-R1-C:MODE` to suit your installation and run it by typing:

```
@MODE XTRA-LOAD-R1-C:MODE "XTRA-LOAD-R1-C:LIST"↵_
```

Update the file XTRA-DUMP-R1-C:MODE in a similar manner, and run it from user SYSTEM to dump XTRA Runtime reentrant.

## 5 Modifications

The manual DIALOGUE-UNIQUE Release Information (ND-860351) provides details about new functions and modifications implemented in revision C10.

For the sake of completeness, we have chosen to include also the modifications implemented mainly for report design.

> Note: There is no official revision C11 of XTRA

### 5.1 New Functions/Commands

**Revision C13:**

- When writing to a SPRINT printer, the following NOTIS-TF macros are now expanded by XTRA:
  ```
  ^FONT=<i>;      ^VP=<i>;
  ^NAT=<i>;       ^HP=<i>;
  ^BIN-IN=<i>;
  ```
  The rules are as for NOTIS-TF.

  ^VP and ^HP must be written on separate lines not containing other text.

- CTRL-V in the report menu will display the current version number and system name in the status line.

### 5.2 Changed Functions/Commands

**Revision C13:**

- The internal fields ^Date and ^Time are updated when
  - the fields are used in expressions.
  - the fields are written to the output device.
  - the fields are used in a STORE / MODIFY function.

- XTRA now documents display code on hidden fields when describing a report to a :XTRA file. The display code is then available if the field is made visible later on.

## 5.4 Other Modifications

*Revision C13:*

- Improved support for NOTIS-WP version N is implemented.
  - Version N08 has a new subroutine interface which is now supported by XTRA.
  - NOTIS-TF with DS syntax in the filename parameter may be used provided the following is done in SW-CONFIG:SYMB:  
    (this functions properly for NOTIS-TF >= N09 only).

      ```
      system-name: <the actual system name>
      NOTIS-TF ='NOT-TF SINTRAN,,'
      ```

    NOTE the syntax!!!

- Due to changes in the S-format required in different versions of the NOTIS products, a new file must be present on user DIALOG-SYS. 
  This file is named UQ-ND-S:INI and must have public read access.

  All S-format files produced by UNIQUE products will have the same S-format header as the file (DIALOG-SYS)UQ-ND-S:INI.

  UQ-ND-S:INI is an 'empty' file containing only an S-Format header matching the version of NOTIS-WP you are using on your machine. By storing the S-Format header in a file, it is possible for you to define the default settings and rulers. UNIQUE will read the default header from this user defined file, if it exists.

  If you start using a version of NOTIS-WP with a new S-Format, e.g. going from WP version M to N, just repeat the procedure described below and UNIQUE will produce documents readable by the new WP version.
