## Purpose

The IBM 3780/2780-II Emulator is made for file transfer between ND computers and computers from any other manufacturer. The mandatory requirement is that both computers can emulate at least one of the IBM binary synchronous communication (BCS) protocols 3780/2780/2770.

## Installation Instructions

Before starting the installation, please find and remember:

a. One free segment for each emulator

b. One RT program name for each emulator  
   (proposed names: EMUL1, EMUL2 etc.).

c. One free internal device for each emulator.  
   Verify that this device exists and can be reserved when the emulator is started. (Use the List-device command in SINTRAN, and inform the system supervisor.)

d. The device number and the type of the line (synchronous or asynchronous interface).

The files from the diskette are copied to the disk, any user. User BPUN-USER is used in the examples in this documentation.

### Installing the Emulator EMUL-OPCOM Program

This program is a normal background program with a SINTRAN-like command processor and a set of commands to supervise the emulator. When a command is executed and parameters are collected, this program passes the information to the emulator through an internal device.

EMUL-OPCOM for only one emulator. The device number for the internal device is an installation parameter for the OPCOM program, and this number must be equivalent to the corresponding parameter defined for the emulator (see description below). The file EMUL-OPCOM:PROG is delivered with this parameter set to 201 (octal), and if this agrees with your installation, the next step is skipped. If you have chosen a different internal device, then start FMAC with image file EMUL-OPCOM:PROG and change location 400:

```
&FMAC
image file:EMUL-OPCOM:PROG
400/201 Octal value for the internal device, then return>
)EXIT
```

Then copy the file to user SYSTEM, if it is to be used from other users.

EMUL-OPCOM for more than one emulator. If you want to use more than one emulator of this type at the same time, the OPCOM program can communicate with all of them if the corresponding internal devices are given to the OPCOM program (max 8 emulators for one OPCOM program). This is done by inserting the device numbers in addresses.

## Installing the Emulator RT-program

Create a modefile to load the file EMUL-MAIN:BPUN on a segment using the RT-Loader. Start with the delivered file EMUL-RTLOAD:MODE, and edit the installation parameters to suit your configuration.

The installation parameters are:

| Parameter | Type      | Description                                                        |
|-----------|-----------|--------------------------------------------------------------------|
| <user>    | (chars)   | user name for the EMUL-MAIN:BPUN-file                              |
| <seg>     | (octal)   | segment number                                                     |
| <name>    | (chars)   | name of the RT program                                             |
| <prior>   | (octal)   | priority of the RT-program                                         |
| <modem>   |           | device number for the (modem) line                                 |
| <linetyp> |           | 1 for synchronous line, 0 for asynchronous                         |
| <opdev>   |           | internal device number for operator com.                           |
| <errdev>  |           | device number for messages from the emulator (normally the same as SINTRAN error device, the emulator will not reserve the device. For SINTRAN I-version or later, device number 2 can be used). |

Substitute the symbols above (including < and >) with your actual values, and write the result to a new file with the name indicating the actual emulator (e.g., EMUL1-RTLOAD:MODE for emulator 1, EMUL2-RTLOAD:MODE for emulator 2).

The parameter `opdev` must correspond to the definition when installing the OPCOM program.

In case of more than one emulator RT-program of this type, please note that the parameters `<seg>` and `<name>` must always be different. In addition, if the emulators are to be used at the same time, parameters `modem` and `opdev` must also be different.


To start the program, use the SINTRAN command RT:

```
ØRT EMUL
```

When the emulator is running, you can communicate with it from any terminal by starting the OPCOM program:

```
ØEMUL-OPCOM
```

If defined for more than one emulator, EMUL-OPCOM will ask for the emulator number. The selected emulator must be running, else an error message is given. The HELP command gives a list of available commands and their parameters.

Create the message log file.

Create the file `(RT)EMUL1:LOG`.

The emulator will log the names of all transmitted and received files on this file, and it may at any time be inspected by an editor. (The last part of it is normally the most interesting.) The file will be inaccessible for the editor for very short intervals when it is updated. If you do not succeed in reading on the first attempt, try again.

Initialize the emulator.

When the emulator is running, parameters can be given to it by the operator commands, and also in mode files. It may be convenient to append some commands to the load file (e.g., EMUL1-RTLOAD:MODE etc).

An example (from the end of a load file):

```
ØRT EMUL1
ØHOLD 4 2    (ensure that the emulator is started)
ØEMUL-OPCOM
ASS-OUTPUT   (assign channel 0)
C
0/(REMOTE-USER)EMUL:PRIN
ASS-OUTPUT   (assign channel 1)
C
1/(REMOTE-USER)EMUL:PUNC
PROTOCOL     (set 2770-emulator, 3780 is default)
2770
COMPRESS     (no compress)
```

### Modification of the Synchronous Modem Driver

This modification is only necessary when your line is synchronous and you want to receive data in transparent mode.

The current modem driver for SINTRAN versions I and H cannot handle transparent reception of data. On the installation diskette there are two files:

- EMUL-SPAT-H:MODE (for SINTRAN H-version)
- EMUL-SPAT-I:MODE (for SINTRAN I-version)

Run one of these files (dependent on your SINTRAN version) as a mode job under user SYSTEM to modify the modem driver to accept transparent received data. Do a system coldstart afterwards. Note: The mode file will modify the system file SINTRAN:DATA, so do this just after a disk backup, or when you have the possibility to load the system diskettes, in case there is something special with your system (e.g., other patches in the modem driver).

### Modification of the Asynchronous (Terminal) Driver

This modification is always necessary if the line is asynchronous (a normal terminal interface).

The receive part of the driver data-field has to be prepared to accept 8 bits data bytes without modification, set no echo, break on all characters and of course no enabling of xon/xoff for send or receive. The modifications are made by the SINTRAN Service program, but some parameters to be given are system dependent and they are found in the SINTRAN symbol list (address of TELIN/TELEM/TTGET).

The detailed procedure is found in papers delivered with SINTRAN.

## Modifications from Version 1.4

1. **Command "Assign-output":**  
   Set to "no assignment" will work  
   "One shot" will change to "no assignment" when the received file is closed.

2. **Command "Logging"** is changed to "Log-transmission".

3. **Command "Log-messages"** is implemented.  
   (Specify log device number and log file).  
   If the file cannot be opened, an error message is displayed and the file name is not changed. There is no check for the messages device, but it should be 0 or 2 or set equal to the Sintran error device for Sintran version older than I.

4. **Command "Transfer-file":**  
   The source file will be opened and closed.  
   If the open is not successful, an error message is given and the operator is asked to delete the entry.  
   If no user name is given, the text (RT) will precede the file name when it is displayed on the terminal.

5. **Command "Installation"** is implemented.  
   With this command, one or more load files will be generated. Can be used instead of editing the delivered mode file for loading (emul-rtload:mode).

6. **Command "Status"** gives some additional information.  
   If there have been errors when transmitting files scheduled from the same terminal, the entries with error are displayed on the screen.

7. **Default value in address 27** changed to 0 (concerning short files to console). For communication with a mainframe, this variable may be set to max 1777 with the Look-at-segment command.

8. **Value in address 30 on the emulator segment** (def=0) can be set to 1 if very special text is to be received from another emulator in nontransparent mode.  
   In this case, the user is responsible to set up a complete translation table for receive (ebcdic to ascii), i.e. also codes like Record separator, Ebcdic new line etc. must have entries different from 0 in the corresponding line of the table source file.

## Additional Changes from Version 1.5

9. The emulator terminates on the following error conditions:

   a. Max number of consecutive NAK's from the remote [illegible]  
   The limit is found in address 31 on the segment [illegible]*10).

   b. Max number of consecutive timeouts.  
   The limit is found in address 32 on the segment (default*10).

   c. Max number of consecutive block sequence errors when receive mode.  
   The limit is value in address 32 multiplied by 2.

   In all these cases, the emulator sends EOI and the files are closed and an error message is given.

10. Corrected error in transmission of a file when byte count equals a complete page (multiples of 2048 bytes). In previous versions such files were transmitted OK, but error message 18 (no such page) was reported.

11. The commands SEND-SIGNON and SEND-MESSAGE do not longer start transmission of the files in the transmission queue.  
Transmission from the queue is only started by the command START-TRANSMISSION (or the optional library routine EMULGO).

12. Timeout handling changed and should work better now.  
The limit for timeout (in basic time units) is found in address 33 on the segment (initial value is 50*10 {10 seconds}). Timeout is not counted when the emulator is in connect phase. There is no error message when the first timeout for a block occurs.

# Load File Execution

Run the load-file (from user SYSTEM or RT):
```
@MODE(USER)EMUL1-RTLOAD:MODE..
```

Start the RT program:
```
@RT EMUL1
```

If everything is OK, all the commands in Emul-opcom can be used.

Test:
```
EM-OP
CONF
```

Some installation parameters should be displayed.

Note: It is convenient to add some Opcom commands to the load file. These commands may be: `load-table`, `protocol`, `assign-output-files`, `edit-signon`.

Example: the following is added to the original load-file for emulator 1:
```
@RT EMUL1
@HOLD 1 1
@HOLD 4 2
@EMUL-OPCOM
<some command>
EXIT
```

Then run the load file again.

For installation of emulator no. 2-8, use the same procedure but change address (400+emulator number -1) instead of 400 in the file `EMUL-OPCOM:PROG`. RT-program names will be EMUL2, EMUL3 etc. and load file names will be `EMUL2-RTLOAD:MODE`, `EMUL3-RTLOAD:MODE` etc.

When more than one emulator, it is also possible to have one copy of `emul-opcom:prog` for each emulator, using names to identify the remote computer.

Example (user System)
```
Copy-file "IBM:PROG" ((bpnu-user))EMUL-OPCOM:PROG
Copy-file "SPERRY:PROG" ((bpnu-user))EMUL-OPCOM:PROG
Copy-file "DATAPOINT:PROG" ((bpnu-user))EMUL-OPCOM:PROG
```

Each copy must have the actual opcom internal device number in address 400.

For more complete installation guide, see the Users manual.
