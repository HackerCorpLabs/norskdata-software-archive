## 4 Installation Procedure

### 4.1 Automatic Installation

#### 4.1.1 Preparations

Prior to the installation, verify the following:

- Ensure that the user areas specified in Chapter 1.3 exist with the required number of free pages and free files. If not, find a directory having enough space to hold the user areas. The installation program will try to allocate space whenever needed, but you may need to specify on which directory to create user areas.

- The following files will be loaded with UNIQUE-II Runtime:

| Abbrev. | File name     | Default user area(s)     |
|---------|---------------|--------------------------|
| SIBAS F | SIBLIB-2BANK-F| DIALOG-SYS, SYSTEM       |
| UE library | UE-PLIB-P2 | USER-ENVIRONMENT         |

Check where these files are installed. If not installed on the default user area, the installation program will ask where to find these files.

- Ensure that your configuration fulfills all other requirements mentioned in Chapter 1 and 2.

#### 4.1.2 Installation from Floppy

- Put the diskette 211083C<rev>-XX-01D into the floppy drive.
- Log in to user area SYSTEM.
- Enter directory 211083C-XX-01D.
- Run the INSTALL program on the diskette.

Example: How to enter the directory and start the installation program.

```
@ENTER-DIRECTORY 211083C-XX-01D FLOPPY-DISC-1 0=  
@{211083C:FLOPPY-USER}INSTALL=  
```

## 4.1.5 Updating the SW-Config File

The UNIQUE Runtime version cannot compile applications, and is only working with the :UCOM files. However, if your database has been initiated/modified after the compilation date of the applications, UNIQUE Runtime will try to start compilation anyway, resulting in an error message.

In order to tell UNIQUE that it can ignore this safety check, the following parameter must be added to the database description in the SW-CONFIG file:

```
AUTOMATIC-RECOMPILE = OFF
```

## Revision C13:

- New menu command: LIST-VERSION. Displays all information concerning revision level, prefix definitions, etc.

- The system file (:SYS) may now contain System File Commands. The syntax is: `<command>=<parameter>`

### Currently available commands are:

- **FILE-NAME=<filename>**  
  Check/compile given application file.  
  This is equivalent to just writing the  
  file name without the "FILE-NAME=" prefix.

- **LIST-FILE=<filename>**  
  Write all messages from the system check  
  to the given file. To turn listing off  
  and close the file, give the command  
  with no file name. If the file does not  
  exist, it will automatically be created.  
  The default file type (extension) is  
  LIST (LST).

- **ABORT-ON-ERROR=ON/OFF**  
  ON: Abort system check if a compilation  
  error occurs.  
  
  OFF: Do not abort system check if a  
  compilation error occurs. This is  
  default.

- **FORCE-COMPILATION=ON/OFF**  
  ON: Compile all applications without  
  checking the necessity of it. This is  
  equivalent to giving the file name with  
  extension.  
  
  OFF: Only compile applications which  
  need compilation. This is the default.

The commands may be abbreviated as usual, but there may be only one command per line. If an illegal command is given, a message is given on the terminal, but the system check will not be aborted.

Note: Certain fatal database errors will abort the whole system check.

## Revision C14

- **New Features in SW-CONFIG for User Environment and Unique Access System:**

  **UE-REQUIRED=NO/YES**  
  New command on system level which specifies whether the user must be logged in via UE or not. If YES and the user is not logged in via UE, a message is given and the system is stopped. Default is NO.

  **CHECK-USER=NO/YES/EXIST**  
  New parameter EXIST which specifies that the log-in user must exist as a legal user in the Access System. If EXIST and the log-in user (normally the UE user) is not defined in the Access System, the user is not asked to give a new user name, but a message is given and the system is stopped. Default is NO.

- **UNPACKED DECIMAL as Storage Type**

  Unpacked decimal as a storage type has caused some problems concerning the position of the sign. In SIBAS-DRL it is not possible to specify whether the sign is leading or trailing. SIBAS assumes trailing while UNIQUE uses leading as default. A new parameter in SW-CONFIG has been introduced to overcome this problem.

  `sign-position=LEADING.TRAILING` (default = LEADING)

  The parameter should be specified under `SYSTEM-NAME: <name>` in the SW-CONFIG file for systems assuming that the sign is trailing.

  SIBAS-DRL allows an S after UNPACKED DECIMALS to indicate a separate sign, default is embedded.

- **Database Search Enhancement**

  After having discarded 50 records due to a SELECT statement, the message '... please wait ...' will now be given. After this, the user may abort further database search by first hitting any key and then confirming the abortion by hitting the EXIT key.

Currently implemented option codes are:

- **$R** Refresh the screen *after* the command is performed.

  - Note: Should only be used when the command to be executed is starting a separate program.
- **$D** Dump restart information *before* the command is performed. MENU-COMMAND('$SCHECK-IT')


## A. Setting/Removing Search Region Limits

### A.1 How to Set Search Region Limits

A search region limit is the key value which marks the first or last record to be available from a table. Normally, the RANGE function is used for setting search region limits. From revision C13, the limits may also be set by the user.

This is useful if you wish to define a temporary "work region" in the table, e.g., before using SHIFT + PRINT.

Search border limits are set by pressing either LEFT BORDER or RIGHT BORDER when the cursor is positioned in a record with contents. The value of the record’s main key will then be used as either lower or upper limit respectively. Detailed description of these keys is given below.

Active search region limits are indicated with '(' , ') ' or '()' on the status line.

## B. Searching Using Shift + F7

SHIFT + F7 leads you into the query mode which allows you to search for records with a given key value. In this mode the ALTERNATIVE-KEY fields are also utilized.

When you press SHIFT + F7 the following happens:

1. Fields belonging to the current table and tables which are owned by the current table are cleared. Search region limits which may have been set previously, are removed.

2. '?' indicating query mode is shown on the status line.

3. The current search key is marked in inverse video, and the names of the table and the key are given as a message.

    If the current field is a key or a member of a key, that key will be used as current key, else the main key of the table is used.

4. The cursor moves to the first marked field ready to receive search values.

By pressing SHIFT + F7 again, the next alternative key in the table is marked and the cursor moves to the first marked field. Repeat SHIFT + F7 until the correct key is marked.

DOWN ARROW moves the cursor to the next field in the key, UP ARROW to the previous field in the key. CR works like DOWN ARROW, except when used in the last field of a group key.

The search is activated by entering a value in the key and pressing either LEFT BORDER, RIGHT BORDER, STRETCH JUSTIFICATION or PERFORM from any field, or CR from the last field in a group key. The search criteria defined by these keys are described below in detail.

If a search is successful, the record found is fetched and existing repeat lines are filled. The query mode is turned off. Active search region limits are indicated with '(', ')' or '()' on the status line.

If no record fulfilling the search criteria is found, the message 'XXXX not found' is shown.

The query mode is turned off automatically when a successful search is done. The query mode may also be turned off by pressing EXIT or HOME.

Subchapter A.2 describes how to remove the defined search region limits. In addition, search region limits on member level are automatically removed when a new owner is fetched.

- Due to changes in the S-format required in different versions of the NOTIS products, a new file must be present on user DIALOG-SYS. This file is named UQ-ND-S:INI and must have public read access.

  All S-format files produced by UNIQUE products will have the same S-format header as the file (DIALOG-SYS)UQ-ND-S:INI.

  UQ-ND-S:INI is an 'empty' file containing only an S-format header matching the version of NOTIS-WP you are using on your machine. By storing the S-Format header in a file, it is possible for you to define the default settings and rulers. UNIQUE will read the default header from this user defined file, if it exists.

  If you start using a version of NOTIS-WP with a new S-Format, e.g. going from WP version M to N, just repeat the procedure described below and UNIQUE will produce documents readable by the new WP version.

  You have to install/create this file manually:

  ```
  1. Log in on user area DIALOG-SYS.
  2. Start NOTIS-WP.
  3. Use the internal menus in WP to set the wanted default values.
  4. Make sure you define it to be an S-Format document.
  5. Type some blanks so WP will store it as a document.
  6. Save this 'empty' document to the file "UQ-ND-S:INI".
  7. Set public access to READ: @set-file-access UQ-ND-S:INI R R,,,
  ```
