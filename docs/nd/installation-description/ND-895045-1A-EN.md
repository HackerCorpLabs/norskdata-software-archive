## 1.3 Warning to Supervisor Guide ND.30.059.4

The supervisor guide for version D states that BACKUP-SYSTEM may be used for copying the database. This is so, but under certain conditions. **The conditions are that the SINTRAN files are consistent before the copying is started.**

FOR PRACTICAL PROCEDURE ONLY, PLEASE SKIP TO SECTION "SOLUTION"

### Explanation

Inconsistencies may occur in one or more of the SINTRAN files used by DS when the database is closed down in an uncontrolled manner. Uncontrolled means any kind of stop except by the DS-SERVICE command STOP-SERVER. Specifically, the object entry of some of the database files may not be updated with correct number of pages in the file. For example, the file on the disc contains 200 pages, but the object entry has not been updated and "believes" that the file has only 195 pages. File copying may result in only 195 pages being copied. (NOTIS DS itself does not use this information so is not affected by this error).

### Solution

The SINTRAN files containing the database must be verified before taking backup. If inconsistencies are found, these must be repaired.

Run the Warning-And-Error-List command under VERIFY in the OPERATOR ENVIRONMENT on the directory(ies) containing the database. (See chapter 5 in the Operator Environment User Guide ND-30.061.1).

If no warnings or error messages appear, you may safely copy the database files in any manner.

```
If warnings of the kind:

WARNING : Object entry. User 4 : NOTIS-DS File 2
Pages in file should have been 000310B

occur, then THE FILE(S) CONCERNED MUST BE REPAIRED
before attempting to copy it/them.
```

Run the Remove-Conflicting-Pages under REPAIR DIRECTORY in the OPERATOR ENVIRONMENT on the directory(ies) containing the database. The inconsistencies described will now be repaired.

## 3 Known, But Not Corrected Errors

- DS-BACKUP allows you to create a backup on a user area even if this user area has public access "none".

- Moving a drawer from one user to another will display the error message 'DS: Already open for write' if the other user is using NOTIS-DS. The other user has to leave NOTIS-DS for the move to take place.

## 4 Modifications and New Features

### 4.1 Changed Commands

#### Changes done in DS-BACKUP

- The picture where the program asks where the backup is placed, is changed, because the database can use more than one directory.

- There is also one extra question on whether to copy ID attributes or not (ID attributes = Id info, sender info and receiver info). If you only want to take backup of the text of a document, it will save both time and space to answer NO to this question.

- If you want to copy documents using date modified, you have one more alternative. Here you can specify that you want to copy all documents modified in the last 3 days. This makes it easier to make a mode-file to run f.ex. every 3 days, without having to change the dates in the mode-file.

- If you press ESCAPE during a copy operation, the program gives you control again. The program will finish the copying of a document (for consistency) before it stops the copy-operation.

- The error reporting is better in this version. The program will report all errors if you use an output file.

- The question 'manual check?' has been divided into two questions, one for 'Only list?' (Y/N), and one for 'manual check?' (Y/N). If you answer Y to 'Only list?', the elements are only listed and not copied.

# 5 Before Installation

**BEFORE YOU START, note the following points:**

1) XMSG and User Environment should be running when you start the installation, and user SYSTEM should have 400 free pages.

2) You should read the NOTIS-DS Supervisor Guide before starting.

3) NOTIS-DS consists of two parts, the document server and the document manager. The document server is an RT program running the storage system (keeping all documents in the document database). The document manager is a utility program for creating, listing, etc. of users, drawers, folders and documents.

Further, a system for personal backup is supplied. It consists of an interactive (background) part and an RT program.

The DS-SERVICE program is used for supervisor tasks.

In a COSMOS network, the document server (i.e. the database) may be shared by many computers, and may be installed on one centrally located computer. The document manager must be installed on all computers.

The personal backup system and the backup server must be installed on all machines with NOTIS-DS users who may want to take personal backup of their documents.

Refer to the Supervisor Guide for more information on installing NOTIS-DS in a multimachine environment.

## Installation Instructions

4) The installation program assumes the following default user areas to be used:

   ```
   SYSTEM        min. 300 pages (UE-files, DDBTABLES)
   NOTIS         min. 1000 pages (DS files and domains)
   ND-OPERATION  min. 83 pages
   NOTIS-DS      min. 70 pages (database), preferably much more.
   ```

   You may choose user areas other than NOTIS and NOTIS-DS during the installation procedures. The NOTIS user area is used to hold all program files, while the NOTIS-DS user area is used to hold the database containing all documents and the information about them. This user area needs 70 pages plus 1.1 pages for each document, folder, drawer, and user in addition to the space occupied by the document text.

   Before you start, you must check on which directory you have space for the files. User areas will be created during installation if they don’t exist.

5) If the current version of NOTIS-DS is earlier than the C-version, you must install the C02-version before installing the D-version.

6) During installation, the NOTIS-DS:INIT file will be deleted (if it already exists) and created again with default values. If your current version of NOTIS-DS is the C-version, we recommend that you use the command `LIST-PARAMETERS` in DS-SERVICE and take a note of the parameters before installing the D-version.

7) If the UE-ERMSG-xx-C:ERR (xx = language) file on user area SYSTEM is in use by a program and if this file is older than the one on the DS diskette, then the installation procedure will not be able to replace it and will install the new :ERR file with the file type :NEW.

   It will copy the program UE-RENAME-A01:PROG to user SYSTEM. This program deletes old revisions of DDBTABLES-G:VTM and UE-ERMSG-xx-C:ERR and renames the :NEW files to :VTM or :ERR. It should be run as the first statement in the LOAD-MODE job (after @ENTER). You should then do a warm start before trying to run NOTIS-DS.

# Installation Procedure

- Log in as user SYSTEM.

- Put the first floppy into the floppy drive. We assume here that this is floppy disk 1 unit 0.

- Give the following commands to start the installation procedure:

  ```
  @ENTER-DIRECTORY 210794 FLOPPY-DISC-1 0↵
  @(210794:FLOPPY-USER)INSTALL-DS↵
  ```

The installation procedure will guide you through the installation.

# After Installation

1. If you have an existing database on one directory, and you want to split the files onto two directories, you must do the following. Take a backup of the database files if you haven't already done it. Create the database-user on another directory: f.eks.

   ```
   @CREATE-USER PACK-4:NOTIS-DS
   ```

   and give this user sufficient space to contain the DS-DB-TEXTS files and a pool file of 40 pages. (Preferably much more). Then copy the DS-DB-TEXTS:DATA and DS-DB-TEXTS:ISAM using BACKUP-SYSTEM to the new directory. For example if the database is on PACK-2 you will write the following:

   ```
   @BACKUP-SYSTEM↵
   COPY-USER-FILES↵
   D↵
   PACK-4↵
   NOTIS-DS↵
   D↵
   PACK-2↵
   NOTIS-DS↵
   DS-DB-TEXT↵
   L↵
   EXIT↵
   ```
