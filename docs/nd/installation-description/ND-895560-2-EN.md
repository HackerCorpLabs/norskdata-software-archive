# Description of Product

Basic Software Package for ND-5000 ES (ND 380799) is a part of the Basic System Package for ND-5000 ES (ND 211731), which is a prepackaged system for the ND-5000 ES with menu-oriented operation routines for easy operation. It is also part of the Basic System Upgrade Kit (upgrading from version A to version B of the System Package), ND 211730.

# Reason(s) for New Product or Version

This product is meant to be used together with one of the platform kits. All the software in this product is prepacked and ready for installation. This product will be installed and prepared by ND on all deliveries of the ND-5000 ES models.

## 4 Read This First

The ES platform consists of four directories, all placed on the system disk:

```
PACK-BASIC        ----->  DISC-4-SCSI-1,0,0  
PACK-MAIN-SW      ----->  DISC-4-SCSI-1,0,1  
PACK-EXTENSION    ----->  DISC-4-SCSI-1,0,2  
PACK-APPLICATION  ----->  DISC-4-SCSI-1,0,3  
```

a) **PACK-BASIC** contains system files and must remain as it is when delivered from NORSK DATA A.S. Some few exceptions exist.

b) **PACK-MAIN-SW** contains configuration files for the system and customer-defined users.

c) **PACK-EXTENSION** contains your additional ND applications not included as standard on the platform.

d) **PACK-APPLICATION** is reserved for the different business units belonging to NORSK DATA, and their application packages.

# 5 Manual Installation Procedure

This procedure should be followed when a new version of the Basic System Package is to be installed as part of upgrading from an older version.

---

**CAUTION!**

All software located on PACK-BASIC will be destroyed and a new version of PACK-BASIC will be restored from the streamer. On user area SYSTEM there may be files belonging to products other than those listed in chapter 10 (libraries, init files etc.). Backup of these files must be taken before the disk is restored.

---

## 1. Preparations Before Stopping the ND-5000 ES:

a. Perform a controlled shutdown of the ND-5000 ES:

   Log in to user area SYSTEM and execute the command:

   ```
   @MODE (MODE-FILES)SYSTEM-SHUTDOWN:MODE
   ```

   All configuration-dependent system files located on PACK-BASIC will be copied to user CONFIG-FILES on PACK-MAIN-SW.

b. Execute the command `@LIST-TITLE,...` and note the CPU number and type. You may be asked for it later in the installation procedure.

c. Check that the file `(MODE-FILES)DEF-PERIPHERALS:MODE` corresponds to your system.

## 4. Initialising the New Platform:

Press the MCL (Master Clear) and the LOAD buttons on the Operator panel.

The system will then start (this takes about 5 minutes) and the following text will appear on the terminal:

```
--------------------------------------------------
! All configuration-dependent files are now reinstalled !
!                                                        !
! Please continue with next point in the installation   !
! procedure in the PI sheet.                            !
--------------------------------------------------
```

Customise the new platform:

### a) Platform Preparations

Log in as user area SYSTEM and start the installation program `@PLATFORM-INST~`

Answer the questions according to the software and hardware configuration on your system.

The installation program will now prepare the system according to your specifications.

### b) Do a Warm Start: `@RESTART-SYSTEM~`

The system is now running through a complete cold start and warm start (this takes about 15 minutes).

When the system has been restarted, the following text is displayed on the console printer and on the console:

```
>> The ND-5000 ES is available
```

### c) Swap File Configuration

This system has only one swap file with a size of 2000 pages. This means that before the system is taken into use you must define a swap file on a "non-platform" directory.

1. `@CREATE-FILE (<directory name>:<user name>)swap-file-1:swap,<size>~`

2. `@ND~`
   - `DELETE-SWAP-FILE (<directory name>:<user name>)SWAP-FILE-1:SWAP~`
   - `DEFINE-SWAP-FILE (<directory name>:<user name>)SWAP-FILE-1:SWAP~`
   - `EXIT~`

Point 2. above must also be put into the file USER-DISKS:MODE

`@PED-E (MODE-FILES)USER-DISKS:MODE~`

## 10 General Information

- **DSS Basic System (ND 211479 A09)**

  - Device parameters should be set with DP-SERVICE for some devices.
  
    Command: CHANGE-PARAMETERS
    
    These are:
    
    - **CDC disks**: Device settle time = 10 seconds
    - Device power uptime = 90 seconds
    - **GTS, STC tapes**: No synchronous transfer
    - **GTS tapes**: No. of retries on aborted command = 0
    - **GTS tapes**: Abort command allowed = NO
    
    Remember also when defining the device GTS that the device code = 1.

- **SINTRAN III patches**

  When it is necessary to install SINTRAN from floppies.
  
  In addition to the patch file **4200**, the file (SYSTEM)SINTRAN-PATCHES:MODE must be run as a mode job after the standard patch file.
  
  This file includes additional patches for SINTRAN that are **NOT** included in the patch file **4200**.
  
  When a new SINTRAN with patches is installed, do the following:

  - **@COLD-START**

  - Log in and enter the main directory by typing:
  
    ```
    @ENTER-DIRECTORY,,DISC-4-SCSI-1,0,0
    ```

  - Log out and log in as user area SYSTEM

  - ```
    @SINTRAN-SERVICE
    @SET-COLDSTART-MODE-FILE PACK-BASIC-B,DISC-4-SCSI-1,0,0
    @HENT-MODE:MODE

## Redefining OpenLAN-Printers

When you have installed a new platform on your system:

1. From user area SYSTEM, use an editor to read the file:
   - `SYMBOL-2-LIST:SYMB`

MEMORY? YES~
IMAGE? YES~

```
@SET-PERIPHERAL-FILE "<name>" <23xx>~

5. Steps 3. and 4. must be executed for each OpenLAN-printer on your system.

6. `@SPRINT /START-SPRINT`

7. `@START-SPOOLING COSMOS-SPOOLING`

## 11 Creating and Customising a NOTIS-DS Version E Archive

If you have previously installed NOTIS-DS version D on your ND-5000 ES, you should now upgrade to the E-version.

You must then create a new (E-version) database and convert your old database using the program DS-CONVERT. The conversion takes time (6-8 Mbytes per hour). Until the conversion is completed, you need disk space to keep both databases. This chapter contains a detailed description of how to create a NOTIS-DS version E database and convert the database from version D to version E.

This chapter consists of four parts:

1. Creating the NOTIS-DS version E archive
2. Defining NOTIS-DS access from frontend computers

## 3. Converting an Existing Version D Database to Version E

The program DS-CONVERT converts data from a database for NOTIS-DS version D to an E-version database. You have two options:

a) Converting the whole database in one operation.  
To do this nobody must be allowed to use NOTIS-DS or NOTIS-ID until the conversion is completed.

b) Converting the database in two phases.  
This enables you to leave the NOTIS-DS version D archive available during most of the operation, but the conversion will take longer.

Before you start converting, you must stop the Emulator server by running:

```
@MODE (DS-PROGRAMS)DS-EMSTOP-E02:MODE.l
```

and load and start the D-version document server by running:

```
@MODE (NOTIS)DS-LOAD:MODE.l
@(NOTIS)DS-SERVICE
    START-SERVER
    SELECT-SERVER BS
    START-SERVER
EXIT
```

The D-version document server (DsDs) and the new database must be running while you convert your database. Make sure that the E-version database is not opened by any users, and that the R-log(s) are turned OFF before the conversion is run.

The different conversion procedures are described in the NOTIS-DS Supervisor Guide, chapter 3.

## 4. After Successful Conversion to NOTIS-DS Version E

a) Check the output from the conversion to see if the operation has been successful.

b) Stop the D-version document server(s) and the E-version database. Take a full backup of your new database. (You should also back up your old database if you have not already done so.)

DEFINE-STANDARD-DOMAIN NOTIS-DS (DS-PROGRAMS)NOTIS-DS-<lan>-E

g) Your NOTIS-DS archive is converted and ready for use!
