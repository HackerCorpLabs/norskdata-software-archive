## 4 Installation Procedure

### 4.1 Automatic Installation

None

### 4.2 Non-Automatic Installation

ND-380853B, SIBAS/R Client, should be installed prior to this product.

This installation procedure assumes that the installation procedure of SIBAS/R Client has been followed.

- Log in as user: `SYSTEM-`

- Make sure that user area SIBR-B has 2500 free pages.

- Insert the floppy volume 380855, part 1 (of 5), in floppy-drive 0.

- Use the Backup-System to copy floppy no. 1-5 as volume to user SIBR-B.

```
@BACKUP-SYSTEM-
Ba-sy: COPY-USER-FILES DIR, SIBR-B,VOLUME,380855,F-D-1.0..
```

    When the Backup-System asks if next floppy is ready,
    insert next floppy and answer YES.
    Answer NO, when end-of-volume is found (after floppy no. 5)
    and the Backup-System asks if more volumes are to be copied.

```
Ba-sy: EXIT-
```

- The installation can continue when all the floppies have been copied without any errors, run:

```
@MODE (SIBR-B)IN-380855B05:MODE "(SIBR-B)IN-380855B05:OUT"-
```

NOTE: You will be asked if you are going to install a nucleus- or message-version of SIBAS/R B.

The mode file terminates with:

```
. .<FINISHED, Check out-file for Errors>
```

## 4.3 Completing the Installation

- In case of fatal errors in SIBAS/R, internal structures will be written to the file SIBAS:DUMP on user SIBR-B, to be used by ND support personnel. The size of the dump depends on the actual situation when the dump occurs - there should always be enough space on user SIBR-B to allow the dump file to grow to approx. 300 pages.

- Define the utility programs as Standard Domains - the following lines should be added to your HENT-MODE file:

```
@ND-500
DEFINE-STANDARD-DOMAIN SIBR-DBM-B (SIBR-B)SIBR-DBM-B
DEFINE-STANDARD-DOMAIN SIBR-DRL-B (SIBR-B)SIBR-DRL-B
EXIT
```

- The installation of this product is now completed.

## 4.4 Hints for Installation

- Due to previous abnormal system stops, some files may be open even if all databases are properly stopped.  
  Deletion of the files will then fail.  
  The files may be manually closed by patching the object entry  
  of the file, as illustrated in the following example:  
  (user input underlined)

- Log in as user SYSTEM

```
 @LIST-FILES (SIBR-B)SIBR-MESS
    FILE 0 : (PACK-EXTRA:SIBR-B)SIBR-MESS-TS-B03:SEG;1
    FILE 1 : (PACK-EXTRA:SIBR-B)SIBR-MESSAGE-B03:SEG;1
    FILE 12 : (PACK-EXTRA:SIBR-B)SIBRP-MESS-B03:NRF;1
    @CHANGE-OBJECT-ENTRY:
     USER NAME: PACK-EXTRA:SIBR-B   NB! Remember dir. name
     OBJECT INDEX: 0=  File 0 is open
  
    22/ 000001 0=  
    xxxxxx
    @
```

- The file may now be manually deleted.

## 7 Errors Known but Not Corrected

### 7.1 SQL-Server

- The SQL-server may find a column name ambiguous even if it is an exact match.

  Solution: Prefix with table name.

- There must be exact match between the user name supplied by User-Environment (UE) and the DATABASE-ADMINISTRATOR defined in SW-CONFIG.

  Solution: The only user allowed to operate as Database-Administrator in SQL is the first defined DATABASE-ADMINISTRATOR in SW-CONFIG.  
  If this is user SYSTEM, it's ok. If this is SIBAS-MANAGER, you have to use UE-PMAN and change the UE login name from SIBAS MANAGER to SIBAS-MANAGER.  
  Then you can grant privileges.

- The SQL-server may stop when receiving a nested query.

  Solution: Do not use nested queries.
