# 1 FEATURES

- Output to spoolinq devices may now be defined for typesetter output modules. Details are found in the parameter file.

NOTE: The ND-500/5000 version should be used on a ND-500/5000 computer, because this version will take advantage of all new functionality introduced in the H&J program. (See NORTEXT Editorial and Production system Release Information, M-release).

ND-100 version.  
The typesetter output programs for the ND-100 distributed in the M version correspond to the L-release. No new funtionality has been introduced in the ND-100 version.

ND-500 version.  
The APS Output module now has the ability to output scanned graphics. Graphics are included in the article by means of the `<MGR ...>` function code. The scanned graphics must be stored as SINTRAN or DS files in TIFF format.  
In order to obtain acceptable output speed for graphics, parallel transmission is recommended. The APS should be equipped with the HSI option, and on the host side a Universal DMA interface (UDMA), modified for APS output, must be used.

The time-sharing output modules for the ND-500 now use the same program both for the real-time (RT) and the time-sharing (TS) output.

The TS-module can now fetch its input from SINTRAN files, NORTEXT text files and the NORTEXT queue system. When the input file name starts with a letter followed by number(s) only, the text is fetched from the NORTEXT text system, else it is assumed to be a SINTRAN file.  
When outputting to a SINTRAN spooling file, you now have the option to change to another spooling file even if the input queue is not empty. When the spooling files are changed, the last used text will be sent to the output device. Thus, the article queue printing may be started before the output module has finished processing all articles in the queue. This "function" is monitored by the following two parameters in the file `(PARAM-NTX)FOT0xx-PARAM-M<rev>:NTXP`

MAXMM  
The MAXMM parameter determines the amount of typesetter material in millimeters to be put into the spooling queue before the spooling file is closed and output to the device. This is done between two "articles" when the leading limit in millimeters has been reached.

## MAXARTNO
The MAXARTNO parameter is a limit for the number of articles to be put into the spooling queue before the spooling file is closed and sent to the output device.

If both the above parameters are filled in, the first condition met will result in a device output.

## Other new parameters:

**STATUS**  
Determines the status of articles when output by the output module.

**PROOF**  
When this parameter is activated by "PROOF=1", the device may be used as a proof-output device.

**RECORDER**  
When driving an APS-55, it is possible to send to 4 different devices from the same "rip". This parameter will tell the actual device number. Only valid for 500-programs.

When starting the time-sharing version of the output modules you now may choose between the following "/" modifiers:

- **/TYPSNO**  
  You want to specify typesetter number. The typesetter number is prompted for.

- **/TEST**  
  Puts the time-sharing output module into test (debugging) mode.

- **/LINE**  
  Sets up the TS to run a simulated typesetter output line (RT) mode.

- **/OPTIMIZE**  
  Activates the paper optimization specified in the parameter file.

- **/NOPTIMIZE**  
  Deactivates the paper optimization specified in the parameter file.

- **/PRODUCT**  
  The slug line specified by SLUG1 in the parameter file is output at the top of the first page.

- **/XY**  
  The article is positioned at the point given by the article record fields POSX and POSY and the slug line defined by SLUG2 in the parameter file is output at the top of the page.

### /AD
The matter is output as columns, starting from left to right. The slug line defined by SLUG3 in the parameter file is output at the top of the page.

### /S
A number between 4 and 15 is prompted for. The modifier is used to activate the corresponding SLUG parameter (SLUG4 ... SLUG15) in the parameter file.

### /F
A number between 1 and 8 is prompted for. These are flags to be used for testing of formats executed in the typesetter output module.

### /PROOF
This forces a proof output, i.e. the line breaks are kept. All direct codes are ignored in the proof output mode.

When the output modules are run in TS mode, they use a separate set of parameter files stored on the user area PARAMETERS-NTX. The parameter file name is composed by merging the user name, the name of the output module, and the -PARAM-xxx:NTXP file, where "xxx" is the version letter and revision level. For an APS output module the reference to a parameter file may look like this: (PARAMETERS-NTX)APS-PARAM-M<rev>:NTXP

This TS mode parameter file contains the same type of parameters as a typesetter output line (RT) parameter file. When no output device is specified in the parameter file the name of the output module is used as default device. For an APS output module "APS" will be default device name.

- A new parameter (COLSPACE) in the parameter file specifies the minimum space between articles when optimized output is produced. (The parameter COLWIDTH specifies the distance from the start of one column to the start of the next.)

- The control block: The new fields "Extra Leading" must be initialized. Set them to -1 if you have no other well-founded ideas.

- PHOTOSETTER-INFO table, page 6: Control old and update new information.

- Updated with all new features in the justification module. See NORTEXT Release Information, M-version.

## THE PARAMETER SETTINGS:

### End of page leading.
Leading between pages given in pica points.

### End of page number.
Number to be sent to the APS at the end of job.

### Number displayed when output.
Number displayed during timesharing output.

### Number displayed when finished.
Number displayed when job is finished.

### Automatic letterspacing.
Makes it possible to justify loose lines by spacing each letter on the line (used in some countries).

### Ext. value.
If the system includes inverse fonts, the external values of the spaces must be given.

### APS-55 device selection.
This byte makes it possible to choose device number (0-3).

### APS-55 number of copies.
Number of copies of last page.

### Type of prog.
Serial output: 0, parallel output: 1.

### Online.
Sending to a SINTRAN file: 0, sending to a typesetter: 1.

### Device resolution.
If the device is a printer, the resolution is 300.  
If the device is a typesetter, the resolution is 1000.

### Scale factor.
A factor of 8192 will give a 1/1 scale, the value can lie between 2048 - 10240.

### APS-55 screen gauge.
This field gives the screen gauge value for raster in boxes.

### Default values for picture generation.
The meaning of these parameters is the same as in the function code <GRP explained in the NORTEXT Release Information, version L.

The parameter **Resolution** gives the index in the table below the parameter. This table has 10 entries. The X-values give the maximum number of grey levels for the picture. The Y-values give the half tone cell size, the possible values are 7, 8 or 11 which corresponds to screen rulings of 100, 85 or 65.

**Default grayscale values:**  
These are values on a grayscale curve running from 0 as black to 255 as white. A correction curve in maximum 15 coordinates may be given to compensate for incorrect reproduction of the picture on this particular printer.

## 2 INSTALLATION PROCEDURE

**NOTE:** This installation procedure requires BACKUP-SYSTEM version F or later.

1) If you want to preserve any program files from your "old system", make backup copies now. If your "old system" was the NORTEXT J-version, the "old files" are of type :BPUN. Please remember to delete these files before continuing the installation procedure.

   Log in as user REALTIME-NTX and type:  
   `@DELETE-USERS-FILES --FO: YES--`

2) Log in as user SYSTEM.

3) Put the installation floppy in the floppy drive and enter it with:  
   `@ENTER-DIRECTORY,,FLOPPY-DISC-<drive-no.>,<floppy-unit>•`

4) Start the installation by typing:  
   `@X_(210823:FLOPPY-USER)INSTALL•`

This XCOM file will copy all files from the floppy to the actual users on disk. **NOTE:** All the old program files will be deleted before copying takes place.

If this product has been installed earlier and the :FORM file is found in your system, you will be asked if you want the new form file installed (and the old one deleted). The only reason to prevent the new form file being installed should be if you already have translated the texts in the form file, and no changes have been introduced since the previous release. The form file in this release has English text only.

5) This installation job will start the customizing procedure, i.e. `(REALTIME-NTX)CUSTOMIZ-NTX:XCOM` will be started. You will then have to answer the questions concerning the fototypesetter. The customizing procedure results in a NORTEXT system definition file called `DEFINE-NORTEXT:XCOM`.

7) When the installation job is finished, the directory will be released and the floppy may then be removed.

8) Log out and log in as user PARAMETERS-NTX.

The typesetter programs (lines) in NORTEXT need parameter files. The parameter files contain device numbers, conversion table numbers, constants and strings necessary for the individual RT-programs. The naming convention for these files is:

```
FOT0nn-PARAM-M<rev>:NTXP
```

`nn = 01, 02, 03 and so on.`

Multiple parameter files for the same type of lines may be created with the `CREATE-PARAM:XCOM`.

```
@X_CREATE-PARAM-
```

Carefully inspect and edit each and every file under this user to make sure that all parameters have the right value. **NOTE:** The typesetter parameter files are in 16-bit format, and must be edited in the NORTEXT editor.

First you must make sure that the corresponding RT-programs (lines) in question are not running.
