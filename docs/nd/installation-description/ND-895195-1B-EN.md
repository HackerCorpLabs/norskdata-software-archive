# 4 Installation Procedure

## 4.1 Automatic Installation

### 4.1.1 Preparations

Prior to the installation, verify the following:

- Ensure that the user areas specified in Chapter 1.3 exist with the required number of free pages and free files. If not, find a directory having enough space to hold the user areas. The installation program will try to allocate space whenever needed, but you may need to specify on which directory to create user areas.

- The following files will be loaded/linked to UNIQUE-II:

| Abbrev. | File Name    | Default User Area(s)        |
|---------|--------------|-----------------------------|
| ● SIBAS library | SIB-LIB     | SIB-500                      |
| ● UE library    | UE-PLIB     | USER-ENVIRONMENT             |
|   and, if desired         |              |                             |
| ● TRUE library  | TRUE-LIB    | TRUE-C                       |
| ● NOTIS-WP (N)  | WP-500      | NOTIS, DOMAIN-USER, SYSTEM   |
| or             | NOTIS-WP--M  | NOTIS, DOMAIN-USER, SYSTEM   |

Check where these files are installed. If not installed on the default user area, the installation program will ask where to find these files.

- If you already have a version of UNIQUE-II installed, you should make sure it is not defined as a standard domain. Delete it prior to the installation.

- Ensure that your configuration fulfills all other requirements mentioned in Chapter 1 and 2.

## Installation Program

The installation program can do the following:

- **CREATE**: Create a new user area (or verify an existing one) for UNIQUE.
- **COPY**: Copy all files from the floppy to the desired user area.
- **LOAD**: Write the load procedure and load the UNIQUE ND-500 domain.
- **DUMP**: Dump UNIQUE as a standard domain.
- **EXAMPLE**: Install the DIALOGUE example database and applications. See chapter 4.1.5.
- **EXIT**: Leave the installation program and return to SINTRAN.

The first time, run all the tasks 1-4, one at a time, in sequence.  
To reload UNIQUE, run tasks 3 and 4. To re-dump UNIQUE, run task 4.

When selecting the CREATE or COPY option, and an (old) version exists on this user area, you are asked if these files should be deleted. You may answer Yes, No or Manually. When answering YES, program files, domain files, :MODE and :LIST files of current and previous versions/ revisions will be deleted. Afterwards the program checks if there are enough free pages on the user area.

When selecting the LOAD option, there are some questions that need an explanation:

- **SPECIAL**: `'Do you want to load any SPECIAL routines (Y/N)? /N/'`

  If you answer Y, the program will ask for the name of the :NRF file which the special routine has been compiled into. Answer N (or -) if you don’t have any special routines. See also chapter 4.1.4.

- **TRUE**: `'Do you want to run UNIQUE under TRUE (Y/N)? /N/'`

  Answer Y if you have installed TRUE version C and want this version of UNIQUE to run under supervision of TRUE. The file (TRUE-C)TRUE-LIB:NRF must exist!

## 4.1.4 Implementing Special Routines

To install a special routine the following must be done:

- Write the routine in PLANC, COBOL or FORTRAN.
- Compile it with the appropriate compiler.
- Run the installation program and select the load option.
- When the program asks if you want to load a special routine you must answer YES.
- The next question is which programming language the special routine is written in. Possibilities are FORTRAN, COBOL and PLANC.
- Finally you must give the name of the object file (:NRF) the special code is compiled into.
- A file named UNIQ-LOAD-S5-C:MODE including the load job will be created. You may run it from the installation program if desired. If you have special requirements for the load procedure or the special routine is split on more than one :NRF files, you may edit the load file in an editor before running it.

If you at a later time want to recompile/reload the special routine, you will have to run the load job after compiling:

```
@MODE UNIQ-LOAD-S5-C:MODE UNIQ-LOAD-S5-C:LIST
```

When the program tells you so, insert the UNIQUE Text System diskette, and the examples will be installed on the desired user area.

## LIST-FILE=<filename>
Write all messages from the system check to the given file. To turn listing off and close the file, give the command with no file name. If the file does not exist, it will automatically be created. The default file type (extension) is LIST (LST).

## ABORT-ON-ERROR=ON/OFF
**ON**: Abort system check if a compilation error occurs.

**OFF**: Do not abort system check if a compilation error occurs. This is default.

## FORCE-COMPILATION=ON/OFF
**ON**: Compile all applications without checking the necessity of it. This is equivalent to giving the file name with extension.

**OFF**: Only compile applications which need compilation. This is the default.

The commands may be abbreviated as usual, but there may be only one command per line. If an illegal command is given, a message is given on the terminal, but the system check will not be aborted.

Note: Certain fatal database errors will abort the whole system check.

## Revision C13

- The length of the DOCUMENT-NAME parameter in the EDITOR function is increased from 30 to 60 characters.

- When a special routine is called in search mode (Shift+F7), the APPLCOM parameter will contain the text 'SEARCH'.

- MENU-COMMAND('@<OS-command>') functions, specifying operating system commands, are now performed immediately and not delayed until the end of the function execution. This means that a sequence of such menu commands may be given. Example:

```
on COPY
    menu-command('@DELETE-FILE TO-FILE:DATA')
    message('Wait, copying file ...')
    menu-command('@COPY-FILE "TO-FILE:DATA" FROM-FILE:DATA')
endon
```

*Note*: SINTRAN commands may write error messages to the terminal and UNIQUE-II is not able to prevent that. However, the cursor is always positioned at the top of the screen before the command is executed, such that the *message(s)* will start at the second screen line. You may also use the new menu command options to automatically get a screen refresh afterwards.

- Some new options are available when performing an operating system (e.g., SINTRAN) command using the MENU-COMMAND function. The syntax is:

```
MENU-COMMAND('@<options><op.sys. command>')
```

`<options>` is a list of `$<option code>`

*Note*: Revision C11 used '%' instead of '$' to indicate the `<option code>`

### Currently Implemented Option Codes

- **$S** Clear the screen *before* the command is performed.

- **$R** Refresh the screen *after* the command is performed.

- **$C** Close the database *before* the command is performed.
  *Note*: Should only be used when the command to be executed is starting a separate program.

## $D 

Dump restart information before the command is performed. The restart information is dumped to a restart file which makes it possible to leave UNIQUE-II and restart it again getting the same context as given by the restart file. A restart is requested by giving the character @ as the only parameter on the startup command line. Example:

```
@UNIQUE-II @
```

## $A

After the command is performed, ask the user to confirm by hitting any key on the keyboard. Has the same effect as the HOLD function, except that it is performed for example before the screen is refreshed by the $R option.

**Example 1:** To start the program CHECK-IT after first having cleared the screen:

```
MENU-COMMAND('Ø$$CHECK-IT')
```

**Example 2:** To start PED (with file WORK) in such a way that after exiting PED UNIQUE-II will be restarted again with the same application and data as when leaving. Also clear the screen before leaving UNIQUE-II:

```
MENU-COMMAND('Ø$$DSPED WORK;1,,"UNIQUE-II @"')
```

- ND500/5000 only: The maximum total length of all fields in one application is increased from 2000 to 6000 bytes. This may cause applications not being portable to ND100 machines which still have the limit of 2000 bytes.

- If the user is not logged in via User Environment and the Access System is used, the internal field "AUE-USER:USERNAME" will now contain the user name given by the user on startup. (In earlier versions, the field was blank in such cases.)

### A.1 How to Set Search Region Limits

A search region limit is the key value which marks the first or last record to be available from a table. Normally, the RANGE function is used for setting search region limits. From revision C13, the limits may also be set by the user.

This is useful if you wish to define a temporary "work region" in the table, e.g., before using SHIFT + PRINT.

Search border limits are set by pressing either LEFT BORDER or RIGHT BORDER when the cursor is positioned in a record with contents. The value of the record’s main key will then be used as either lower or upper limit respectively. Detailed description of these keys is given below.

Active search region limits are indicated with '(' , ')' or '()' on the status line.

## B. Searching Using SHIFT + F7

SHIFT + F7 leads you into the query mode which allows you to search for records with a given key value. In this mode the ALTERNATIVE-KEY fields are also utilized.

When you press SHIFT + F7 the following happens:

1. Fields belonging to the current table and tables which are owned by the current table are cleared. Search region limits which may have been set previously, are removed.

2. '?' indicating query mode is shown on the status line.

3. The current search key is marked in inverse video, and the names of the table and the key are given as a message.

   If the current field is a key or a member of a key, that key will be used as current key, else the main key of the table is used.

4. The cursor moves to the first marked field ready to receive search values.

By pressing SHIFT + F7 again, the next alternative key in the table is marked and the cursor moves to the first marked field. Repeat SHIFT + F7 until the correct key is marked.

DOWN ARROW moves the cursor to the next field in the key, UP ARROW to the previous field in the key. CR works like DOWN ARROW, except when used in the last field of a group key.

The search is activated by entering a value in the key and pressing either LEFT BORDER, RIGHT BORDER, STRETCH JUSTIFICATION or PERFORM from any field, or CR from the last field in a group key. The search criteria defined by these keys are described below in detail.

If a search is successful, the record found is fetched and existing repeat lines are filled. The query mode is turned off. Active search region limits are indicated with '( , )' or '()' on the status line.

If no record fulfilling the search criteria is found, the message 'XXXX not found' is shown.

The query mode is turned off automatically when a successful search is done. The query mode may also be turned off by pressing EXIT or HOME.

Subchapter A.2 describes how to remove the defined search region limits. In addition, search region limits on member level are automatically removed when a new owner is fetched.
