- **Product name:** UNIQUE SERVER for ND-110

## Description of Product

A module in the UNIQUE CONCEPT/DIALOGUE-1 family that allows you to order XTRA reports to be performed in the "background" while you perform other tasks on the screen, or to order a report to be performed at a specific time. It consists of two parts; a controlling RT program and an interactive service program.

A schematic diagram of the server control program and example servers is provided in the Appendix.

## 4.2 Non-Automatic Installation

- Copy the files OEM-OETAD-A<rev>:PROG and OEM-OETAD-R-A<rev>:MODE to user area ND-OPERATIONS if not already installed.
- Run the mode file (ND-OPERATIONS)OEM-OETAD-R-A<rev>:MODE from user SYSTEM to load and start RT-program OETAD (if required).
- Create a user area <ANY USER> with the number of pages mentioned in chapter 1.3. The default user area is DIALOG-SYS. Copy the remaining files from the floppy to this user area.
- Edit the mode file UQSERV-LOAD1-C:MODE to suit your installation. Run it from user area <ANY USER> to load the UNIQ-SERVICE program.
- Run the mode file (<ANY USER>)UQSERV-DUMP-S1-C:MODE from user area SYSTEM to dump UNIQ-SERVICE reentrant.
- Run the mode file (DIALOG-SYS)UQSECO-RTLO-C:MODE from user area SYSTEM to load and start RT-program UQSECO.
- Chapter 4.1.2 describes how you should update the system startup files (HENT-MODE and LOAD-MODE).

## 4.3 Reports from Protected SIBAS Databases

The following precautions should be taken in order to allow a server to run reports against a SIBAS database which is protected by password.

1. Create a new SINTRAN user area, e.g. XTRA-SERVER. Access to this user area should be restricted to the main user area of the UE-user which the server TAD will use when logging in (or the SINTRAN user area entered when starting the server on batch).

2. Install a new version of XTRA on this user area. Answer YES to the question whether it should be allowed for users to create a local SW-CONFIG file.

3. Copy the global (ND-OP)SW-CONFIG:SYMB file to the same user area. For each database protected by a password, add the parameter PASSWORD=<password> to the database description in the file. Make sure that the access rights to this file are NONE for public access.

## 5.1 New Functions/Commands

**Revision C11:**

- **SET UNAVAILABLE/SET AVAILABLE.**
  This new command allows you to make a server unavailable for new jobs. A job already running on the server will be unaffected by this command.

- **COPY:** Pressing the COPY-key in the 'Edit jobs' screen will copy the job under the cursor into an order-form.

- **DELETE:** Delete-all-jobs (SHIFT+F1) deletes all jobs on the current server.

- **START:** The START-SERVER command is available from the SINTRAN command line, and from mode files. The syntax is:
  ```
  @UNIQ-SERVICE-C START-SERVER <server_name>
  ```

- **PERIODIC JOBS:** Periodic jobs can now be ordered as described in the manual.

## Revision C13:

- **STOP:** The STOP-SERVER command is available from the SINTRAN command line, and from mode files. The syntax is:

  ```
  @UNIQ-SERVICE-C STOP-SERVER <server name>
  ```

  The control program UQSECO may be stopped as follows:

  ```
  @UNIQ-SERVICE-C STOP-CONTROL
  ```

  or

  ```
  @UNIQ-SERVICE-C ABORT-CONTROL
  ```

## Revision C14:

- The function EDIT-JOBS is available from the Sintran command-line. The syntax is:

  ```
  @UNIQ-SERVICE-C <server name>
  ```

- XTRA servers can also be started on batch processes. This is useful if you want more control over the priority of your servers, or if you don't have enough TADs. The service program can only start servers on TADs - use the following method to start them in batch:

  - In the service program, define the name of your server in the "Define local server" form. Example:

    ```
    +------------------------+
    | Server name : XTRA-BATCH |
    | Server type : XTRA in batch |
    +------------------------+
    ```

    Only the server name is used, but the service program requires that the server type is not empty. The other fields may be used for comments or left blank.

  - Make a batch file (e.g. (DIALOG-SYS)XTRA-SERVER:BATC) with the following commands. Example:

    ```
    @ENTER DIALOG-SYS,<password>,<project password>,-1
    @XTRA /Xtra-batch
    &&
    ```

    (The last two characters are ASCII 27, or <CTRL>+<O> <ESC>).

## 5.2 Changed Functions/Commands

**Revision C11:**

- SECURITY: Only users defined as system supervisors in User Environment can define and control servers, and delete jobs on servers. These commands have been removed for other users.

- STARTING SERVERS: Improved error reporting when starting servers.

- DEFINE: The 'Define local server' form has been changed.
  - **Server name** is now **Server type** and vice versa.
