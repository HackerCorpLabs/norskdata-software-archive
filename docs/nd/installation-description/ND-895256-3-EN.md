## Description of Product

USER ENVIRONMENT is a supplement to the operating system. It provides security functions and a personal user environment for high-level ND systems.

Among the security functions are login control for users and servers, access control, log facilities and a user group concept.

The personal user environment includes tailormade menu systems, language handling (the user will run products in their own language) and personal setups in subsystems (e.g. default printer in NOTIS-WP).

User information in USER ENVIRONMENT version D may be shared by several machines.

## 4 Installation Procedure

### 4.1 Automatic Installation

The system may be delivered on:

- 1.2 Mbyte, 8 inch or 5¼ inch double-sided diskettes

You may install the complete UE, or add extra languages to an existing UE.

**ADP Segment**

Before the installation, please decide if you want to use the ADP segment on your machine. If you do, make sure that it is turned on by calling the SINTRAN III Configuration program. Choose the background option and "MON ADP" should be 1. If you change it from 0 to 1, you must perform a cold-start to activate it.

If you are using the ADP-segment, UE needs one system LAMU for each terminal. Choose the LAMU option in SINTRAN III Configuration program to determine this.

**Old UE Versions**

If the old database are version C, the installation program will convert the existing C version database to the D version format.

If the old database are version B and you still want to transfer all users to the D version, you must install the C version of User Environment before the D version. And finally if you have A version database, you first have to install the B version, then the C version before installing the D version of User Environment.

However, if you have the B version (or the A version) we recommend that you delete the old database files and define all users again. You should then delete the files:

```
(USER-ENVIRONMENT)UE-USER-PROFILE:DATA
(USER-ENVIRONMENT)UE-TERM-PROFILE:DATA
```

**SINTRAN Extended Security**

If you are using the forced password option of the extended security data field in SINTRAN-SERVICE (bit 4 in EXSECURITY set to one), and if the SINTRAN user area USER-ENVIRONMENT is not yet created, you must create this user area and give it a password before you start the installation.

## Name on Local Machine

The local machine MUST have a name before you start installation. If this is not done, enter XMSG-COMMAND program and define it using the command DEFINE-REMOTE-NAME.

This name should NOT be changed while UE is running. If you want to change it, you must run the program UE-CHCPU (see 5.4). If the installation is performed without a name on the local machine, it will not be possible to edit the UE-FUNC,SUPERVISE MACHINE menu. To correct the problem, you must stop UE, define a local machine name, and use the UE-CHCPU program, giving a <CR> as input when the machine name is asked for.

**XMSG** must be running when the installation program is started.

## How to Start the Installation

Install User Environment from a terminal with the same terminal type as most users will use later on. This will save one second at startup of every UE module, because the terminal tables (DDB-tables) will not have to be read again.

The installation must be run from SINTRAN, not from a menu! If UE is running, you should either be logged in, or the installation must be run from terminal number 1.

- Log in as SINTRAN user SYSTEM.

- Insert the diskette containing the directory name `210518D07-<lg>-01D` into the diskette station
  - NOTE! `<lg>` means language suffix ('EN' for English)

- Execute these commands (operator input is underlined and parameters are enclosed in angle brackets).

```
@ENTER-DIRECTORY,210518D-<lg>-01D~
DEVICE NAME: FLOPPY-DISC-<controller-no>~
DEVICE UNIT: <floppy-unit>~
@(210518D-<lg>-01D:FLOPPY-USER)IN-UE-<lg>-D~
```

The installation procedure has now started, it is self-explanatory.

After installation, check the file IN-UE-<lg>-D:LOGG, to see if any errors have occurred.

If everything went OK, skip the next section and read "4.3 Updating the mode jobs" on page 10.

## 5 Modifications Since Version C

### 5.1 New Functions/Commands

There are four major additions in USER ENVIRONMENT version D. These are:

**The Local Domain concept.** Machines may be connected to form a cluster which is called a Local Domain (LD). In an LD, the profiles are common for all the machines. A tool for defining/deleting an LD and including/removing machines in the LD is included.

**The UE-PMAN.** The profile manager (UE-PMAN) has become an advanced tool for maintaining the profiles in UE.

**The UDO concept.** The concept of "User Defined Object" (UDO) is introduced. A UDO may be used for access control by other products and program systems.

**The generalized login.** By using the program library, other process types may log in, several processes may run the same session and one process may log in several times.

Please refer to the manuals for more detailed descriptions.

### 5.2 Changed Functions/Commands

**Error codes.** The meaning of some of the error codes are slightly modified. E.g. the error message "No profile found for this user or terminal" is changed to "No profile found". It will be returned to most calls which involve reference to any non-existing profile, that is: user profile, terminal profile, user group profile, UDO profile, and so on.

**Authorization.** The number of authorization levels is expanded from two to six: Guest, Public, Operator, Server, Programmer and Supervisor.

## Start up

When starting UE (@UE-FUNC Start) the starting process (usually warm start (LOAD-MODE:MODE)) will automatically be logged in to UE with Operator access. If the UE database is empty, the login process will get Supervisor access. Then after starting UE for the first time, it will be possible to start @UE-PMAN directly to define users. The automatic login in to UE may cause problems when trying to start Multi-Machine Operator-Environment, and it is therefore recommended to include the following line before you start it:

```
@(USER-ENVIRONMENT)UE-PLIB-TEST,LOGOUT
```

## UE-FUNC Start-Server

UE-FUNC Start-Server will not wait for the server to start before it returns. This may cause problems in the start up of the machine (in LOAD-MODE) if subsystems depending on User-Environment is started immediately after the command UE-FUNC Start-Server. A program called WAIT-FOR-UE:PROG on user User-Environment may be used to wait for the server to start. The following may be put into the LOAD-MODE job after `@UE-FUNC START`:

```
@(USER-ENVIRONMENT)WAIT-FOR-UE
```

The **UE-FUNC Change-User-Area** previously made it possible to specify a user area which was unique with respect to a user’s alternative areas. Now, the user area specified must be unique on the given machine.

## Default user area

This is NOT the same as Main user area used in previous versions. That a user has a default user area does NOT mean that he has access to this user area. To give a user access to a user area, the user area has to be in the users list of Legal user areas.

Please refer to the manuals for more details.

- The possibility to go to the User-Area-Manager from UE-PMAN is removed.

## 5.4 Other Modifications

The **menu editor** is renamed from **UE-ME-C** to **UE-EDIT-D**.

### Changing of CPU Number

UE will no longer do an automatic change of CPU-number on its database if the CPU number is changed (or the database are moved to a new machine). If a CPU number is to be changed, or the database are moved from one machine to another, a program called **UE-CHCPU** (which is copied to the user area USER-ENVIRONMENT) is required. **YOU MUST RUN THIS PROGRAM BEFORE YOU START THE UE PROFILE SERVER.** This program asks for the name of the database, the name and CPU number of the old machine, and converts all information related to that old machine, so that it corresponds to the current machine (i.e. the machine the program is running on). The UE-CHCPU program must be executed from user area SYSTEM.

### Verification of UE Database

A problem that may occur with the UE database (file: UE-DATABASE:DATA), is that the number of pages in the object entry does not correspond with the number of pages in the file. If you have an LD, it will make the distributed copies of the database become inconsistent. A symptom on this problem, is that you get the error message 'database has been corrected, information may be lost’, after verification of the database on the slave machine(s).

A way of checking if this is the case and correcting it, is to run the program (USER-ENVIRONMENT)UE-EX-VER-D:PROG. This program will ask for the database file name and check if the number of pages in the object entry corresponds with the number of pages in the file. If the numbers are equal, it returns with OK, and ask if you want to perform a UNLOAD/LOAD of the database, which may decrease the size of the database file. If the numbers are unequal, a UNLOAD/LOAD of the database will automatically be started.

In the UNLOAD/LOAD process, the program requires a file to make a temporary copy of the database.

You will be asked for this file with the question 'Unload File name:'. The program will report some ISAM information about the database file, ask for `Unload File name:`, and then do what is called UNLOAD and LOAD in ISAM, i.e. the content of the database file will be copied to the 'Unload File' without indexes, and then loaded back to the database file.

## USER ENVIRONMENT version D07 and Remote Shell

In order to integrate Remote Shell and UE, some patches must be made to UE. These patches are described in the file `UE-PATCH-D:MODE`. The files `UE-LOGIN-D:PROG` and `UE-PSER-DATA-D:PROG` should be patched.

### Database-file on another user area

It is possible in USER ENVIRONMENT version D07 to put the database files on a user area different from USER-ENVIRONMENT. By running the mode-file `UE-TP-PATCH:MODE` (`@MODE UE-TP-PATCH:MODE`), the user area `UE-DATABASE-USER` will be assumed as the user area where the database files reside. If the database should be moved to another user area, you must first install UE normally, then UE should be stopped, `UE-TP-PATCH:MODE` should be run, the database files should be moved (`UE-DATABASE:xxxx and UE-1575B-POOL:DATA`) to user `UE-DATABASE-USER`, `UE-LOAD:MODE` should be run (`@MODE UE-LOAD:MODE`), and then UE may be started.

### Starting UE without taking backup

In USER ENVIRONMENT version D07 it is possible to shorten the start up time of the UE server, by not taking any backup of the `UE-DATABASE:DATA` file when the server is started. This is described in the `UE-PATCH:MODE` file. If this is done, you must ensure that a backup of the `UE-DATABASE:DATA` file is taken periodically in some other way.
