## 1 Read This First

The following things are required in order to use this product.

- This Patch Kit requires version C01 of the Basic Software Package for ND tpServer. The Patch Kit is generated with a SINTRAN III/VSX Standard system C (250306N01) and a Patch file version 2200 (250306N01).

- Software Keys (210507B)

  After installing this Patch Kit, all previously installed software keys are lost and must be reinstalled. Ensure that the diskette(s) with all necessary software keys are available before you start installation of this Patch Kit. UNIQUE is a product which requires a software key.

- Output to a connected printer.

  By changing the variable TINFO, you can choose if you want the output to the console to be written on a printer or on the terminal.

  TINFO = 0 : the output will be written on the terminal  
  TINFO = 20 : the output will be routed to a connected printer

  After installation of this Patch Kit, TINFO is set to 20.  
  If you do not have a printer connected to the console terminal, all output will disappear.

  To change TINFO, the following procedure should be used:

  ```
  @SINTRAN-SERVICE-PROGRAM~ 
  *CHANGE-DATAFIELD I I N Y Y~ 
  TINFO/ nnn 0~         (or 20)

  *EXIT~
  ```

- Prerequisite for all ND tpServer models:
  - Console terminal
  - 310 Mbyte System disk divided into two directories:
    - PACK-BASIC-C (DISC-2-SCSI-1,0,0)
    - PACK-MAIN-SW (DISC-2-SCSI-1,0,1)
  - Streamer drive (155 Mbyte)

## 3 Manual Installation Procedure

```
+--------------------------------------------------------+
| CAUTION!                                               |
|                                                        |
| Before you start this installation procedure, ensure   |
| that you have an image backup of PACK-BASIC-C and      |
| PACK-MAIN-SW.                                          |
| Set the system unavailable and get all users to stop   |
| working on the machine.                                |
+--------------------------------------------------------+
```

1. **Check the Size and Number of Files for Some User Areas**

   This is a job that must be done manually.

   The directory PACK-BASIC must have at least 1200 unreserved pages.

   | User area                    | Requirement                                 |
   |------------------------------|---------------------------------------------|
   | PACK-BASIC-C:RT              | must have 1100 free pages.                  |
   | PACK-BASIC-C:SYSTEM          | must have 1100 free pages and 13 free file entries. |

   User area PACK-MAIN-SW:RT must have no files and no space. Files on this user must either be moved to user PACK-BASIC:RT or be deleted. When all files are deleted, use the command @TAKE-USER-SPACE to remove all user space from PACK-MAIN-SW:RT.

2. **Make a Note of the Password for User Area SYSTEM**

   You need the SINTRAN password for user area SYSTEM during the installation of this Patch kit.

3. **Make a Note of the Password for User SIBAS Manager**

   You need the User-Environment password for user SIBAS Manager during the installation of this Patch kit.

## 6. @MODE COLD-START-SEQ:MODE,,,´

This MODE-job will prepare the COLD-START to automatically start the file SHORT-HENT:MODE.

## 7. PERFORM THIS STEP ONLY IF YOU ARE USING THE RAM DISK FEATURE

To find out if you are using this feature, you can use the command 
`@LIST-USER` to check if user area SCRATCH-RAM exists on your system.

If you are not using the RAM disk feature, skip to step 8.

Execute the command:

```
@RAM-SCRATCH:MODE,,,´
```

This MODE-JOB will set up the memory configuration to allow part of memory to be used as a RAM disk.

**NOTE:** Automatic start of the SHORT-HENT:MODE file is implemented.

-*- SYSTEM IS AVAILABLE, AND READY FOR PATCHING. -*-

If this sequence finishes with only the message: - Exit -  
you should inspect the file (SYSTEM)HENT-OUTPUT:LIST to determine what went wrong and correct this.

This procedure takes about 10 minutes.

Log in as user area SYSTEM (without giving any password).

## 12. Modifying for Special Modification Reports (SM Reports)

If you do not want to run any SM reports, verify that the file `(SYSTEM)PF-MODIF-N:FADM` exists and consists of only one line containing the character `@`.

If you want to run some Special Modification patches, you must edit the file `(SYSTEM)PF-MODIF-N:FADM` before you run the file `(SYSTEM)AFTER-COPY:MODE`.

A list of Special Modification Reports is found on page 13.

The file `(SYSTEM)PF-MODIF-N:FADM` must contain the library mark for the SM report(s). After editing it should look like this (7-bit format):

```
PN031
PN035
@
```

If you want to install additional SM patches at a later stage, follow the procedure described on page 23.

## 15. Link Applications Using SIBAS/R to the New Version of the SIBAS Library

All applications using SIBAS/R must be linked to the new version of the SIBAS library (SIBR-b)SIBR-LIBRARY-B07:SEG.

Use the ND-Linker (in the example below, we assume that the application is called APPLICATION:DOM):

```
@LINKER
NDL(ADV): LINKER-SERVICE-PROGRAM
NDL(SRV): CHANGE-FILE-REFERENCES APPLICATION:DOM
Old string name: (SIBR-B)SIBR-LIBRARY-B06:SEG
New string name: (SIBR-B)SIBR-LIBRARY-B07:SEG
xx substitutions done in domain APPLICATION:DOM
NDL(SRV) EXIT
NDL(ADV) EXIT
```

## Work Space for the SQL Server

The work area (SINTRAN user area) for the SQL server must be defined in the SW-CONFIG file under the section "SYSTEM-NAME : SQL-SERVER-xxx".

**DATA-FILE** = (user name) file name  
"file name" is used by the SQL server to generate names of the work files.  
"file name" is only a prefix to the file names created by the SQL server and can be up to 13 characters long.  
File type may not be given.

The SQL server will create (no. of threads * 5 + 3) work files on the SINTRAN user area defined. All files are created when the SQL server is starting, if they do not already exist. If the files already exist, all allocated file space will be released (it is quite safe to delete all the work files of a passive server).

The necessary work space on the SINTRAN user area depends on the following parameters: what kind of SQL queries to be run; the size of the returned data; if the data must be sorted; the number of active cursors; if "joins" are used; and the number of SQL threads in use (a set of work files is created for each thread).

The only way of finding the necessary work space is therefore to allocate a large amount of extra space and later release the unused space when the system has been in operation for a while (for example 5000–10000 pages).

# SPRINT OpenLAN Printers with SINTRAN Spooling Queue

The procedure for defining OpenLAN printers with a SINTRAN spooling queue is as follows:

1. Select a SINTRAN logical device number between 2300₈ and 2377₈ (1216 to 1279 decimal).

2. Connect the logical device number to the COSPO data field:
   - Read the file SYMBOL-2-LIST:SYMB into an editor (for example PED) and find the symbol `F1731`. Note the value of the symbol.
   - In a standard ND tpServer platform version C02 the value (data field address) is 077536.

   **Note:**  
   This address may be different in later version. You should therefore always verify the value of this address, because patching in the wrong address may cause serious damage to your system.

3. Then execute the following commands:
   ```
   @SINTRAN-SERVICE
   INSERT-IN-LOGICAL-UNIT-TABLE
   LOGICAL UNIT NUMBER (OCT): 23xx    (use the device number you selected)
   INPUT OR OUTPUT? OUT
   DATAFIELD ADDRESS (OCT): 077536    (use the address you noted above)
   MEMORY? YES
   IMAGE? YES
   SAVE-AREA? YES
   EXIT
   ```

4. Define the device number in the S3-CONFIG program and then perform a cold start or use the command `SET-SPOOLING-DEVICE` in the SINTRAN Service Program.

5. Define a peripheral file and spooling files in the usual way.

6. Stop COSMOS spooling by executing the command `@ABORT COSPO`  
   (Otherwise you will get the error message `Device already defined` when defining the printer in SPRINT).

7. Define the printer in AIP-HOST:SYMB and SPRINT.

8. Start COSMOS spooling: `@START-SPOOLING COSMOS-SPOOLING`

9. Stop and start SPRINT.  
   Otherwise you will get the error message `Not opened for sequential read` when printing via SINTRAN III.

If the printer is only to be used from NOTIS-WP version N or later or other applications with a direct SPRINT interface, you should skip all steps above except 7 and 9.

# UPS Server for SINTRAN Version A

The server RT-program PFTCON will be started during a SINTRAN start-up, when running SINTRAN version N or later. The RT-program is an integrated part of SINTRAN N.

The PFTCON server will check if the UPS Power Supply is present by sending Octobus messages to the Octobus station of the UPS power supply. If no answer is returned from the UPS then the UPS power-server PFTCON will enter the passive state, otherwise it will reserve a TAD logical device and start the communication with the UPS Octobus station.

If a power is lost for more than ten seconds, the UPS power server will detect this, and the TAD device already reserved will execute the command:

```
MODE SHUT-POWERFAIL:MODE SHUT-POWERFAIL:OUT
```

When the mode file is finished, the UPS power server will take over and send an Octobus message to the UPS power to turn off the power to avoid battery drainage.

The SHUT-POWERFAIL:MODE is included in the platform software. For a non-platform system, this mode file should be modified according to the customer needs.

**Note:**  
The files must not be deleted nor renamed!

A monitor program for display and adjustments can be used with the UPS Power Server. This program is called PS-MONITOR, and it uses Nucleus for communication with the power supply (requires that the command @START-SERVERS has been executed, and that your system is an ND-5000).
