# 1 INTRODUCTION

This product contains the necessary software modules to run the ND-100 (IPS) side of the Wordplex/IPS Bridge. It is made up of an RT server program and some patches to the MTAD system software.

Using the WPX/IPS Bridge, all users connected to the 8000 can log in to the IPS using the product "IPS Terminal Program - WPX/IPS Bridge", number ND-211319, which should be installed on the 8000. In addition, documents may be shared between the 8000 and IPS by means of the document copying options in NOTIS-DH, product number ND-211266, which should be installed on the IPS.

# 2 INSTALLATION PROCEDURE

- Before starting installation, make sure that no one else is working on the IPS system.

- If a Wordplex 8000 is connected to the MPM4 card, the MMIC card must NOT be active.

- Log in as user SYSTEM on the IPS system.

- Check the HENT-MODE:MODE file to see if it already installs the COMMTAD tasks. If so, comment out by inserting '@CC' on the COMMTAD lines. Do the same in the LOAD-MODE:MODE file.

- If COMMTAD has already been installed (and therefore you commented it out from the two files) then do a cold start, as specified in the supervisors manual, before continuing as below.

- Insert the floppy labelled 211320A<rev>-XX-01D into the floppy drive and enter the directory by typing:

```
@ENTER-DIRECTORY,211320,F-D-1,< UNIT NO > ↵
```

- Then type:

```
@(211320:FLOPPY-USER)COMMTAD-INST ↵
```

This starts the installation program which checks the system for the correct SINTRAN version, then checks/creates the user COMMTAD and copies the files to this user and some files to user SYSTEM.

After the COMMTAD server has been dumped, you are asked if you want to run the mode job that patches MTAD in SINTRAN. If this patching has been done on your SINTRAN after the last COLD START, you should answer NO. There is no danger of patching several times, although it occupies unnecessary space in the SINTRAN area.
NOTE: The first time you install this software you **must** answer YES.

When the installation is completed, you should check the two output files to see that everything has been installed properly. The files to check are:

```
(COMMTAD)COMMTAD-PTCH-A:LIST
(COMMTAD)COMMTAD-LOAD-A:LIST
```

After the installation is finished, follow this procedure:

1. Insert in the file HENT-MODE:MODE these lines:
   ```
   @CC
   @CC Loading COMMTAD server for IPS Bridge
   @MODE (COMMTAD)COMMTAD-PTCH-A:MODE (COMMTAD)COMMTAD-PTCH-A:LIST
   @(COMMTAD)COMMTAD-INST-A CHECK-PATCH
   @MODE (COMMTAD)COMMTAD-LOAD-A:MODE (COMMTAD)COMMTAD-LOAD-A:LIST
   ```

   If earlier versions have been installed before, remove additional "`@MODE (COMMTAD)`" line(s).

2. In the LOAD-MODE:MODE just after the directories are entered:
   ```
   @CC
   @CC Starting COMMTAD server for IPS Bridge
   @MODE (COMMTAD)COMMTAD-STA-A:MODE (COMMTAD)COMMTAD-STA-A:LIST
   ```

   Check that the HENT-MODE:MODE, as the very last thing, does a `@RESTART-SYSTEM`, rather than just running the LOAD-MODE:MODE file.

2. Restart the system to make the patches valid.

   **WARNING:** Do not start the server before a restart is done.

3. After SINTRAN is restarted, the Wordplex 8000 may be restarted to load the MMIC card, and the communication should be up and running.

3 Using the HARMONY file transfer
---------------------------------

The enhanced NOTIS-DH file transfer is using LAMUS as file transfer buffers. Each of the 40 possible connected WPX workstations needs one buffer to be able to do file transfer. Hence you need 40 LAMUs just for the file transfer buffers (that is if all workstations need to be able to do file transfer). The SINTRAN default no. of LAMUs is 15. To change this value, log in as user SYSTEM and do the following:

```
@SINTRAN-SERVICE 
*SET-LAMU-CONSTANTS
NO. OF LAMUS PR. RT PROGRAM (OCT):□
TOTAL NO. OF LAMUS (OCT):□
TOTAL NO. OF SYSTEM-LAMUS (OCT):nn□
```

`<nn>` should be a value greater or equal to 70B. A restart of the system is necessary to put this change in effect.

```
 ___________________________________________
|                                           |
| NOTE: This change is done on the IMAGE    |
| area, and the change would consequently   |
| be lost after a cold start.               |
|___________________________________________|
```

4 Running HARMONY IPS/WPX bridge and OpenLAN
--------------------------------------------

When running Harmony IPS/WPX bridge and OpenLAN/Ethernet on the same system, you might run out of background processes (eg. MTADs). The Harmony IPS/WPX bridge requires 50B MTADs. The OpenLAN/Ethernet requires 30B. The default generated in SINTRAN is 40B. To change this value, log in as user SYSTEM and do the following:

```
@SINTRAN-SERVICE 
*CHANGE-VARIABLE MTMAX
VALUE(OCT):<nn>□
IMAGE? Y□
SAVE-AREA? Y□

IMAGE: <old value>
SAVE-AREA: <old value>
```

`<nn>` should be a value greater or equal to 100B.

A restart of the system is necessary to put this change in effect.

# 5 COMmTAD Utility Program

This is a utility program that runs in the IPS system and makes it possible to look into and have decoded the contents of the shared memory. The program is started by typing `@COMMTAD-UTIL;`.

All values shown are in decimal. Input and Output refer to the ND side.

The program has the following commands:

## 1) Display initialisation array

This command gives the content of all variables in the initialisation array. The most interesting variables are NDRES and WPRES which indicate that the initialisation has been done.

## 2) Display request queue

The first screen picture of this command gives the Input interrupt queue and its header. The PUT variable tells where in the queue the Wordplex will put the mailbox number of the next interrupt, and GET is where the COMmTAD server will read the next time it is kicked from Wordplex. If GET and PUT have the same value there are no outstanding kicks in the queue and if PUT is one less than GET the buffer is full.

The next screen picture is for the Output interrupt queue, and the values GET and PUT are updated by the opposite server as in the Input screen picture.

## 3) Display MTAD mailbox control block

This command asks for the mailbox ID, and then displays the control block for a specified mailbox. The variables for read and write will tell where in the two ring buffers the different servers will read/write the next time they are accessing this mailbox.

## 4) Display MTAD mailbox buffer

This command will ask for mailbox ID. The first screen picture shows the input buffer, first in decimal numbers then decoded to ASCII characters. The second screen picture shows the Output buffer.

## 5) Reconnect MTAD Mailbox

This command will reconnect a specified mailbox. If a user was logged in through this MTAD, all connection will be lost and he/she will have to log in again.

## 6) Kick MTAD

This command will give a specified MTAD a kick in the same way as when there has been a kick from the Wordplex side.

## 7) Kick WPX

This command kicks the MMIC board through the asynchronous line.

## 8) Exit

Exits the program.
