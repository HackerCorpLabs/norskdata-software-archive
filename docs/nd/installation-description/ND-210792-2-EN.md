## Description of Product

NOTIS-ID is ND's electronic mail system aimed at distribution of messages and documents in a COSMOS network.

The product consists of the following diskettes:
```
210792B12-<lng>-01D    (where <lng> is EN, NO etc.)
210792B12-XX-01D
```

which contain the installation program, the NOTIS-ID Main User Program, the Queue Server, the Transfer Server, the Server driver program and the Service Program.
  
**Note:** A version of the User program that is compatible with Notis-WP version M is included for the convenience of customers that still need it. It has NOT been changed in any way since the B07 release, however.

**Documentation:**

- NOTIS-ID User Guide ................. 863011.02 EN
- NOTIS-ID Supervisor Guide ........... 830062.01 EN

## Reason(s) for the New Version

```
This version of NOTIS-ID on ND-500(0) is the first version of
NOTIS-ID Main User Program that offers full integration between
the ND host NOTIS product line and the new NOTIS concept developed
for PC. The differences in user interface between NOTIS-ID for
ND-500(0) and PC-NOTIS ID are kept on a minimum.
```

## 4 Installation Procedure

### 4.1 Automatic Installation

**Installation Procedure**

- Delete all files on user NOTIS with extension :D500.
- Log in as user SYSTEM.
- If the system is running User Environment version D you MUST define a new user named NOTIS-ID SERVER. It must have SERVER authorization.
- Insert the diskette 210792B<rev>-<lng>-01D into the machine.
- Enter the directory by typing:

  ```
  @ENTER-DIR 210792B <floppy_drive> <unit>~
  ```

- Start installation:

  ```
  @(210792B:FLOPPY-USER)ID-INSTALL.~
  ```

**After Installation**

In the following presentation,

- `<sysno>` denotes the CPU-number of the system that has the Mail-Server part of NOTIS-ID installed.
- `<notis-id-user>` denotes the name of the storage area (SINTRAN user) where the files and domains of NOTIS-ID have been stored during installation. The default choice (presented during installation) is DOMAINS.
- `<utility-user>` denotes the name of the storage area where the system utility programs (such as XMSG-COMMAND) are located.

- Include the following commands in the XMSG-START file after existing DEFINE-REMOTE-NAME commands.

  ```
  @(<utility-user>)XMSG-COMMAND
  DEFINE-REMOTE-NAME,.*IDYSYSTEM <sysno>
  EXIT
  ```

- Ensure also that the name *DSSYSTEM is defined on your system (and on the system where the Mail-Server part of NOTIS-ID is installed if it is installed on another system).

  Use the commands to check this:

  ```
  @(<utility-user>)XMSG-COMMAND
  LIST-NAMES,.
  LIST-NAMES <sysno>
  EXIT
  ```

- If the name is missing, include the following commands in the XMSG-START file on your system (and on the system where the Mail-Server part is installed if it is on another system):

  (include the commands AFTER existing DEFINE-REMOTE-NAME commands)

  ```
  @(<utility-user>)XMSG-COMMAND
  DEFINE-REMOTE-NAME,.*DSSYSTEM <DSsysno>
  EXIT
  ```

  (Here <DSsysno> denotes the system where the document storage, NOTIS-ID is located)

# 5 Modifications

## 5.1 In Revision B10

- A change has been made in the user interface concerning formatting of directives using the "PRINT"-key. Notis-ID will ask if any directives within the text should be formatted.

- A new version of BMS has been included making it possible to move back and forth between programs on the HOST and programs on the PC.

- Printer output now uses S-format :OUT file codes, instead of the older 8-bit :OUT format. This means that it is possible to print on the ND-715 Postscript printer directly from Notis-ID.

## 5.2 In Revision B12

- If a letter is read by a friend of the recipient (or by a user group member if the recipient was a user group) this will be handled as if the recipient had read it herself. I.e. mail-count will be decremented and a receipt is sent if the letter was registered. To the originator it will appear that the intended recipient had read the letter.

- When running on a system with User Environment version D, Notis-ID is aware that a given user name refers to the same person (recipient) on all systems in the local domain. Specifically, users can read their mail on any system in the local domain, as long as they can reach their normal archive (Notis-DS system) from it.
  NOTE: The mail servers log into UE as user NOTIS-ID SERVER, which must have "server" authorization.

- An accounting log has been implemented. It may be turned on by changing the ACCOUNTING parameter with the service program. It is stored on the file (NOTIS)NOTIS-ID-ACC-B:LOGS. The accounting log will only contain information about successful deliveries. There is no option to record information about unsuccessful transmissions, e.g. for statistical or diagnostic purposes. Contact Norsk Data for further information if you want to use this feature.

- The address for patching the form name that is used when printing directly to SPRINT has been changed. The new address is 1'226441B. (See report number 1 for product 210792B07 in the February 1989 issue of Customer Support Information for further information.)

## 6 Errors Corrected

### 6.1 In Revision B11

Changes have been made in the ID Main User Program B11. There was an error in B10 concerning "Letter/Fetch". This has now been corrected.

### 6.2 In Revision B12

- Pagination of printer output will be correct.

- It is possible to list available printers even if more than 17 are defined in SPRINT.

- An error that could cause the message "132B: No file opened with this number" when mailing a letter has been corrected.

- An error that could cause users to receive empty letters has been corrected.

- An error (introduced in B10) that would cause move/copy to SINTRAN files to create empty files has been corrected.

- When copying a document to the same folder as the original is in, the document list is reread from NOTIS DS to present a correct list.

- Before retrying undelivered messages the Mail Server would query XMSG on all addressees' systems to determine which systems their DS archives reside on, also for addressees to whom the letter already had been delivered. This caused problems in X.25 based networks, as well as being wasteful.

- The error described in SSR#8 in the December 1988 issue of CSI (Customer Support Information) regarding multiple recipients with similar names has been corrected.

- Notis-ID attempts to recover from DS-server disconnects (idle timeout) without bothering the user with error messages. (But see chapter 7.)

- Notis-ID attempted to inform Notis-Mail at each recipient's address that a letter had been delivered. Notis-ID now attempts to check if the recipient’s system has Notis-Mail installed, and where in the network the Notis-Mail servers are running before attempting to inform Notis-Mail about new letters.

## 7 Errors Known but Not Corrected

### User Interface Program:

When starting NOTIS-ID when not logged in through User Environment, the program terminates and no message is given. Sometimes the program will hang instead.

When executing a SINTRAN-command inside NOTIS-ID, the screen is cleared directly.

If the SPRINT spooling system reports an error condition when you attempt to print out a letter, the error message from SPRINT will be overwritten by the message "Fatal error 0I in routine 0A. Please contact ND." (Or the equivalent in your language.) Press the sequence <FUNC> 5 L <FUNC> 5 P to see the message from SPRINT.

If you are logged on to a computer (e.g. SYSA) that uses a Notis-DS archive on another computer (e.g. SYSB), and you set your default archive to be SYSA by using the Notis-DS command Functions/Set default, Notis-WP and Notis-DS will work fine, but Notis-ID will claim that Notis-DS isn’t available.

If Notis-DS disconnects a Notis-ID user while she is using the editor, Notis-ID fails to recover from this situation, making it impossible to store the letter the user was working on.

### Errors in the Mail Servers

If Notis-ID is installed on a system that is running User Environment version D, and the Mail Server (IDMS) is unable to log in, e.g. because the user name NOTIS-ID SERVER hasn’t been defined and given SERVER authorization, the mail server may crash due to a Protect Violation Trap, instead of reporting the error.

## Errors in the Service Program

On computers that are running User Environment version D you can't start the Mail Servers without being logged into User Environment even if you are logged in to Sintran user area SYSTEM. This is a problem for the batch job (typically LOAD-MODE:MODE) that is run after a warm start. Create a User Environment user BATCH OPERATOR with OPERATOR authorization, SINTRAN access and SYSTEM as default user area. Add the following to LOAD-MODE:MODE immediately before the commands to start Notis-ID:

```
@UE-LOGIN
BATCH OPERATOR
<password for user BATCH OPERATOR>
```

## Compatibility Problems

- User Environment version D has an idle session time-out feature that causes processes that haven’t called the Profile Manager for a certain period of time to be logged out. This can cause problems with NOTIS-ID if the time-out period is too short. Increase it to several days. (See the User Environment Reference Manual, ND-861094.4EN, page 97-99, "Editing machine-specific parameters" for further details.)

- The Mail Server will sometimes abort, reporting "Communication problems in User Environment" when User Environment version D performs a "soft" restart.
