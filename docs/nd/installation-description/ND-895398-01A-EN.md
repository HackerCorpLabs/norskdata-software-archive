# Description of Product

The COSMOS X.25 Option for PIOC provides for access to the public data networks (PDNs). Both the extension of a COSMOS network over the PDN and access to other vendors’ machines are made possible. To access other ND hosts (and thus extending the COSMOS network) the COSMOS X.25 Network Server is used. The Network Server is delivered as a part of this product. Other vendors’ hosts can be accessed by using the product COSMOS X.29 PAD (ND 210405), and the ND host can be accessed from other vendors’ hosts by using the product COSMOS X.29 Server (ND 210578). An OSI Transport Service (ND 211023) is also available.

## 4 Installation Procedure

### 4.1 Copying the Files from Diskettes

In the following instructions, please replace `<rev>` with the current revision number.

- Log in as user SYSTEM.

- Make available the user COS-NETSERVERS with at least 800 pages and 26 files free. The user X25-NETWORK or any suitable user can also host the product, but be aware that the file **X25PI-PROFILE:-SAVE must always be present** under either user SYSTEM, COS-NETSERVERS or X25-NETWORK.

- Make available the installation user with at least 200 pages and 5 files free. The user UTILITY is proposed as installation user by the installation program.

- Insert the diskette with the directory name 210570A<rev>-XX-01D.

- Execute these commands (operator input is underlined):

```
@ENTER-DIRECTORY,210570A<rev>-XX-01,FLOPPY-DISC-1.0_
@(210570A-XX-01:FLOPPY-USER)INST-X25PI-A_
```

The installation procedure then starts. It will:

- Check chosen users.
- Delete old versions of the product.
- Copy the new files to the user hosting the product.
- Prepare the mode-files according to chosen values.

**NOTE:** Previous versions of the configuration dependant files X25PI-START-A:MODE and X25NS-START-A:MODE will be deleted by the installation program if not saved. If new START files are used, they must be edited before the system can be started. This editing is done automatically by the installation program, but can also be done manually.

### 4.2 Running with SINTRAN < K 3200B

If you run a SINTRAN K revision 3200B or older, the file X25PI-SIN3-K-A:PATC must be run. To make patches effective, the system must be restarted. If patches are not run, the X25 module may crash at any time.

## 4.3 Loading

When you have installed the new X.25 system, you can load it using the mode file `X25PI-SYSLO-A:MODE`. This file should be called from the `HENT-MODE:MODE` file, which is run at "COLD-START".

## 4.4 Configuring and Starting

The mode-file `X25PI-START-A:MODE` is used to initialize and start the X.25 packet- and link-level. The parameters in this file should be edited to suit the X.25 connection supplied by your local PDN authority.

The file `X25NS-START-A:MODE` starts the X.25 Network Server, defines COSMOS X.25 connections, and also calls `X25PI-START-A:MODE`. The file `X25NS-START-A:MODE` should be called from your `LOAD-MODE:MODE` file in order to make COSMOS X.25 start automatically after a "WARM-START". 

The file `X25PI-OPEREX-A:LIST` shows an example of output from the mode-file `X25NS-START-A`.

## 4.5 Getting the PIOC Status Word

To ease troubleshooting and correction a special program is delivered with this product: `X25PI-PISTAT-A<rev>:PROG`.

It will give you the size of the PIOC memory, tell you in which memory-banks the PIOC is located, and give its start address. The size of the PIOC should **ALWAYS** be 512KBytes, while the other data can be used if SINTRAN need to be reconfigured (see below!).

## 4.6 Troubleshooting

The most common error when installing the X.25 PIOC Option is that the physical memory in the PIOC is used by SINTRAN for some system table. The error occurs when the START-MODULE command is given in the X25 Command program and results in the error message: "Unable to load PIOC"

If the PIOC physical memory is moved to the middle of the physical address range the problem may be resolved. To do this the system supervisor should consult the "PIOC Hardware Reference Manual".

## 4.7 Changes in X-Message and File-Transfer

It is necessary to increase some of the X-MESSAGE network timeouts. You must do the following:

### With SINTRAN K:

- Set X5TO1 to 400 (ie. 40 seconds).
- Set X5TO2 to 400 (ie. 40 seconds).
- Set X5NGT to 200 (ie. 20 seconds).

This is done using the XMSG installation program, which changes the parameters of XMSG. You must then reload and restart XMSG. This should be done on all the machines in the COSMOS network.

### With SINTRAN L (or later):

- Set 'Timeout in XTUs when receiving datagrams' to 400
- Set 'Timeout in XTUs when transmitting datagrams' to 400
- Set 'Gateway timeout in XTUs when sending to net server' to 200

These parameters are changed in the S3-CONFIG program. Afterwards, you must run the command GENERATE in S3-CONFIG, and then COLD-START the machine. This should be done on all the machines in the COSMOS network.

Additionally, the FILE-TRANSFER timeout should be patched to 170B (=120 seconds) on the segment XFTRAD, like this:

```
@LOOK-AT SEGMENT XFTRAD~
YYYYY/xxx 170~
```

YYYYY is the location of the timeout value on the XFTRAD segment, and can be found in the load-file COS-XFTRA:MODE.

## 8.2 Channel Group Number

Some PDNs (e.g. PSS in the UK) use the channel group number in addition to the channel number. When you apply for an X.25 connection, you must specify the number of channels you want to use. The network provider may tell you which channel group they belong to. The X.25 profile command in the command program requires a channel number only. Hence, you must transform the channel group number and channel number to a channel number for the command program. It is done in this way:

- Lower bound: Multiply the channel group number by 256.
- Upper bound: Lower bound + (number of channel -1)

Example:

The network provider gives you this channel information:
- Channel group is 4.
- Number of channels is 8.

The channel range used in the command program will then be:
- Lower bound: (4 * 256) = 1024 (default value)
- Upper bound: (4 * 256) + 7 = 1031 (default value)

## 8.3 Diagnostic Program

The X.25 diagnostic program (X25PI-DIAG-A:PROG) is a tool, which enables an operator to establish a fast and simple diagnostic on the current status of connections within a COSMOS X.25 network.

## 8.4 Network Server Timeouts

The network server checks all the connections in use. If it takes too long time to complete a connect request, the connect is aborted, and the user data returned to X-MESSAGE. The connect request timeout is set to 60 seconds.

The network server will clear a connection if it takes too long to receive the acknowledgement of a sent data packet. The data packet timeout is set to 90 seconds.

## 8.5 Network Server and Packet Level Window Size

The network server will try to negotiate a bigger packet level window size when a CALL REQUEST is sent. The window negotiation can be switched off with the variable X25EXTF.

Values:  
0 - No negotiation will be attempted.  
1 - Negotiation (default).

## 8.6 Network Server Logging

The network server will count the number of entries written on the file. When this number exceeds a pre-defined maximum, the file is rewound. The parameter must be structured if you want to use it as an NSAP parameter. If you want to send a DTE subaddress on outgoing calls, and ignore it when finding a match for incoming calls, the subaddress is delimited with a `.`.

### Example

```
2422110006.55     The network server will send the DTE number 
                  242211000655, but for incoming calls search 
                  for a match with the number 2422110006.
```

If you do not want to ignore the subaddress for incoming calls, you do not need the delimiter (incoming address = outgoing address).

The X.25 call user data field can be used for extended addressing. The delimiter `+` is used to delimit the DTE address from the address part in the call user data field. The address used for outgoing calls must be indicated first. After the delimiter `/` the address for incoming calls is given. If they are identical, they must be entered twice. Usually they are not. Since this NSAP parameter is one parameter in the XMSG command program, spaces and commas are not allowed in the parameter string. The `;` is interpreted as `,`, and `$` as ` ` (space). `;;` must be used to indicate `;` and `$$` for `$`. `//` is interpreted as `/` (no delimiter). A `/` as the last character in the outgoing address part is impossible.

### Example

```
40+PSS(AAA;BBB).NFS  63500140/GB  263500140
Outgoing call user data field:  PSS(AAA,BBB).NFS  63500140
Incoming call user data field:  GB  263500140
```

```
...../   is interpreted as   .....    (redundant delimiter)
..../    ...../              (character '/', no delimiter)
                           no incoming address part)
.././    ../.               (character '/', no delimiter)
../../   ..D.               (Delimiter)
.///.    ..D/.              (Delimiter, first incoming 
                           character is '/')
```
