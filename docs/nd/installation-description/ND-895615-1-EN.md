## Description of Product

With version B01 of SIBAS/R SQL Interactive for ND-500/5000 (SQLI-B01) you can write and execute queries, look at the result, and store queries in a database.

The product also contains the file REDEF-SQL, containing instructions to redefine a database with the system tables NDSQLT01 and NDSQLT02.

NDSQLT01 allows you to store queries in the database. NDSQLT02 allows you to protect individual tables against select, delete, update, or insert queries.

The schema definition for the DIALOGUE example database is also included. The file SQL-TUTORIAL-B01:LIST is a collection of examples from this database. It is produced by the batch input file SQL-TUTORIAL-B01:SQL.

## Reason(s) for New Release

```
- The new SIBAS process with built in SQL server allows SQL
  programming from application programs.

- The Interactive Query Editor, SQLI-B01, is an updated version
  of the SQLI-A version, but can only use SIBAS with built in
  SQL server. SQLI-B01 sends queries to the database server for
  execution, just like an application program using the SQL
  Library. The old SQLI-A version can still be used, but cannot
  store queries in the new database.
```

## 4 Installation Procedure

The installation process is fairly simple. SQLI is in the new domain format. All files should be copied to user SQL-SYS.

SIBAS/R B05 must have been installed! Then SQLI must be linked to Sibas library on Sintran user SIBR-B.

SQLI-B is language dependent. The text strings on the message and status lines are fetched from UE. The UE-ERMSG-xx-Dyy:ERR file on your system should therefore be D09 or later.

NOTIS-WP  
SQLI calls NOTIS-WP as a subroutine when the user wants to look at the contents of a wide column.  
SQLI in the new domain format and must be linked to NOTIS-WP in the new format.  
The system therefore contains a special converted WP-500-N05.

### 4.1 Automatic Installation

The installation must be done manually.

### 4.2 Non-Automatic Installation

1. Log in as SINTRAN user SYSTEM

2. Create a user with the name SQL-SYS  
   If user already exists, you should delete all files on this user. (Except for SQL-library if you have installed it already).
   ```
   @create-user sql-sys
   @create-user <directory>:SQL-SYS
   ```

3. Give SQL-SYS 1300 pages (minimum)  
   ```
   @give-user-space <directory>:SQL-SYS,1300
   ```

4. Enter user SQL-SYS  
   ```
   @new SQL-SYS
   ```
   You must be this user in the following steps.

## 6

SQLI is normally defined as a standard domain:
```
@ND
define-standard-domain SQLI-B01,(SQL-SYS)SQLI-B01:DOM
exit
```

The first time you use SQLI and open a database, the SQL-server in the SIBAS/R database process will be activated for the first time. The parameters for SQLI and the SQL-server must be set correctly in the (ND-OPERATIONS)SW-CONFIG file before you access a database. See chapter 4.4.

Any errors from initialization of the SQL-server will be printed on the error device.
_NOTE: If the server does not start correctly the first time, you must stop and restart SIBAS before you try again._

## 4.3 Installing HELP-Pictures in a New Language

This is an option. Skip this chapter if first installation.

To make HELP-pictures in a new language, you have to translate the file SQLI-EN-B01:CMND. Call the file SQLI-YY-B01:CMND where YY is the new language code.

This file will be automatically compiled the first time a user with language code YY (registered in User Environment) enters SQLI-B. A new object file (SQL-SYS)SQLI-YY-B01:DATA is generated.

Next time a user with language code YY enters SQLI-B, no compilation will take place. The existence of the file SQLI-YY-B01:DATA indicates that the data is ready and will be loaded into the data segment overlapping the default language.

Languages other than the default (English) need a little extra overhead because the file SQLI-YY-B01:DATA is located, opened and read into the data segment called SQL-NDP-SEG:SEG each time SQLI is started.

## DATABASE-ADMINISTRATOR = <ue name>
The name of the database administrator is only important if you use the security system. Only the database administrator can grant or revoke privileges.

## PURPOSE = <text describing the database>
The purpose will appear as a description after the database name when you press shift+HELP.

Prompt for database password

The SQL-server part of a SIBAS process looks for a SYSTEM with the name SQL-SERVER-<no> where <no> is the SIBAS process number.

If this specification is missing, you cannot use SQLI on the database!

## SYSTEM-NAME : SQL-SERVER-kk
This process contains a SQL server. kk is the process number. This system name must be present for local databases. Otherwise you will not see them when you press shift+HELP at request for database name.

The parameters of SQL-SEVER-xx are described in the SIBAS documentation, and may be changed in new SIBAS versions. Only the database administrator should insert or change these parameters.

However, for SIBAS/R B05, the following information can be given:

## FUNCTIONS = <func>
The <func> parameter tells which functions the SQL server can perform. The legal values are:

- SELECT: Select only.
- INSERT: Insert only.
- UPDATE: Update only.
- DELETE: Delete only.
- ALL: All SQL transactions can be run. (default)

## AVAILABILITY = `<avail>`

The `<avail>` parameter tells which range of users the server can handle.  
The legal values are:

- **SQLI**: only requests sent from SQLI are legal
- **LIBRARY**: only requests sent from user written programs are legal.
- **ALL**: Both SQLI and LIBRARY. (default)

## DATA-FILE = `<filename>` No default, must be present!

The SQL server will use this file name as a basis for creating temporary work files.  
The server will work as the Sintran user SYSTEM.  
Make sure that user SYSTEM is able to create and use these files.

The files are:

```
<filename>:SWAP
<filename>:SORT
<filename>:DATA
<filename>-n:JOI1
<filename>-n:JOI2
<filename>-n:JOI3
<filename>-n:UNI0
```

where n is the SIBAS thread number (only one thread in BO5).

The size of these files depends on the size of the database and the queries.  
The files could be placed on a special SINTRAN user area, or on the database user area. (Example: (sql-work)serv4)

## LOGGING = <logtype>

The `<logtype>` parameter specifies which kind of logging the user requests. This log is only for troubleshooting, and is normally not used.

The legal values are:

- **NOLOG**  
  No logging is used. (default)
- **SIMPLE**  
  A simple logging is performed. This logging tells which users the server has received requests from.
- **DETAILED**  
  A detailed logging telling which calls and transactions the users have used.
- **COMPLEX**  
  A complex logging logging almost everything happening in the SQL server. This feature is time consuming and should be used only when debugging errors.

## LOG-FILE = <logfile>

This is a trouble-shooting log for SQL only.  
The log is cyclic, and has a fixed size of 300 pages (600K bytes).  
You can inspect the file (or print it) with an editor.  
The last error or message in the log is followed by a sequence of equal signs `'=================='`.  
The default file type is :LOGG.  
This file is not created automatically. You must create it!

Example:

```
SYSTEM-NAME : SQL-SERVER-4
FUNCTIONS   = ALL
AVAILABILITY = ALL
DATA-FILE   = (SQL-TEST)SQL-FIL4
```

## 5 Modifications

### 5.1 New Functions/Commands

In the SQL language:

- UNION has been implemented.
- Cartesian product when joining tables.
  The A version could only handle equi-joins.
- Wide Columns.
- Keyword index. SQL will use the keyword index to find rows
  in a column with keyword index.
- The GRANT and REVOKE have been implemented.
  These functions will work on databases if the system table
  NDSQLT02 is present.
- You can refer to an element of an array within a column.
  (This is a feature of SIBAS and not standard SQL.)
- Datatypes date, week and time.

A new batch command lets you make a form or letter for each row
of a result table.

All new features are shown in the tutorial batch files of the
DIALOGUE database, SQL-TUTORIAL-B01:SQL and SQL-TUTORIAL-B01:LIST.
The :LIST file is in NOTIS-WP format, the :SQL file is in 7 bit
format.

### 5.2 Changed Functions/Commands

SQL system tables (Changes in database schema for SQL tables).

SQLI-B01 can not execute queries stored in a database with SQLI-A.
The structure of the system table has been totally changed.

SQLI-B01 stores queries in one table, NDSQLT01, with two wide
columns.

A new system table, NDSQLT02, must be added if you want the
security system to work.
The file REDEF-SQL-B will add the new tables to a database.

If you have a database with the old tables NDSQLT01, NDSQLT02 and
NDSQLT03, these tables must be deleted. (The simplest way is to
rename the tables. Otherwise you must unload all other data tables,

## Temporary tables

In the A-version, a result of a select query could be stored on a temporary table. This table would disappear when SQLI was terminated.

In the B-version you can store the result on a SINTRAN file. These files are permanent and contain a header describing the columns of the table. A result table on a SINTRAN file can be copied to other databases. It can also be used in queries.

With SQLI-B01 you can import the table back into the same database or into another database if the column descriptions are equal. This restriction will be removed in later versions.

The B01 version can not export or import wide columns to/from tables on SINTRAN files.

## Query parameters

The special character to signal a query parameter has been changed from `$` to `:` in accordance with the SQL standard.

## 7 Errors Known But Not Corrected

When looking at wide columns, the content does not appear automatically. You must strike a key.

The interpretation and execution of queries are done by the SQL server in SIBAS. Any known errors are described there.

The present version of the SQL-server in SIBAS-B05 can only handle one SQL thread. This means that only one query can be executed at a time. If one query is executing, other users will "hang" until the execution is finished or until timeout. If the server is busy, you will get a message back after 30 seconds. This message is cryptic, "SQLLIB 43" which means "SQL server is busy". The message will be correct in the D10 version of UE-ERRORS.
