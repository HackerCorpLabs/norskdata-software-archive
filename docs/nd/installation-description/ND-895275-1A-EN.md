## Description of Product

SIBAS Manager is a tool giving a simple and (semi)automatic operator environment for SIBAS database administration. SIBAS Manager includes functions to handle all daily tasks involved in managing a database system, for example:

- Start of databases, with automatic recovery if necessary.
- Controlled database shutdown procedures.
- Various status commands.
- Automatic monitoring of table and R-log utilization.
- Automatic disconnect of database users with no calls in a predefined interval.
- Error handling with automatic transaction rollback.
- Event logging on disk file.
- Scheduling of database consistency check procedures.
- Automatic database checkpointing.
- A procedure to start databases, with automatic recovery if necessary, included in the computer startup procedure.

## Reason(s) for New Release

```
- SIBAS Manager features a simple menu-oriented screen interface.
  One, several or all databases can be handled (for ex. stopped)
  with a single command.

- With SIBAS Manager, you can handle all SIBAS databases in your
  local or wide-area COSMOS network from one terminal.

- Used in combination with Backup Manager, SIBAS Manager offers
  a tool for the database administrator, covering all daily SIBAS
  management tasks.

- SIBAS Manager consists of an operator program, one or several
  servers, and an error handler (termination handler) program.
```

## 4 Installation Procedure

### 4.1 Automatic Installation

- Before you start installing SIBAS Manager, check that the prerequisites listed above are fulfilled.

- If SIBAS Manager has previously been installed, make sure that the SIBAS Manager server is stopped and that the SIBAS Manager operator program is not in use.

- Log in on user: **SYSTEM**.

- Insert the diskette 211455A<rev>-XX-01D in the floppy drive.

- Enter the floppy directory as usual by typing:

  ```
  @ENTER-DIRECTORY 211455A<rev>-XX-01D <device name> <device number>»
  ```

- Start the installation program by typing:

  ```
  @(211455A<rev>-XX-01D: FLOPPY-USER)IN-SIBMAN-XX-A<rev>:PROG»
  ```

  SIBAS Manager will then be installed. You will be asked if you want to delete current and previous versions. If you answer YES to these questions, answer SIBR-B, ND-OPERATIONS, SYSTEM when the installation program asks for user areas to search for the files.

- After installation, remember to update the (SYSTEM)HENT-MODE (or corresponding) file by typing the command:

  ```
  @MODE (SIBR-B)SM-LOAD-A<rev>:MODE,,
  ```

- Remember also to update the (SYSTEM)LOAD-MODE (or corresponding) file by typing the command:

  ```
  @MODE (SYSTEM)SM-START-A<rev>:MODE,,
  ```

  Note that this file must be customized to your local configuration. See chapter 5.

## 5 Getting Started

Before you can use SIBAS Manager to administer your databases, you must customize it to suit your configuration:

### 5.1 Configuring a Non-Networked Computer

If you want to run SIBAS Manager in one single computer only, follow these guidelines:

- Use the UE-PMAN program to create the UE user SIBAS-MANAGER.

```
UE-username   : SIBAS-MANAGER       % Fixed name
Password      : <password>          % User defined name
Standard task : SINTRAN             % Fixed name
... 
Main User Area: SYSTEM              % Fixed name

As alternative user areas, register the user areas of all
databases that are to be controlled by SIBAS Manager on
this computer.

Give user SIBAS-MANAGER authorization level PUBLIC if you
do not want to allow the operator to log in as user
SIBAS-MANAGER and run the operator program. Set authoriza-
tion level to SUPERVISOR if you want to allow this. If
you start the operator program when logged in as user
SIBAS-MANAGER, you will get access to all databases defined
in the SIBAS Manager configuration.
```

- Fetch the file (SYSTEM)SM-START-<Arev>:MODE into an editor.

  Update the file with the password you gave to UE user SIBAS-MANAGER.

  **NOTE!** For security reasons, this file should have PUBLIC and FRIEND access = NONE. This will be set by the installation procedure.

- Fetch the file (ND-OPERATIONS)SW-CONFIG:SYMB into an editor.

  For every database that you want to be controlled by SIBAS Manager, insert the parameter: DATABASE-ADMINISTRATOR = SIBAS-MANAGER as the first `database-administrator` parameter for this database.

In addition, you can specify personal database administrators. These names will be used by SIBAS Manager to control management access to each database. Example:

```
DATABASE-NAME : ORDRBASE
    HEADING = Order database
    DATABASE-ADMINISTRATOR = SIBAS-MANAGER
    DATABASE-ADMINISTRATOR = PHILIP-JONES
    DATABASE-ADMINISTRATOR = OLA-NORDMANN
    ....
DATABASE-NAME : SALES
    HEADING = Sales database
    DATABASE-ADMINISTRATOR = SIBAS-MANAGER
    DATABASE-ADMINISTRATOR = OLA-NORDMANN
    ....
```

In this example, the user OLA-NORDMANN can control both databases, whereas PHILIP-JONES will only be given management access to the ORDRBASE. If the UE user SIBAS-MANAGER is defined as a supervisor, it will be possible to log in as this UE user and control both databases. If user SIBAS-MANAGER is defined as a public user, this will not be possible.

Note that a HEADING should be defined for each database. This will make it easier to identify the databases for you in the SIBAS Manager status pictures.

- If any of your databases have a DBA password (a password defined with the SIBR-DBM program), then this password must be defined in the SM-DBINFO file.

Fetch the file (SYSTEM)SM-DBINFO-A<rev>:SYMB into an editor. For each database having a DBA-password, register:

```
<Database name> <User area> <DBA Password>
```

For security reasons, this file should have Public and Friend access = None (N). This is set by the installation program for SIBAS Manager.

- Note that a number of other parameters also may be given for each database and for SYSTEM : SIBAS-MANAGER to customize the use of SIBAS Manager and SIBAS. See the manual "DIALOGUE Operations" for a description of these.

## 5.2 Configuring in a Network Environment

### 5.2.1 On the Database Computers

- For the database computers (the computer(s) running SIBAS processes), first follow the steps given in section 5.1.
- Then fetch the file (ND-OPERATIONS)SW-CONFIG:SYMB in an editor. Register (at least):

```
SYSTEM-NAME: SIBAS-MANAGER
OPERATOR-COMPUTERS = <computer name>(,<computer name>,...)
```

Specify here the name(s) of the local and/or remote computers that you will allow to give management requests to the SIBAS Manager server (and SIBAS databases) on this computer. If you do not specify this parameter, only requests from the local computer will be accepted by the SIBAS Manager server.

- Note that a number of other parameters MAY be given for each database and for SYSTEM-NAME : SIBAS-MANAGER.

See the manual "DIALOGUE Operations" for a description of these.

### 5.2.2 On the "Operator-Computers"

- On the computer(s) running the SIBAS Manager operator program, make sure that at least one UE-username exists, that is among the legal database administrator names given in the(ND-OPERATIONS)SW-CONFIG file on the database computer(s) (see above).
- Then fetch the file (ND-OPERATIONS)SW-CONFIG:SYMB into an editor. Register:

```
SYSTEM-NAME: SIBAS-MANAGER
DB-COMPUTERS = <computer name>(,<computer name>,...)
```

Specify the name(s) of the local and remote computer(s) you want to control from this computer (computers running SIBAS Manager server and SIBAS databases).

# 8 Limitations and Errors Known But Not Corrected

## 8.1 Limitations in the Operator Program

- It is explained in the manual, DIALOGUE Operations, ND-830072.2 EN (page 153) that the low intensity bar shows how full a table was at "Comparison time". This is correct. The high intensity bar shows the growth since "Comparison time" and the present time. A somewhat misleading picture emerges when data has been removed from a table since "Comparison time". Due to limitations in the graphics, we are not able to represent the decrease. The length of the bar displayed will be longer than the actual amount of data in the table. The actual amount can be read from the percentage number to the right of the bar. Since the status picture is sorted by descending growth rate, the bars that may cause some confusion will be listed last.

## 8.2 Errors in the Manual, Dialogue Operations,

- Page 34: The EXECUTE key has a different function than described. The MARK key or the << key performs the operation mentioned. The EXECUTE key refreshes the consistency check status picture.

- Page 148: It is not mentioned in this subchapter that the EXECUTE key can be used to refresh the user status picture.

- Page 163: It is not easy to see from the example, but there must be a space between `(SIBR-B)SM-SERVER` and `/LINE` when starting the server in line mode. So the command should be:

  @ND (SIBR-B)SM-SERVER /LINE

- Page 164: The correct command syntax for STOP-DATABASE should be:

  STOP-DATABASE <DB name>,<User area>,<Message>,<Wait time>,<Close?>

  In the manual, the `<Message>` and `<Wait time>` parameters have been mixed up.

  IMPORTANT: Also note that COMMA not SPACE should be used to distinguish parameters. This is true for all commands mentioned on the page.

ND-895275.1A EN

## 9 Information

- To make use of the termination handling facilities of this version of SIBAS Manager you must link your application program to the SIBAS library as follows:

```
@linker
Open-Domain "MYPROG"
Load MYPROG
....
....
Special-Link SIBLIB,OMIT,SOPDB,SCLDB
Define-Entry SOPDB,TRMHSOPDB,P,P
Define-Entry SCLDB,TRMHSCLDB,P,P
....
....
Close
Exit
```

This procedure is only valid for SIBAS library version B and later.

- To use termination handling, the UE-RUN program also needs to be updated. To patch the UE-RUN program version C03 to include the SIBAS Manager termination handling, do the following:

(Log in to SINTRAN user area USER-ENVIRONMENT):

```
@LOOK-FILE
OPEN UE-RUN-C03:PROG,,,
PATCH 230 65
   ’SM’
   ’T’
   ’RM’
   ’H’’
CLOSE,,,
EXIT
```

Then dump UE-RUN again as a reentrant subsystem!

## Instructions

1. Log in to user area SYSTEM and delete the standard domain SM-TRMH.

2. Log in to user area SIBR-B and type:

   ```
   @LINKER
   APPEND-SEGMENT SM-TRMH-DATA-A SWAP-ON-ORIGINAL-FILE
   CLOSE NO NO
   EXIT
   ```

3. Start the termination handler.

   ```
   @ND ()SM-TRMH
   ```

   The termination handler will then read the language-dependent texts from `SM-TEXT-EN-<Arev>` and the database information from `SW-CONFIG` into memory. When the program terminates, the information will be written back to the `SM-TRMH-DATA-A<arev>:SEG` file by the ND-500(0) swapper.

4. Change the segment attribute for the `SM-TRMH-DATA-A<arev>` back to normal. Type:

   ```
   @LINKER APPEND-SEGMENT SM-TRMH-DATA-A SWAP-ON-SWAP-FILE CLOSE NO NO
   EXIT
   ```

5. Log in to user area SYSTEM and define SM-TRMH as a standard domain.

Note that this procedure must be repeated if a new database is defined in the `SW-CONFIG` file.
