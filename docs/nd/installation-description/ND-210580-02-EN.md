## 2 INSTALLATION

Log in as user SYSTEM. If one version of COSMOS Ethernet Option is currently running on your system, then it must be stopped prior to running this installation job.

### Initial installation

Insert the (first) installation floppy and enter the directory. Start the installation program by typing:

```
@(210580: FLOPPY-USER)ENCOS-INJ
```

This program will copy the files from floppy and generate a COSMOS Ethernet server. For operator interaction with the installation program please refer to the example on the next page.

# 3 OPERATOR COMMANDS

The COSMOS Ethernet Option uses only a subset of those XMSG-COMMAND directives used by the X21 and X25 options. The specific use of the commands for COSMOS Ethernet Option will be included in the COSMOS network operator documentation, but is also explained below.

The COSMOS Ethernet servers are named by the following convention:

ENNS1 ==> EtherNet Network Server 1.  
Where 1 is the same number as the thumbwheel setting of the Ethernet Interface.

The "Server system name" parameter accepts carriage return as local system.

| EXAMPLE                   | COMMENTS                        |
|---------------------------|----------------------------------|
| X-C:START-NETWORK-SERVER↓ |                                  |
| Server name?↓ENNS0↓       |                                  |
| Server system name?↓      | => Default is local system       |  
| Window size?↓             | => Number of receive buffers (Def.5) |
| Wide Area Network(Y/N)?N↓ | => Local Area Network            |

NOTE: Maximum number of receive buffers for 108630-version is 6.

## 5 TRACE AND STATISTICS FACILITIES

When the network server stops, either due to a normal command (SINTRAN-SERVICE; stop-xmsg or XMSG-COMMAND; stop-network-server) or due to a fault, the system statistics for the Controller will be dumped to a file (RT)ENCOS-DUMP:DATA. If trace is enabled, the contents of the trace buffer will also be dumped to this file.

**NOTE:** The next time the network server is stopped, the dump-file will be overwritten.

A monitor program is included in order to enable the experienced user, ND-service and ND-support to locate errors, get indications of network overload, etc. The program is called by:

    @(utility)encos-mon↓
    ...
    ENTER COMMAND:

### Enable/Disable trace

```
ENTER COMMAND:trac↓
manipulate trace
server number (0/1/2/3):↓  => 0 is default
function enable/disable/read (E/D/R)?E or D↓
<enable for specific remote system only(Y/N)?↓>
```

### Dump trace

```
ENTER COMMAND:trac↓
manipulate trace
server number (0/1/2/3):↓  => 0 is default
function enable/disable/read (E/D/R)?R↓
filter display by system number (Y/N)?N↓
via physical copy (Y/N)?
output to file (ENCOS-TRACE:DATA)(Y/N)?
Copying.....
Formatting to file...
```

The trace can now be inspected by reading the file into any editor.

# 6 POWERFAIL HANDLING

The powerfail handler, POPWR, is an RT program that logs in on a Terminal Access Device on the local computer. POPWR will execute any mode file that does not stop TADs or XMSG. The hardcoded input- and output-file names are:

(SYSTEM)PO-PWRFAIL:MODE and (SYSTEM)PO-PWRFAIL:OUTP

The last command executed by the TAD is 'LOGOUT'. When this command is performed, POPWR will go into passive mode. To enable the program to be started at powerfail one must enter SINTRAN-SERVICE-PROGRAM and type:

DEFINE-USER-RESTART-PROGRAM POPWR  
or (SINTRAN Version K only)  
NEXT-USER-RESTART-PROGRAM POPWR if the command  
LIST-USER-RESTART-PROGRAM gives any RT program name as output.

Execution of the Ethernet startup mode file, (Please refer to earlier given example), and any other mode files for devices that do not handle powerfail are then included in the PO-PWRFAIL:MODE file.

NOTE: SINTRAN versions older than K may only have ONE user restart program.
