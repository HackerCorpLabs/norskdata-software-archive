# TRUE - Transaction User Environment

## Introduction

TRUE is the DIALOGUE transaction processing monitor, ensuring data integrity and secure operation of on-line systems using the SIBAS database management system. TRUE is designed to handle applications that run in a non-professional operations environment, as well as complex multi-machine networks. It consists of two modules: TRUE Basic System and an optional extension, TRUEMAN.

The main objective of TRUE Basic System is to protect the database from computer, application or network problems, which otherwise may leave the database in an inconsistent state.

TRUE safeguards transaction systems under DIALOGUE against such problems. During normal operation, TRUE offers a continuous terminal and database monitoring service. After abnormal incidents, TRUE's termination handler will automatically take control to reset (roll back) any incomplete updates.

This service includes database checkpointing and recovery. In addition, TRUE creates an environment that makes operation of even complex application systems simple.

TRUE offers system control of single-CPU systems as well as multi-CPU networks from one operator terminal. TRUE is part of DIALOGUE-3. DIALOGUE-1 applications may also use the TRUE Basic System functions.

TRUEMAN is an optional extension of TRUE, creating an integrated environment for high-volume transaction systems. TRUEMAN also creates a transparent interface for the application programs to the TRUE Basic System. TRUEMAN consists of two parts, a menu handling and access control system, and a batch-report administration system.

## TRUE Basic System

### Features

- Automatic error detection and error handling, including transaction recovery and total system recovery if required.
- Simple operation based on predefined procedures.
- Most operational procedures also available for application customizing through a programmer's library.
- Functions for batch job scheduling in a network.
- Transparent network operation from one terminal.

## Product Description

### Transaction Monitoring

The monitor part of TRUE is a server program which is active during regular operation. It contains the controlling functions, and initiates the operational procedures to be carried out for instance at system startup, shutdown or recovery. It will also perform functions such as periodical checkpointing of databases, control of transaction-log utilisation, terminal and database status etc.

In multi-CPU configurations, at least one monitor must run in each CPU. It is possible to create control hierarchies, so that one module can initiate e.g. multi-machine recovery or shutdown.

Several databases can also be grouped together to operate as one entity. They can still be distinguished by name by the operator.

The databases are controlled by a set of subroutines which are loaded together with the TRUE monitor program. Source code versions of these subroutines are available for customising to special needs.

The monitor module controls:

- A set of transaction terminal and batch processes.
- One or several SIBAS databases.

At startup, the monitor reads its configuration parameters from a file, making it easy, for instance, to include another database, or to perform automatic recovery of databases after a system restart.

### Operation

The operator interface is a screen oriented program, presenting all commands in the form of a two-level flat menu. Extensive defaults and help-information are available for most commands.

Messages from the TRUE system modules and its application systems will be displayed on the bottom four lines of the screen. The messages can be logged.

The operator menu includes commands for:

- Starting and stopping application systems and databases.
- Reading status information on systems, terminals, batches and databases.
- Sending messages to one or all terminals or to terminals running a specific program.
- Assisting the operator in database recovery situations.
- Operating TRUE’s batch scheduling system.

### Termination Handler

The termination handler ensures database integrity after error incidents, by initiating appropriate action on behalf of the application system affected by the error. The termination handler may also display error messages to the end-user, and/or send them to the system operator or error-log.

It will be activated by the operating system or by the application program in the case of errors or abnormal situations, e.g. if the terminal is stopped, the terminal line goes down or operating system time-out occurs. The termination handler will then:

- Back out transactions which have been interrupted while inside a critical database updating sequence - if required, full system recovery is initiated.
- Close the database(s) for the user.

# TRUE - Transaction User Environment

## Application Development

A user library is delivered as part of TRUE, providing subroutines for

- establishing membership in a TRUE system module
- enabling or disabling the TRUE termination handler for a terminal or batch program
- supervision and administration of the transaction system (start/stop/shutdown/rollback/recovery)
- sending messages to the error device and the operator terminal
- starting a new application program
- starting a batch job, either immediately or at some future time (execution interval start may also be specified)
- sending and receiving broadcast messages
- session-protocol routines for the exchange of data between user programs in a network

## Backup

The OE standard backup/restore program (ND 211076) integrates the standard backup system (ND 210337) with the database control, batch scheduling and error handling facilities of TRUE Basic System. This combination offers simple procedures for supporting a TRUE application system, with scheduling of backup procedures, stopping databases in a controlled manner, SIBAS transaction-log testing etc.

The backup procedure may have predefined parameters, and may be initiated through an interactive, menu-driven interface or automatically through a batch job. File copy, device copy and combinations may be performed.

## TRUEMAN

Online applications, whether developed as traditional COBOL/FORTRAN programs or generated with 4th-generation tools like ABM/Complete PG, will need supporting tools for menu handling, access control etc. to tie everything together into a high-performance online transaction system. TRUEMAN is a system utility to fulfill these requirements.

TRUEMAN also includes a batch administration system that will let the users start batch-jobs (with parameter transfer). It is easy for the supervisors to schedule and monitor the batch system.

## Features

- System programs handle application start-up, access control, and menu and function handling in the online application system, with a transparent interface to TRUE Basic System
- A batch administration system to schedule and monitor batch-report programs, where user-defined parameters can be transferred from the end-user to the application
- Tools for making high-performance application systems through special linking schemes and routines for data transfer and program start-up
- Definitions of menus, users, application programs and user accesses are stored in the SIBAS database and can be updated online

## Product Description

### Menu Handling and Access Control

The TRUEMAN modules for menu handling and access control consist of a maintenance system used by the supervisor and a runtime system that creates the environment for the end-users.

**The maintenance system** is used to define

- user profiles
- menus
- user/program access
- application programs

All configuration data is stored in the application database.

**The runtime system** consists of programs to handle

- user login
- menu display and selection
- function administration and access control

The TRUEMAN menu and access control system gives full support of the menu-handling requirements from applications made with COMPLETE-PG. This includes user/program access control, data transfer to/from programs and sequencing of applications.

The menu system created in TRUEMAN can be integrated as submenus in the general user-environment menus.

### Batch Administration System

The TRUEMAN batch administration system consists of a supervisor part, a batch-ordering program to be used by end-users, a batch monitor and a user/program interface library.

**The supervisor part** consists of functions to

- define batch reports
- schedule batch jobs
- monitor status
- print out result lists

**The end-user part** consists of system programs to

- request the execution of batch jobs. The user may simultaneously specify parameters for the application or for the environment, e.g. define a default printer
- check the status of ordered batch-jobs

Batch reports can also be scheduled for automatic start-up. Up to 20 parameters can be transferred to the batch job.

Application programs can be COBOL or FORTRAN programs, or report generation with NOTIS-RG.

### System Utilities

- TRUEMAN provides methods for optimal program linking, to give fast application program switching.
- TRUEMAN also includes simple ways to transfer data from program to program and to conserve data context during dynamic program switching.
