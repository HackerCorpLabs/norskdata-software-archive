# User Environment

## Introduction

User Environment is designed to enhance the security built into an ND computer system. It allows the supervisor to control access to the system, to restrict the availability of certain functions and to control access to data. This is done by setting time-limits for user and terminal access to the system. Menus control the functions that users are allowed to access, and the data can be controlled by allocating work areas to users.

User Environment greatly enhances the user friendliness of the system. It gives the user a personal identity on the machine. It is possible to create tailored menus for individual users or for user groups. User-written programs can be included so that an individual user sees them in a menu with other system functions.

User Environment controls access to several ND-NOTIS products. This means that the products can only be used by users who log on through User Environment.

Users with little computer experience will benefit from the use of menus. New users on the system will find it easier to choose between available functions than to give commands to the system.

# User Environment

## Features

- Control of user access to the system
- Personal user name protected by password
- Work areas protected by password, distinct from personal user name
- Easy-to-use menu control for inexperienced users
- Can limit the tasks available in menus to minimise confusion
- Tailor menu or menu hierarchy for individual users
- Full-screen editor for menu-forms editing
- UE Library Routines for integration of user-written programs with UE

## Benefits

User Environment provides added security and enhanced user-friendliness. There are many ways to accomplish these two features.

- **SECURITY:** All users should log on to the machine through User Environment. This ensures that User Environment is in control of access to the computer. User Areas should also be defined with passwords for extra protection of data.

- **USER-FRIENDLINESS:** Users may have different needs, and a different perception of how to do things. User Environment makes it possible to tailor menus to individual users, or users can go straight to SINTRAN and not have menus at all.

- **DATA MANAGEMENT:** Work areas may be maintained and administered with the powerful file manager. Maintenance is carried out with a full-screen editor to look at the required file names. All the files in a work area may be examined, or a selection may be made in a variety of ways. New files may be created and old ones deleted by simply adding a new name or removing an old one.

- **USER-WRITTEN PROGRAMS:** Locally written user programs may be accessed from menus in exactly the same way as system functions and ND software products. To install a new program, use the menu editor to specify which menu the program is to be accessed from.

## Product Description

User Environment is a security shell around SINTRAN. It provides added security and enhances the user-friendliness of the system. It consists of three parts: A User Profile, a Terminal Profile and a Menu System.

### The User Profile

System Supervisor defines all users in the User Profile, where the user is given access rights to the system. The user may be prohibited from using SINTRAN, s/he can be given menus with access to SINTRAN, or s/he may only log on through UE and afterwards only use SINTRAN. In addition, the supervisor can limit the hours and days of the week when the user can log on to the system.

### The Terminal Profile

The terminal profile overrides the user profile. The terminal can be set to run a given menu system, in which case all users who log on to the specific terminal will run that system, regardless of their own user profile. In addition, the terminal can be limited to certain time-frames for access to the system.

### The Menu System

Menus may be created for individual users, or for user groups with similar needs. The menus are easy to create and to edit, and they make the system user-friendly and easy to use. For each menu, HELP text may be created to guide the user.

## Requirements

- SINTRAN III, version J or later
- Minimum Local XMSG Communications System
