# Software Programming Language

## ND 10196 APL-100
## ND 10538 APL-500

### INTRODUCTION

APL is a concise and powerful programming language for scientific and commercial applications.

The language interactively executes user-written expressions or functions without intermediate compilation. Using a highly efficient interpreter schema, combined with APL's compact notation, it processes user applications very quickly.

An APL system offers a total development and execution environment, consisting of a Full Screen Editor (accepts many popular CRT/video terminals), mathematical and system functions, direct executions of expressions, file system support for exchange of data (both between APL applications as well as other programming languages), use native files and debugging and performance analysis.

User-written functions can be defined and tested, combined into higher level applications, saved on permanent disk-files, and copied into other applications as needed within the APL environment.

The Norsk Data APL language is available in two versions: APL-100 for the ND-100 16-bit minicomputer systems, and the APL-500 for the ND-500 CX series of 32-bit superminis. Both systems offer the same functions and conveniences, although performance may differ due to hardware capabilities.

### FEATURES

- Powerful APL language processor, highly optimized for fast execution.
- Functional level as of IBM APLVS(r) and STSC APL + PLUS(r).
- Includes all standard APL primitives, ⍴ -commands, and ⍥ -functions and variables.
- Extended quad-functions for report formatting, (`⍵ FMT`), screen oriented input and output (`⍵ SCREEN`), and several new string manipulations (`⍵ SS` and `⍵ BOX`).
- Large Workspaces that dynamically expand; on the APL-100 up to 1MB, and on the APL-500 up to 3MB.

- Built-in FULL SCREEN EDITOR, simplifying writing and modification of user defined functions and character data. Accepts many different APL-terminals from several vendors.
- File system support, both APL component files for exchange of data between APL applications; and Native (ASCII) file for exchange of data from other programming languages, spooling of output and setting character-font on suitable printers.
- Structured programming support using APLGOL, a block oriented «super-APL» language using IF-THEN-ELSE, CASE, LOOP-UNTIL, DO-WHILE etc., freely intermixed with ordinary APL-functions.
- Extensive program debugging tools: quad-functions for stopping, tracing, and monitoring the execution of APL-statements without prior preparations.
- Help information on two levels: listing of implemented commands and quad-functions, and detailed explanation and examples for each topic. The FULL SCREEN EDITOR also contains extensive help-information.

### PRODUCT DESCRIPTION

The APL-100 uses 48-bit floating-point representation, giving up to 9 significant digits for real numbers. The APL-500 uses 64-bit floating-point for up to 15 significant digits.

On APL-100 the active workspace is kept on a disk-file transparent for the user, and may be as large as 1MB. The full workspace need not be in memory at any time, and a software cache keeps track of which functions and data are most active in memory, swapping out on the disk when necessary.

On APL-500 the workspace may be addressed without constraints. However, the maximum workspace has been set to 3MB.

Several active users may access the APL-system, and execute the same workspace simultaneously since each user will have his/her own copy during execution. Datafiles may be shared and continuously updated; a protecting mechanism allows only one user to change data at a time.

# REQUIREMENTS

The APL-100 can run on any ND-100/CX version under the operating system SINTRAN III/VSX version I or later. The software modules constitute a set of 5 re-entrant segments, occupying approximately 285 pages on one of the segmentfiles. During execution, the background segment for each user must be 128 pages; several active users will share common segments.

The APL-500 consists of one ND-500 domain occupying approximately 330 pages on the system disk. It may be installed as a common standard domain.

The terminal definition file, help-file for commands and editor, requires approximately 30 pages, stored under user SYSTEM.

A terminal with APL character set is mandatory during program development (applications may run on any ASCII terminal), either CRT or hardcopy. Although ND does not offer APL terminals, the TANDBERG TDV 2221 APL/ANSI is highly recommended due to its excellent ergonomic and Full Screen capabilities.
