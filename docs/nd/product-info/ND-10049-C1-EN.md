# ND 10049 SINTRAN III/VS, VSE VSE-500 SPOOLING SYSTEM

## INTRODUCTION

In a multi-user system it is necessary to share common resources, like line printers, diablos, graph plotters and magnetic tapes, which are too expensive to be individually assigned. Even if each user has a hardcopy terminal, there will be occasions when a high volume of printing is required. It is both inconvenient and expensive for the user to have to wait until a line printer is free. For this reason, the concept of «virtual» line printers has been implemented in the ND File System.

When a user or a program writes data to the line printer, a disk file is assigned instead. Information is transferred in the same way as if a physical line printer had been assigned. Afterwards, the operating system automatically appends the disk file to a spooling queue, i.e. the job is put at the end of the queue. The information will be printed on the physical line printer when its turn comes in the spooling queue, and the file will be available for use again.

The user program performs faster as the data are «written» to a much faster device than the line printer. The printing capacity of the line printer also increases, since it will be running at full speed all the time instead of waiting for user programs to perform operations not connected with printing.

## FEATURES

- In any one system there may be several spooling queues, and several output devices, (e.g. line-printers) may be fed by the same queue.
- The number of line-printer files (i.e. spooling files which are used when a user tries to write to the line printer) is determined by the ND file system and could be up to 250 if necessary.
- Programs execute faster, not having to wait for the line printer to become available.
- Printing capacity increases, as the line printer does not have to wait for user programs.
- Users can produce output to the line printer while long printing tasks are in progress.
- Users can submit their own disk files to be printed by the Spooling System, even specifying the number of copies.
- Output for different users is well separated by a one-page header and a one-page trailer, which contains user name, date and time file was generated and printed. (This can be removed if necessary).

## THE SPOOLING QUEUE

Files submitted to the spooling system are held in a queue and whilst there can be manipulated freely.

- The queue will survive a system stop and restart.
- Files in the queue can be moved both backwards and forwards (the latter operation only being permitted to user SYSTEM who controls the running of the computer installation).
- User files and spooling files can be inserted and removed from the queue by their owners or by user SYSTEM.
- User SYSTEM may «delete» spooling files so they are available for use again; their contents being lost.
- The number of copies of a file to be printed can be set by command, either when submitting it to the queue (by command or by monitor call), or when it is in the queue by command.
- Printing of files from the queue may be done selectively by defining a SPOOLING-FORM, to be compared with a USER TEXT associated with each file in the queue. The user text is defined when the file is added to the queue. The spooling form can be set by command by user SYSTEM.
- The contents of the queue can be listed by command.

# Control of the Spooling System

- **User SYSTEM** can start and stop spooling for any peripheral device quite independently of any other peripheral device.
- The total number of disk pages used for spooling files can be evaluated easily by command within limits of disk space available to user SYSTEM.
