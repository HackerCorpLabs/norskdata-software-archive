### INTRODUCTION

Remote Job Entry – RJE – offers both economical and functional advantages. An inexpensive RJE-terminal gives a user access to the processing power of a host mainframe, or one or several organizations can share the same data and programs, which is the current trend – towards increasingly complex computer networks.

The ND IDT HASP-II WS is specifically designed for remote job entry to computer systems in the IBM 360/370 series. The range of possible RJE configurations provides the user with numerous options concerning the mix of local and remote processing. For instance, data entry, program editing etc. can be performed locally while compilations and file updating routines can be submitted by RJE to the host mainframe.

ND IDT HASP-II WS is a software system running under the SINTRAN III/VS with the ND File System for use on NORD-10/S and ND-100 computers. NORSK DATA has extensive experience with RJE applications and markets and supports RJE terminals and software protocols compatible with all major makes of mainframes. Our product covers the range from simple one-only configurations to multiple remote operation systems with sophisticated features.

### FEATURES

- Space compression/expansion gives up to 50% reduction in transmission time
- Multileaving speeds up two-way transmission, improving overall system efficiency
- Transmission rates from 1200 to 9600 bps
- Optional HASP DMA interface giving 48K bps transmission rates
- Supports both transparent and non-transparent communication protocols as user options
- Communication via private or dial-up lines
- Advanced versions supports I/O spooling
- Comprehensive repertoire of local commands with SINTRAN syntax with command and parameter abbreviation
- Multiple console support
- Console log on dedicated disk file

### PRODUCT DESCRIPTION

The ND IDT HASP-II WS is a software system developed for the ND-100 computer series with the SINTRAN III/VS operating system. HASP-II WS is a communication system which enables ND computers to interact with IBM 360/370 systems, and is available in two versions: As a Standard and DMA-version.

The software package comprises a set of asynchronous real-time programs, each assigned specific functions. Based on a modular design, it is a software concept which prevents bottlenecks due to slow peripherals from degrading overall system performance.

The ND IDT HASP-II WS provides a communication protocol with IBM 360/370 host systems running under HASP or JES. It handles operations like spooling of I/O files, job priority scheduling and assignment of peripherals. Normally, IBM HASP supports a configuration comprising card reader, console, punch and lineprinter.

The ND IDT HASP-II WS leaves the user free to substitute any other type of device for the card reader, the punch and the line printer. In addition, disk files can be used as storage devices for I/O files, alternatively diskettes (i.e. FLOCCON).

Normally, a synchronous modem interface is used, however, a HASP DMA interface is optional for faster transmission (if available at the remote site). CPU offloading and faster processing. The number of reader and printer streams is defined at system generation at the central site. The standard system supports 1 console reader, 2 input streams, 3 print streams and 1 punch stream. This may be expanded to 7 input, 7 print and 7 punch streams, provided the system on the terminal site conforms to the remote configuration, the IBM host installation.

### COMMAND SUMMARY

The latest version of the ND IDT HASP-II WS command repertoire has been vastly improved and expanded. All local commands conform to familiar SINTRAN syntax, and may thus be abbreviated as long as they remain unambiguous. Local commands fall into two categories – general and service commands.  
Remote commands are listed in the IBM HASP manual.

# Comments

Several users may communicate with the host computer simultaneously. Any unsolicited messages from either sites are logged on a dedicated disk file. Both local and remote commands are available to the users, however, command protection can be established by use of passwords.
