# ND 10029/10056 NORD IDT UNIVAC NTR EMULATOR

## INTRODUCTION

The Remote Job Entry approach to data processing offers several significant advantages. Without having to incur large capital outlays, an RJE terminal user may share the processing power of a host mainframe computer and gain access to centrally stored programs and data.

The NORD IDT Univac NTR Emulator is specifically designed for remote job entry to Univac 1100-series computer systems, and provides a range of options that affords the user freedom to configure his RJE terminal in accordance with his particular applications and functional requirements. For instance, it is possible to perform such typical operations as data entry and program editing locally at the terminal site, while file updating routines and compilations are submitted to the host mainframe.

With several years of experience in the field, NORSK DATA can offer RJE terminals for all major makes of mainframes, from simple core-only configurations to multiple remote operation systems with elaborate spooling facilities.

## PRODUCT DESCRIPTION

The NORD IDT Univac NTR Emulator is a software system running on NORD-10/S under the SINTRAN III/VS operating system with spooling of I/O files, alternatively available as a core-only system running under SINTRAN III/RT.

The software package consists of a set of asynchronous real-time programs, each assigned a specific task. By designing a high degree of modularity into the software, bottlenecks related to slow peripherals are prevented from occurring in the system.

The NORD IDT Univac NTR Emulator enables the NORD-10/S computer to communicate with Univac 1100-series host computer systems and handles such functions as spooling, job priority scheduling and operation of peripheral equipment.

Standard peripherals consist of card reader, line printer and operator console, however, these may be substituted by alternative NORD devices. The SINTRAN III/VS also supports spooling of I/O files on disk.

The system may accommodate up to 14 batch channels for input and output. Channels are connected to peripheral devices or mass storage files by local commands entered via the operator console.

## FEATURES

- Space compression/expansion, can reduce transmission time by up to 50 per cent and motivate the use of faster peripherals

- Comprehensive repertoire of both local and remote commands
- NTR — Nine Thousand Remote full duplex communication
- Up to 14 batch channels, connected to peripherals or mass storage files, alterable by local commands

# Command Summary

All commands, such as requests for status information, device assignments etc., can be entered via the operator console. Likewise, messages and acknowledgments from the system are also routed to the console, providing smooth and uninterrupted operation of the terminal and boosting terminal throughput. Consequently, the operator is relieved from such time-consuming chores as card punching and halting of input and output streams.

The following list contains a few sample commands:

## Local Commands

- **COSP N (f-n)**  
  Connect the specified file to output channel N as a spooling file.

- **CIFILE N (f-n)**  
  Connect the specified file to input channel N as an actual device.

- **COFILE N (f-n)**  
  Connect the specified file to output channel N as an actual device.

- **LICH**  
  Display actual and default devices connected to input and output channels.

- **CLOSE D**  
  Close (or release) device D.

## Remote Commands

- **SSID**  
  Establish communication with central site.

- **MESS**  
  Send message to central site, i.e. all console input is transmitted to the host installation.

- **DIFILE N**  
  Display files queued to output channel N.

- **STATUS**  
  Display number of retransmissions to and from the terminal.

In addition to the local and remote NTR commands, a time-sharing user may submit jobs for batch processing and manipulate his local files by the following SINTRAN III commands:

- **APPEND-REMOTE-QUEUE<queue><file name>**  
  Permits the user to submit a job to the host computer.

- **LIST-REMOTE-QUEUE<queue>**  
  Lists the job entries in the input queue to the host computer.

- **DELETE-REMOTE-QUEUE-ENTRY<file name>**  
  Deletes a job from the remote batch queue before execution has started.

Once the terminal has been logged on to the host computer, it remains in this mode until the operator decides to terminate the session by issuing the ABORT \<site id> command.
