## INTRODUCTION

The COBOL programming language is the industry-wide accepted high level computer language. It is oriented towards data processing tasks often found in business applications. A significant feature of the ND-COBOL product is that programs written on an ND 16-bit computer (ND-100 Family) can run on an 32-bit computer (ND-500 Family), without modification.

### THE ND COBOL HANDLES DATA TYPES FOR:

- **Packed Decimal (COMPUTATIONAL-3)**: up to 18 digits
- **Computational**: 
  - Picture 9 (n) where n ≤ 4 range (-32768) to(+ 32767)
  - Picture 9 (n) where 5 ≤ n ≤ 10 range (-2147483648) to (+ 2147483647)
- **Real (COMPUTATIONAL-2)**: only in CALL and MOVE to and from COMP-3
- **Display**: up to 18 digits
- **Numeric-Edited**: up to 18 digits plus edit characters
- **Alphanumeric ND 10177**: up to 2147483647 characters  
  **ND 10176**: up to 32767 characters
- **Alphanumeric-Edited ND 10177**: up to 2147483647 characters  
  **ND 10176**: up to 32767 characters

When applying the ND extended screen handling system, all terminals with an ND-supplied VTM (Virtual Terminal Manager) table can be used.

## ND Extensions

Some major extensions have been included with ND-COBOL:

### Screen Handling

With many new options on the ACCEPT and DISPLAY statements, data can be displayed in any screen position. Parts of the screen, or all of it, can be blanked out using the new BLANK statement. Movement between any two data fields is provided for by control keys. User Control including ACCEPT-ERROR is provided for.

### Multi-user Relative/Indexed Files

New options on the OPEN statement allow Indexed and Relative files to be opened in MULTI-USER-MODE, with or without MANUAL-UNLOCK, or with IMMEDIATE-WRITE. The READ/WRITE statements now have a WITH LOCK option to prevent two programs from accessing the same record at the same time. There is also a new UNLOCK statement. In addition to READ... NEXT RECORD there is also the feature READ... PREVIOUS RECORD.

### The DO, END-DO Statement and the IF, THEN, ELSE, IF, ELSE, END-IF Statement.

A DO statement has been introduced which can contain any number of WHILE phrases, and one FOR phrase, allowing positive or negative increments.

### Inter-Program Communication

- METHOD 1: CALL... USING with PROCEDURE DIVISION USING... in the called program.
- METHOD 2: Declaration of common areas using the new EXPORT and IMPORT clauses. Variables can be passed to called programs without having to be referred in the CALL 'xx' USING statements. These variables are accessible to all the routines in a program. This means, for example, that a program 4 levels below the program which defined the 'common area' can use it.

## COBOL Screen Handling

The ND-COBOL screen handling system consists of extended:

ACCEPT  
DISPLAY  
BLANK  

### Examples

```
BLANK     LINE IND
DISPLAY   (IND 1) 'Give password:' WITH INVERSE-VIDEO
ACCEPT    (IND 16) PASSWORD WITH BEEP INVISIBLE

  UP        ENTER-USER
  LEFT      ENTER-USER
  HOME      EXIT-PROGRAM
            CONTROL CHECK-PASSWORD
```

The format for these statements is:

```
ACCEPT   [position spec.] identifier with options
DISPLAY  [position spec.] identifier or literal with options
BLANK    SCREEN
BLANK    LINE i [TO j] COLUMN n [TO m]
```

**position spec.** is line and column in the screen, which may be specified with identifier or literal.

# Interactive Debugging

The ND-COBOL system provides the user with a number of debug options indispensable to efficient program development. When the command DEBUG-MODE is entered prior to program compilation, the user can choose between a number of debug options during subsequent execution of the program.

The options that can be invoked in DEBUG-MODE are:

- HELP - List available DEBUG options
- BREAK-ADDRESS
- BREAK-RETURN
- ACTIVE-ROUTINES
- ALIGN-LISTING
- CHECK-OUT-MODE
- COMPARE-DATA
- COMPARE-PROGRAM
- DUMP-LOG
- FIND-SCOPE
- GUARD
- LOG-LINES
- LOG-CALLS
- DISPLAY variable
- EXIT - Exit to operating system
- STEP - Execute next statement in logical sequence
- RUN - Start/restart program execution
- LOOK-AT-DATA
- LOOK-AT-PROGRAM
- LOOK-AT-REGISTER
- LOOK-AT-STACK
- MACRO
- RESET-BREAKS

and others.

One or more options may be active during program execution.

A sorted Cross-reference list is available for labels and variables.

# Two-Bank Mode for ND 10176

Programs are by default compiled in a two-bank mode making it possible to run programs with 128 KBytes of code and 128 KBytes of data. It is possible to compile in the 1-bank mode by giving the command 1-bank prior to the compile command.

# Related Software

## Database Management

The inter-program communication module allows COBOL programs to interface with the advanced SIBAS Database Management System through the Call-verb. The SIBAS DBM system is designed for multi-user, on-line terminal applications in business environments with complex information structures.

## Alternative Screen Handling System

The programmer may choose to use either the screen handling system (incorporated in COBOL) or to use the FOCUS screen handling system (which consists of an interactive-forms definition segment and a run-time segment).

## COBOL Code Generator (COB GEN)

COB-GEN generates COBOL source code for screen input/output, input validation and reports. The COBOL programmer's productivity rate can be highly increased with this simple, but effective method for COBOL source code generation. Using the COB-GEN utility removes the most tedious and error-prone tasks for the COBOL programmers, letting the programmers concentrate on the logic of the program. Using COB-GEN leads to brief, efficient and well-structured programs. 

*The simplified COB-GEN way of working is to:*

1. Draw the PICTURES and/or REPORT layouts and store them in a file.

2. Add commands in front and at the end of the drawing in order to associate COBOL variable names to the fields on the REPORT/PICTURE.

3. Process the files, and you get COBOL source code for input from/output to the screen and/or output to reports.

4. COPY the COBOL SECTIONS produced in step 3 into the COBOL program's PROCEDURE DIVISION using the COBOL verb COPY.
