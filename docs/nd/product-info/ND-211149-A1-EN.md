# The C Programming Language

## Introduction

C is one of today's most popular programming languages supporting many types of applications on a variety of different computers. Originally, the language was designed by Brian W. Kernighan and Dennis M. Ritchie as a programming language for the UNIX<sup>*</sup> operating system. C has proven equally well suited for commercial, technical, and scientific applications. The concept for modular programming, efficient language constructs, and an extensive runtime system support are the keys to its success.

In order to provide a high degree of compatibility with other systems, the C language implemented by Norsk Data conforms to the specification described in 'The C Programming Language' by Kernighan and Ritchie, which is generally regarded as C 'Standard'. The implementation of Norsk Data offers useful language extensions and library support for many UNIX system functions, as well as a good integration into the SINTRAN environment (symbolic debug and interfaces to SIBAS, ISAM, FOCUS, and monitor calls).

## Features and Benefits

This C implementation is now a standard Norsk Data product, i.e., further development, maintenance, and tuning are done by ND’s R & D department.

The most important goal is to provide a very high degree of compatibility with C implementations on other systems, while allowing the direct use of ND’s standard subsystems. C supports mixing with other languages like FORTRAN, PASCAL, and PLANC, and provides a convenient interface to SIBAS, FOCUS, ISAM, and Monitor-Calls.

C uses the same (CAT) code generator as PASCAL, which has already proven to be highly reliable and efficient. The following points sum up the major features and benefits:

- High degree of compatibility with other C implementations
- Full integration with ND’s standard libraries:  
  ISAM (indexed sequential access method)  
  the SIBAS database system,  
  the FOCUS screen-handling system, and  
  the monitor-call library
- PASCAL, FORTRAN, PLANC, and assembler routines may be called
- A great number of UNIX functions are supported
- Symbolic debugging allows tracing of execution flow or variables identified by symbolic names
- Source listing including line numbers, nesting level indicators, and a cross-reference listing through the CROSS command

## Additional Features

- Standard ND user/compiler interface
- Pointer check, index check, subrange check, and overflow check may be switched on
- Separate compilation of modules
- The compiler produces error messages providing line numbers and error reasons
- In case of runtime errors, information is given about line number and function where the error occurred
- Possibility to let the preprocessor run alone
- Preprocessed files can be used as input for the compiler
- Full separation of code and data
- Constant expressions within declarations and declarations in local blocks are supported
- Powerful expression syntax
- Complex initializations at compile time and runtime
- Heap allocation is efficiently combined with the ND-500 hardware instructions for heap administration
- The heap space is dynamically extended at runtime, if necessary
- Function variables and functions returning structures, structure assignments
- Enumeration types
- Inclusion of text from multiple source files and conditional compilation
- Compiler options set by commands or directives
- I/O buffering on sequential files
- Dynamic opening and closing of files during program execution
- Operations for bit manipulations are part of the language
- Extensive mathematical functions are available
- Inline hardware instructions can be used for mathematical functions supported by the ND-500 hardware

# The C Programming Language

## Product Description

ND C conforms to the standard description of 'The C Programming Language' by Brian W. Kernighan and Denis M. Ritchie (Prentice-Hall Inc. 1978).

The implemented library functions are, to a very high degree, compatible with those of NDIX and UNIX. At the same time the runtime system supports ND's standard subsystems.

The compiler generates code in standard NRF format that can be loaded by the standard linkage loader.

The compiler is called NC. Together with the standard header files it is contained in a separate user (CAT-NC-500).

## Error Detection and Debugging

The ND Symbolic Debugger may be used to debug a C program, performing line-by-line or routine call tracing, tracing the changes of a variable, restricting the legal range and displaying the value of any variable. All communication with the Symbolic Debugger uses the symbolic program names, and program locations are identified by label or line number.

The information used by the Symbolic Debugger is stored separately from the program code, and will not affect the program speed. Thus, the program code being debugged will be exactly equal to a program compiled without the debug information generated, ensuring that the effect of the program is exactly the same. After debugging, no recompilation is required to execute the program in the ordinary manner.
