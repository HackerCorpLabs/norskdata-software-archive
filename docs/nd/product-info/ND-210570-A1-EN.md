# COSMOS X.25 Option for PIOC

## Introduction

The COSMOS X.25 Option for PIOC is used to interconnect COSMOS networks through the X.25 packet-switched network provided by the PTTs. The X.25 protocol is an internationally accepted recommendation developed by the CCITT, defining the interfaces between computer vendors' equipment and the Public Data Network. Communication over X.25 with other vendors' systems is achieved with the COSMOS X.29 PAD, or with the ND OSI Transport Service.

## Features

- **Improved performance compared to the COSMOS X.25 Option (Using HDLC DMA).** The packet and link-level software runs in a separate controller, the PIOC, which has its own processor (MC 68000) and its own memory (1/2 megabyte), thus offloading the main CPU.

- **Cost Optimisation.** The system makes/breaks the connections based on the cost parameters. This is transparent to the user.

- **Multiple calls.** The COSMOS X.25 network server can communicate with 16 other X.25 nodes simultaneously. At the packet level 64 simultaneous connections may be established. (This includes the 16 COSMOS connections.)

- **Translation of COSMOS logical addresses to X.25 DTE numbers and vice versa.** This means that the user only needs to know the symbolic name of the destination.

# COSMOS X.25 Option for PIOC

## Product Description

Communication between the COSMOS Basic Module and the X.25 software is achieved through the X.25 Server. This means that the end user is provided with a transparent solution and that all functions which are available within a COSMOS local area network are available through a public X.25 network as well. No changes are required in user procedures/ND applications when the remote host is an ND system.

X.25 is a network-dependent protocol divided into three separate layers. At level 1, the COSMOS X.25 Option uses the V.24/V.28 or the V.11 standards. Level 2, the frame level, is divided into two parts: physical framing and logical frame control. Level 3 is the packet level.

- **The COSMOS X.25 PIOC Option supports the following types of calls:**

  - **Virtual call.** This call type gives the opportunity to choose a “communication partner” among the predefined computers in the network. This could be a COSMOS node or (using X.29 PAD) another vendor’s computer.

  - **Permanent Virtual Circuit.** This call type gives a constant route through an X.25 network, meaning that only one predetermined host may be accessed. This is not used by COSMOS but is used by the Program Access.

- **The COSMOS X.25 PIOC Option consists of the following parts:**

  - **The X.25 Network Server.** Provides the communication between XMSG and the X.25 software. Resides in the ND-110.

  - **The X.25 Packet and link-level software.** The communication protocols that run in the PIOC.

  - **X.25 Demoprograms.** Installation-test program. This program tests the installation.

  - **X.25 Command program.** Used for starting/stopping/configuring an X.25 module.

  - **X.25 Printlog program.** Used for storing log data on files, for later processing by the Printlog program.

  - **X.25 Diagnostic program.** Enables the operator to establish a fast and simple diagnostic on the current status of connections, within a COSMOS X.25 network.

The packet/link-level test programs that are included in the COSMOS X.25 Option for HDLC DMA are not included in this version.

The new program access library is now registered as a special product: the COSMOS X.25 Program Access.

The product is also a prerequisite for the following products:

- COSMOS X.29 PAD/Server
- COSMOS X.25 Program Access
- ND OSI Transport Service
- ND Coloured Books family of products
