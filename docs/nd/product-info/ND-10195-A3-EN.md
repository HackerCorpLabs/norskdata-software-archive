# ND 10195 Data Entry System II

## INTRODUCTION

The ND Data Entry System II consists of a set of software modules offering a flexible and easy way of entering and validating data in an ND-100/SINTRAN III/VS computer system.

One big advantage of ND Data Entry System II is that it can provide extensive checking of input so that only proper data are accepted for further processing, avoiding unnecessary additional entering, dominating expensive error-correction procedures and the nuisance of inaccurate reports.

## FEATURES

- For multi-terminal heavyweight data entry.
- Based on SIBAS and NSHS (ND Screen Handling System).
- Advanced screen handling operations using asynchronous display terminals with cursor control.
- Immediate reaction to errors both at the character entry level and at the data field entry level, such that when all data fields have been entered, they are correct as far as the system can judge. One does not wait until the screen is full before checking what has been typed in.
- Built-in field editing of numeric, decimal, alphabetic, alphanumeric fields, bank account and social security number, various data formats.
- Field control by content checking defined as a part of picture definition:
  - default value
  - check digit verification
  - data-controls
  - field accumulation
- End-user oriented
  - Help function
  - Defaults provided
- Easy corrections when altering field values, including copy of previous value, inserting or deleting characters, all by simple keystrokes.
- Records may be deleted.
- Duplicate function sets fields in a schema whose values are duplicated from transaction to transaction
  - remembers which fields
  - values set from session to session
  - new values can be given
- Verification — checking for correct registration.
- Routing — the definition of a path for the order in which the fields in a schema are to be input. Can be:
  - fixed
  - dynamic
  - overruled
  - this together with Duplicate gives a very useful skip and duplicate facility.
- Searching for a registered transaction.
- Total batch sums may be obtained for up to 5 fields within the same job.

## PRODUCT DESCRIPTION

The ND Data Entry System II makes use of a SIBAS database to administer registered data. It consists of three subsystems:

- **DAD**: Data Entry Administrator
- **DED**: Data Entry Editor
- **DWF**: Work File Handler

The Data Entry Administrator is used to define the operators, i.e., persons allowed to register and modify data in the Data Entry Editor and the jobs to be executed. A job is a sequence of data to be registered or modified. Schemas (screen pictures) are used for this registration. They are made by the aid of ND Screen Handling System (NSHS). DAD also maintains the names of schema files and system parameters.

The Data Entry Editor is used by the operator that actually keys in the required data.

The Data Entry Editor presents a picture of the required schema on a display terminal and allows the operator to fill in various fields from the original to the corresponding fields on the screen. The operator does not need to consider actual column positions, the editor automatically moves from one field to the next in any predefined order (see routing above), or can be positioned to a desired field by the operator.

Thus the operator may easily go back and modify any field that has been entered.

The registered data are stored in the data realm in the data base. They are accessible by way of the Data Work File Handler (DWF). In DWF data records may be inspected, printed, deleted or output to a SINTRAN file.
